## 1. 先接上前两批：三条路线的区别（字幕约 1–205 行）

上一批讲的 RoboFlamingo 使用预训练视觉语言模型理解当前画面和指令，然后把融合后的信息交给带记忆的动作模块。RT-2、OpenVLA 采用另一种路线：**把机器人动作编码成模型词表中的 token，让视觉语言模型像生成文字一样生成动作 token**。

| 模型 | 画面、语言信息如何进入 | 动作如何离开模型 | 本课应抓住的差别 |
| --- | --- | --- | --- |
| RT-1 | 视觉网络、FiLM、TokenLearner、Transformer | 各动作维度预测离散区间 | 为多任务机器人控制设计模型 |
| RoboFlamingo | OpenFlamingo 融合图像与文字 | LSTM 动作头输出连续位姿、夹爪状态 | 预训练模型主要提供融合后的表示 |
| RT-2 | PaLI-X 或 PaLM-E 视觉语言模型 | 直接生成动作 token | 同一生成模型用于图文任务与动作任务 |
| OpenVLA | Prismatic 视觉语言模型 | 直接生成动作 token | 开放代码和权重，研究跨机器人数据及微调 |

RoboFlamingo 与 RT-2 的分界，是**动作由哪个模块产生、采用什么训练目标**。不能据此断言 RoboFlamingo“完全没有推理能力”，也不能因为 RT-2 使用下一 token 预测，就认为它必然具有稳定的人类式推理能力。两种说法都超出了实验能证明的范围。

RT-2 论文于 2023 年发布，基于已预训练的 PaLI-X 和 PaLM-E；OpenVLA 于 2024 年发布，基于开放的 Prismatic-7B 模型。OpenVLA 希望让研究者获得模型、训练代码以及适配新机器人所需的方法。这里的“开放”也有边界：其基础组件 SigLIP、DINOv2、Llama 2 的原始训练数据和完整训练代码并非全部公开，OpenVLA 团队公开的是建立在这些组件之上的 VLA 工作所需资源。[RT-2 论文](https://arxiv.org/html/2307.15818)、[OpenVLA 论文](https://arxiv.org/html/2406.09246)

## 2. 零基础补课：语言模型究竟在预测什么？（字幕约 371–589 行）

假设模型见到“请拿起红色”，它需要预测下一个 token。这个 token 可能是“杯子”，也可能是“积木”。**Token 不一定等于一个汉字或一个单词**；分词器可能把数字、标点和词拆成不同片段。

最简化的数据流是：

```text
原始文字
  ↓ 分词器 tokenizer
token ID 序列，例如 [17, 42, 8]
  ↓ 查词向量表 embedding table
一串稠密数字向量
  ↓ 语言模型
下一个 token 在整个词表上的分数
  ↓ 选择 token
得到一个输出 token；重复即可得到一串输出
```

**词表**是 token 与 ID 的对应表。例如“杯子”可能对应 ID 42。**词向量表**则是每个 ID 对应一行可训练的数字；查到第 42 行，模型就得到能用于计算的向量。**输出分数**可以转成概率，表示模型在当前输入下觉得哪个 token 更可能接下来出现。

这个过程与“知识库查答案”不同。模型参数学习的是统计关系。训练时看到“图像 + 指令 → 正确输出”，模型通过比较自己预测的 token 与正确 token，逐渐调整参数。动作也能用这一套训练方式，但前提是先把真实机器人的连续数值转成合法 token。

字幕把这件事概括为“改变词表分布”。更准确的说法是：**为动作区间选定词表 token，并通过机器人数据训练模型，使这些 token 在动作上下文中被正确预测。**词表本身是否新增、覆盖旧 token、以及更新哪些词向量，取决于模型实现，不能一概而论。

### 为什么不直接输出文字 `0.34`？

如果把 `0.34` 当普通文字，分词器可能将其分为多个 token，输出还可能带来格式误差；机器人却需要固定维度、固定范围且可解析的数字。动作区间与指定 token 一一对应，可以把**输出格式**固定下来，并避免由普通数字字符串的分词方式决定动作表示。这是 RT-2 论文采用动作 token 的设计动机；字幕里关于各种分词器“必然如何切分 0.1”的例子只是示意，不是已验证的统一规则。[RT-2 第 3.2 节](https://arxiv.org/html/2307.15818)

## 3. RT-2：如何把连续动作交给词表？（字幕约 206–802 行）

### 3.1 机器人原本要的动作

RT-2 的一个动作包含：夹爪末端在三维空间的位置变化 `Δx, Δy, Δz`、三个方向的旋转变化、夹爪伸展量，以及表示本次任务是否结束的命令。因此，一个动作可写成 **8 个值**。前三项告诉机械臂末端去哪儿，旋转项告诉它朝哪个方向，夹爪项告诉它张开多少，结束项告诉系统该不该停。[RT-2 第 3.2 节](https://arxiv.org/html/2307.15818)

**末端**通常指夹爪等执行器所在位置。模型输出末端目标，并不意味着机器人不需要关节控制：底层控制器还要把末端目标转换成机械臂各关节的运动。字幕说“任意动作都能由控制算法完成”太绝对；目标可能超出机械臂可达范围，也可能遇到碰撞、速度或安全限制。

### 3.2 把数值分成 256 个区间

回忆上一批的练习：允许范围为 `[-1, 1]` 时，数值 `0.34` 约落在第 171 个区间。RT-2 沿用 RT-1 的思路，把每个连续动作维度等宽分成 **256 个区间**，于是每维可由 `0…255` 中的一个编号表示。结束命令原本就是离散的。模型输出若干动作 token，程序再把 token 编号还原为数值并交给机器人。[RT-2 第 3.2 节](https://arxiv.org/html/2307.15818)

这里有两个不同的“数字”，千万别混：

- **动作区间编号**：0 到 255，表示某一动作量处于哪个区间。
- **词表 token ID**：模型内部的索引。某个动作区间需要映射到一个 token ID；二者不必数值相同。

例如：

```text
真实动作某一维：0.34
       ↓ 离散化
动作区间编号：171
       ↓ 映射到词表
用于训练的 token ID：模型词表中的某个 ID
       ↓ 模型生成、再反向映射
区间 171 → 约 0.34 → 控制器使用
```

### 3.3 两种基础模型怎样安排动作 token？

RT-2 试了两个视觉语言基础模型：

- **PaLI-X** 的词表中，0 到 999 的整数各有单独 token，作者把相应整数 token 与 256 个动作区间关联。
- **PaLM-E** 没有同样方便的整数 token 布局，作者覆盖词表中最不常用的 256 个 token，令它们表示动作区间。

这是论文的具体实现。字幕说“所有机器人大模型的核心都是改词表分布”，说得过宽；其他 VLA 也可能用连续动作头、扩散模型或流模型。[RT-2 第 3.2 节](https://arxiv.org/html/2307.15818)

### 3.4 训练目标与输出约束

RT-2 把机器人示范改写成类似视觉问答的样本：输入是相机画面与“为了完成这个任务，机器人该做什么？”的文字提示；答案是动作 token 序列。模型使用**下一 token 预测**学习这段答案。与此同时，训练中还混入原有的图像描述、视觉问答等视觉语言数据，这叫 **co-fine-tuning（联合微调）**。其目的包括让模型继续使用预训练得到的视觉和语义知识。[RT-2 第 3.2 节及第 4.3 节](https://arxiv.org/html/2307.15818)

推理时还有一道工程关卡：若模型意外输出“苹果”之类的普通词，动作解码器就无法把它变成合法区间。RT-2 因而在机器人动作任务中**限制可选输出 token 的集合**；普通图文任务仍可使用正常词表。这是格式正确性的约束，并不单独保证动作安全或任务成功。[RT-2 第 3.2 节](https://arxiv.org/html/2307.15818)

字幕约第 803–874 行还讲到混合数据时的采样比例。你只需先记住：如果网络图文数据远多于机器人动作数据，训练时需明确安排两类样本出现的比例；单纯把两个文件拼起来，可能让小得多的机器人数据在训练中几乎没有影响。**“一比一”是讲者给出的易理解例子，不是所有 VLA 都应遵守的固定配方。**

## 4. RT-2 的成绩意味着什么？（字幕约 1114–1360 行）

RT-2 在真实机器人上测试已见任务，也测试新物体、新背景和新环境。其论文报告约 6000 次评测轨迹，显示与 RT-1 等基线相比，优势尤其体现在若干泛化测试中。RT-2 包含 PaLI-X 5B、55B 和 PaLM-E 12B 等配置；最大的 55B 配置通过远端 TPU 服务运行，不是在普通机器人板载显卡上直接运行。[RT-2 第 3.3、4.1 节](https://arxiv.org/html/2307.15818)

字幕举的“把可乐罐移到某个人的照片附近”“把苹果移到数字 3 附近”等例子，重点在**已有机械技能与新语义线索的组合**：机器人早已学过移动物体；网络视觉语言预训练帮助它识别照片人物、数字、图标或指令关系。论文也测试了颜色关系、简单数学、多语言等设置。[RT-2 第 4.2 节](https://arxiv.org/html/2307.15818)

这不等于它突然学会全新的机械动作。论文明确指出：它的**物理技能仍受机器人训练数据覆盖范围限制**，只是更能把已学技能用于新的语义情境。[RT-2 局限性](https://arxiv.org/html/2307.15818)

论文还有一个实验变体：先生成简短的自然语言 `Plan`，再生成 `Action`。例如“我饿了”→“拿零食”→对应动作 token。作者给出了定性示例，说明这种输出形式可能帮助多步语义判断。请把它当作研究线索：**能生成计划文字，不自动证明机器人会可靠规划所有复杂任务。**[RT-2 第 4.4 节](https://arxiv.org/html/2307.15818)

## 5. OpenVLA：把这条路线做成开放模型（字幕约 887–1113 行）

RT-2 证明了“视觉语言模型可以直接生成动作 token”这条路线，但其主要模型与完整训练资源没有像普通开源项目一样提供。OpenVLA 沿用这一基本思路，训练并发布一个约 **7B（70 亿参数）** 的模型，配套代码、权重及微调流程也对外提供。[OpenVLA 项目](https://openvla.github.io/)、[官方代码](https://github.com/openvla/openvla)

### 5.1 它的结构

```text
一张相机图像 ─→ DINOv2 + SigLIP ─→ 投影器 ─┐
                                             ├→ Llama 2 语言模型 → 动作 token
语言指令 ───────────────────────────────────┘
```

- **DINOv2**：提供有助于空间、物体形状等方面的视觉特征。
- **SigLIP**：提供经图文训练得到的语义特征，有利于把指令与画面里的对象联系起来。
- **投影器**：把视觉特征变成后续语言模型能够接收的向量。
- **Llama 2**：逐个预测动作 token。

两路视觉特征在模型里合并。字幕称之为“DINO 和 CLIP”，论文具体写的是 **DINOv2 与 SigLIP**。它们的分工不是“一个完全只有边缘、另一个完全只有语义”；这是帮助入门的粗略比喻，两者都学习复杂视觉表示。[OpenVLA 第 3.1 节](https://arxiv.org/html/2406.09246)

另一个值得纠正的字幕点：OpenVLA 的原始模型只支持**一张输入图像**。论文筛选数据时要求至少有一台第三视角相机，并使用单臂末端控制；它**没有要求每条训练数据同时具备第三视角和腕部相机**。多图像和历史观察在论文中被列为后续工作。[OpenVLA 第 3.3、6 节](https://arxiv.org/html/2406.09246)

### 5.2 它的数据从哪来？

OpenVLA 使用 Open X-Embodiment 数据集合。整个 OpenX 当时汇集了 70 多个机器人数据集、超过 200 万条轨迹；OpenVLA 筛选并整理出约 **97 万条机器人示范**用于训练。数据混合时参考 Octo 的配比经验，让任务、场景、机器人构型的多样性发挥作用。**97 万是筛选后的 OpenVLA 训练量，不是说 OpenX 总共只有 97 万。**[OpenVLA 第 3.3 节](https://arxiv.org/html/2406.09246)

“数据更多”也不能解释全部差异。数据清洗、机器人类型、动作定义、视觉编码器及训练流程都可能影响结果。读论文中的模型对比时，要同时看这些条件。

### 5.3 动作编码的工程细节

OpenVLA 同样把每个连续动作维度分为 **256 个区间**，但区间边界的确定方式与 RT-1 不同：它先看该维训练数据的**第 1 百分位数**和**第 99 百分位数**，然后在两者之间等宽分区间。极端离群值不会决定区间跨度。[OpenVLA 第 3.2 节](https://arxiv.org/html/2406.09246)

举例：如果 98% 的动作都在 `[-0.2, 0.2]`，却有一个罕见错误记录为 `10`，直接用最小值到最大值分 256 格，会让多数正常动作挤在很少的格子里。用 1% 与 99% 分位数设边界，会让常见动作获得更细的区分。**这不是把所有极端记录直接从训练集删掉**；论文描述的是动作离散化边界的选择。

OpenVLA 的 Llama 分词器没有为新任务预留足够多的专用 token，因此它覆盖**使用频率最低的 256 个词表 token**，令其表示动作区间。训练目标是下一 token 预测，但**交叉熵损失只在动作 token 上计算**。[OpenVLA 第 3.2 节](https://arxiv.org/html/2406.09246)

### 5.4 与 RT-2 的训练方式并不完全一样

两者都从预训练视觉语言模型出发，都通过动作 token 让模型直接输出控制量。关键差别之一是：**RT-2 的主要方法在机器人数据之外继续混合网络视觉语言任务；原始 OpenVLA 的 VLA 微调主要使用机器人数据。**OpenVLA 论文也承认，进一步研究联合训练是否更好，是一个尚待充分探索的问题。不能把两篇论文简化为“完全一样，只是一个开源”。[RT-2 第 4.3 节](https://arxiv.org/html/2307.15818)、[OpenVLA 第 6 节](https://arxiv.org/html/2406.09246)

## 6. 怎样看 OpenVLA 的实验结果？（字幕约 1114–1489 行）

论文在 WidowX 和 Google Robot 两种机器人设置中比较模型。其总体报告是：OpenVLA 在 29 个测试任务上的平均成功率，相比 55B 的 **RT-2-X** 高 **16.5 个百分点**，而模型规模约为 7B。这里要看清名称：对照对象是论文所述的 **RT-2-X**，不能把它的训练数据与 2023 年原始 RT-2 的设置混为一谈。论文同时说明，在**语义泛化**一类测试中，RT-2-X 仍有优势。[OpenVLA 摘要与第 5.1 节](https://arxiv.org/html/2406.09246)

论文还在新任务上用约 **10–150 条示范**进行微调。你可以把“微调”理解为：拿已经学会许多机器人任务的基础模型，再用目标机器人、目标相机和目标操作示范继续训练，以适应实际部署条件。这也解释了为何**模型能跨机器人使用**不等于“拿到任何陌生机械臂即可零样本成功”。相机视角、动作坐标系、夹爪机构都要匹配。字幕中“泛化几乎不存在”是讲者的个人实践判断，不能代替论文的具体实验结论。[OpenVLA 第 5.1、5.2 节](https://arxiv.org/html/2406.09246)

### LoRA 与量化：分别省哪一种资源？

这两件事经常被混淆：

| 方法 | 发生在什么时候 | 主要目的 |
| --- | --- | --- |
| **LoRA** | 微调时 | 只训练少量额外参数，降低训练资源需求 |
| **量化** | 主要讨论推理时 | 用更少的位数存模型权重，降低加载和运行显存 |

OpenVLA 论文的一组微调实验中，LoRA 只训练约 **1.4%** 的参数，任务表现接近全量微调。这里报告的显存数字与论文使用的模型版本、批量大小有关，**不能据此保证任意 8 GB 显卡可以微调 7B 模型**。[OpenVLA 第 5.3 节](https://arxiv.org/html/2406.09246)

推理测试中，4 位量化的模型占用约 **7.0 GB** 显存，16 位约 **16.8 GB**。但“模型权重占 7 GB”不等于“8 GB 显卡必然运行顺畅”：运行时还有图像张量、缓存、框架和控制程序开销，机器人还对每秒输出动作的次数有要求。[OpenVLA 第 5.4 节](https://arxiv.org/html/2406.09246)

字幕提到 8 位量化在该实验中比 4 位效果差，论文给出的具体解释主要是**推理变慢，动作更新频率不符合测试机器人原有的控制节奏**；不是“8 位数字天生不如 4 位精确”。论文报告的该组测试：16 位成功率约 **71.3%**、8 位约 **58.1%**、4 位约 **71.9%**。离线动作 token 准确率相近，是作者将实机性能差异归因于速度的重要依据。[OpenVLA 第 5.4 节](https://arxiv.org/html/2406.09246)

## 7. 本节字幕的关键纠错

1. **RoboFlamingo 不能因为用了动作头就被简单排除出 VLA。**不同文章对 VLA 的界定有宽有窄；本课重点是它与直接生成动作 token 的路线不同。
2. **动作区间编号与模型词表 ID 是两层映射。**“输出 171”只是帮助理解动作离散化，实际要看对应模型的 tokenizer 实现。
3. **RT-2 的八个动作值**包括末端位姿、夹爪及结束命令，不只是字幕口述的 XYZ 和三个角度。
4. **OpenVLA 使用 DINOv2 与 SigLIP，并且原版只接收单张图像。**
5. **OpenVLA 的 1% 和 99% 分位数用于设置离散化边界。**它没有据此宣称所有异常轨迹都被删掉。
6. **RT-2 的语义实验不是新物理技能的证明。**它主要展示已有动作技能如何结合新的识别、关系和符号信息使用。
7. **7 GB 是特定 4 位量化推理实验的模型显存结果。**机器人能否实时控制，还取决于推理速度和整个部署系统。

## 8. 自己动手理解：三个不用 GPU 的小练习

### 练习 A：手算动作区间

仍使用上一批的 [RT-1 动作离散化练习脚本](./练习/rt1_action_token_demo.py)。把允许范围设为 `[-1, 1]`，观察 `0.34` 对应的区间编号。然后尝试解释：为什么还原值与 `0.34` 不完全相等？答案应包含“连续数值被归入有限个区间”。

### 练习 B：区分“理解新意思”与“学会新动作”

机器人训练时会“抓取”和“放下”，但从没见过印有数字 `3` 的纸。现在它按照“把杯子放到 3 的旁边”行动。请分别指出：**原有机械技能**是什么？**新用到的语义知识**是什么？答案：机械技能仍是抓取、移动和放下；新知识是识别图像中的数字 `3` 并把它作为目标位置线索。

### 练习 C：读源码时先找四个入口

打开 [OpenVLA 官方仓库](https://github.com/openvla/openvla)，先看 README 的模型加载、`predict_action` 调用、数据格式与微调说明。暂时不要下载 7B 权重。你要在笔记中写出：输入图像如何预处理？指令如何组织？动作输出的维度和单位由谁定义？输出 token 如何还原成机器人动作？能回答这四问，再决定是否搭建完整复现环境。

## 9. 本批核心结论

**RT-2 提出了把机器人动作当作视觉语言模型输出 token 来学习的直接方案；OpenVLA 把类似路线建立在开放的视觉语言基础模型和较大规模多机器人数据上，提供代码、权重与微调路径。**它们改进的是“理解画面和指令后选择已有物理技能”的能力，而安全、稳定、高频率地控制陌生机器人，仍需解决数据、动作定义、相机、延迟和目标任务适配问题。
