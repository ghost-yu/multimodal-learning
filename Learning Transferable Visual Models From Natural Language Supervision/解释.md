## 0. 先约定读形状的方法

`B` = batch size，一批图片或句子的数量；`C` = 图片颜色通道数（RGB 时为 3）；`H/W` = 高/宽；`P` = 图片小块 patch 的数量；`T` = 一句话保留的 token 数；`D` =向量维度。写作 `[B,T,D]` 意思是一个三维张量。`shape[0]` 取第一维的长度，索引从 0 开始。`self.xxx` 是模型对象长期保存的层或参数；没有 `self` 的局部变量只在这次函数调用里存在。

## 2. `clip.load()`：从模型名到两个返回值

位置：[clip.py 的 `load`](../CLIP/clip/clip.py)。调用 `model, preprocess = clip.load('ViT-B/32', device='cpu')` 时，左边两个变量依次接收函数返回的两个对象：

1. `name` 叫“名字”，既可以是 `_MODELS` 字典内的模型名，也可以是本地 checkpoint 文件路径。`_MODELS[name]` 取模型下载 URL。
2. `_download(url, root)` 把文件下载到缓存目录并校验摘要；`os.path.isfile(name)` 判断传入的是否已有本地文件。
3. `with open(model_path, 'rb') as opened_file` 以二进制模式打开权重文件；`with` 退出时自动关闭文件。`opened_file` 命名提醒这是**已经打开**的句柄，不是路径字符串。
4. `torch.jit.load(...)` 先尝试读取 TorchScript 归档；若失败，`torch.load(...)` 读普通权重。`map_location='cpu'` 意味着先映射到 CPU，避免加载时直接占用 GPU。
5. 默认 `jit=False`。`build_model(state_dict or model.state_dict())` 从权重键和张量形状恢复可检查的普通 PyTorch 模型。`state_dict` 是“参数名字 → 张量”的字典；它不是图片数据。这里 Python 的 `or` 会选择前面非空的对象。
6. `.to(device)` 把模型参数搬到指定设备；`.float()` 在 CPU 情况下改为 float32。注意：`.to()` 并不会自动处理输入图片，你之后也要把图片张量搬到相同设备。
7. `_transform(model.visual.input_resolution)` 生成图片预处理函数。`preprocess` 先调整尺寸、中心裁剪、转 RGB、转张量，再按 CLIP 使用的均值与标准差归一化。`model` 和 `preprocess` 必须配套。

这里 `model_path` 是权重文件的路径；`model` 是实例；`state_dict` 是参数字典；这三个名字容易混淆。`visual` 指 `model` 内的视觉编码器，不是原始图片。

## 3. `tokenize()`：文字为什么变成 `[B,77]`

位置：[clip.py 的 `tokenize`](../CLIP/clip/clip.py)。输入 `texts` 可是一句话，也可是句子列表。若是一句，`isinstance(texts, str)` 为真，代码把它改成单元素列表，后面统一循环处理。

```python
sot_token = _tokenizer.encoder['<|startoftext|>']  # SOT = start of text，取开头特殊符的整数 ID
eot_token = _tokenizer.encoder['<|endoftext|>']    # EOT = end of text，取结束特殊符的整数 ID
all_tokens = [[sot_token] + _tokenizer.encode(text) + [eot_token] for text in texts]
```

`_tokenizer` 是文件顶部实例化的 `SimpleTokenizer`；`encoder` 是字符串 token 到整数 ID 的字典。`encode(text)` 对每句话做字节对编码（BPE，byte pair encoding），返回整数 ID 列表。列表加法 `+` 是串接而非数值相加。`all_tokens` 因为存了“所有句子各自的 token 列表”而这样命名，尚未补齐等长。

`torch.zeros(len(all_tokens), context_length, dtype=...)` 建一个全 0 矩阵；第 `i` 行通过 `result[i, :len(tokens)] = torch.tensor(tokens)` 写入第 `i` 句。`context_length` 默认 77，是模型的固定文本长度。`truncate=True` 时，过长句子会截断，最后一位强制改回 EOT，确保模型能找到结束位置。`result` 是最终 `[句子数,77]` 的整数张量，不是语义向量。

## 4. 图片编码：逐行追 `VisionTransformer.forward()`

位置：[model.py 的 `VisionTransformer`](../CLIP/clip/model.py)。假设 `B=2`、图片为 `224×224`、`patch_size=32`、`width=768`。`patch_size` 名字来自每块边长；`width` 指 Transformer 内部每个 token 的特征宽度。

| 实际语句 | Python/库函数含义 | 这一行之后形状 |
|---|---|---|
| `x = self.conv1(x)` | `nn.Conv2d(3,width,kernel_size=32,stride=32)` 同时切不重叠小块并做线性映射 | `[2,768,7,7]` |
| `x.reshape(x.shape[0], x.shape[1], -1)` | `reshape` 改形状，不改变元素总数；`-1` 自动算出 `7×7=49` | `[2,768,49]` |
| `x.permute(0,2,1)` | `permute` 重新排序维度；第 0 维仍是 batch | `[2,49,768]` |
| `torch.zeros(B,1,D,...)` | 为每张图复制一个可训练 `class_embedding` 的位置；`device=x.device` 防止 CPU/GPU 不一致 | `[2,1,768]` |
| `torch.cat([...], dim=1)` | 在序列长度维拼接，CLS 放第 0 个位置 | `[2,50,768]` |
| `x + self.positional_embedding` | 广播加法：位置向量 `[50,768]` 自动复制给 B 张图 | `[2,50,768]` |
| `self.ln_pre(x)` | LayerNorm 在最后一维做归一化，数值更稳定 | `[2,50,768]` |
| `x.permute(1,0,2)` | PyTorch 旧版 `MultiheadAttention` 要求 `[序列,batch,特征]` | `[50,2,768]` |
| `self.transformer(x)` | 多个残差注意力块，token 之间交换信息 | `[50,2,768]` |
| `x.permute(1,0,2)` | 换回 batch 在前 | `[2,50,768]` |
| `x[:,0,:]` | `:` 表示取全部；只取第 0 个 CLS token | `[2,768]` |
| `x @ self.proj` | `@` 是矩阵乘法；`self.proj` 从视觉宽度投影到共同嵌入维度 | `[2,embed_dim]` |

`x` 没有一直代表同一层的值：它被每一行重新赋值，表示“当前阶段的图像特征”。因此再次遇到 `x` 时先看紧邻上一行的形状。`class_embedding` 是参数而不是图片真实像素，`positional_embedding` 告诉模型 patch 原位置。

## 5. 文本编码：为什么取结束符

位置：[model.py 的 `CLIP.encode_text`](../CLIP/clip/model.py)。`text` 在入口是整数 ID `[B,77]`，与上一节的文字字符串不是同一个对象。

1. `self.token_embedding(text)` 查可训练词表，把每个整数 ID 映射成宽度为 `transformer_width` 的向量。`nn.Embedding(V,D)` 可想成 V 行、D 列的表；返回 `[B,77,D]`。
2. `.type(self.dtype)` 让浮点向量与视觉网络的浮点精度一致。`dtype` 属性从 `self.visual.conv1.weight.dtype` 读出；文本的整数 ID 在查表前仍须是整数。
3. `x + self.positional_embedding.type(self.dtype)` 给每个 token 加位置向量。这里 `x` 是文字隐藏状态，已不再是图片特征；两个 `x` 是不同函数的局部变量。
4. `x.permute(1,0,2)` 变为 `[77,B,D]`；`self.transformer(x)` 用**因果注意力 mask**，位置 `t` 只能看到自己和之前 token。
5. `self.ln_final(x)` 是最后的归一化；`text.argmax(dim=-1)` 沿每句话 77 个 ID 找最大 ID 的位置。此仓库的 EOT ID 最大，所以能定位 EOT。这个技巧依赖 tokenizer 的 ID 排序，不是通用规则。
6. `torch.arange(x.shape[0])` 返回 `[0,1,...,B-1]`，与各行的 EOT 位置一起做成“每句话选自己的结束符”的高级索引。选出 `[B,D]` 后 `@ self.text_projection` 得到 `[B,embed_dim]`。

因果 mask 源于 `build_attention_mask()`：先把 `[77,77]` 全填 `-inf`，再用 `triu_(1)` 只保留上三角的 `-inf`；下三角和对角线为 0。把此 mask 加到注意力分数后，未来位置经 softmax 得到 0 权重。`triu_` 末尾下划线表示**原地修改**。

## 6. `CLIP.forward()` 与原理

```python
image_features = self.encode_image(image)  # image_features: 每张图的 [D] 向量，不是原始像素
text_features = self.encode_text(text)     # text_features: 每句话的 [D] 向量，不是 token ID
image_features = image_features / image_features.norm(dim=1, keepdim=True)
text_features = text_features / text_features.norm(dim=1, keepdim=True)
logit_scale = self.logit_scale.exp()
logits_per_image = logit_scale * image_features @ text_features.t()
logits_per_text = logits_per_image.t()
```

`norm(dim=1, keepdim=True)` 为每个样本算向量长度，返回 `[B,1]`，保留一维才能广播除法。归一化后点积等于余弦相似度。`logit_scale` 参数储存的是对数，所以 `.exp()` 转成始终为正的缩放值；较高的缩放使 softmax 更尖锐。`.t()` 对二维矩阵转置。若有 `I` 张图、`S` 句文字，`logits_per_image` 形状 `[I,S]`，第 `i,j` 个元素是第 i 张图和第 j 句的匹配分数；`logits_per_text` 为 `[S,I]`。**分数不是概率**，可在推理时用 `softmax(dim=-1)` 把每行候选分数转成概率。

论文训练的思想是：成对图文为正例，同批其他图文通常作为负例，对两个方向的分类损失求平均。这个官方仓库的 `CLIP.forward()` 返回分数，并没有实现那段完整训练循环。因此不要把 `forward()` 当成“已自动算好对比损失”。

## 7. 容易卡住的命名与函数速查

| 名字 | 拆开理解 | 再出现时从哪里来 |
|---|---|---|
| `vision_width` / `transformer_width` | 分别是视觉/文字 Transformer 内部宽度 | 构造 `CLIP(...)` 的参数；可以不同 |
| `embed_dim` | 图文对齐的最终公共维度 | 视觉 `proj` 和文字 `text_projection` 的输出宽度 |
| `logits_per_image` | 以图片为行，面对所有文字候选的分数 | `CLIP.forward()` 最后矩阵乘法 |
| `context_length` | 每句话固定保留的 token 槽位数 | `tokenize` 与模型构造都须一致 |
| `patch_size` | 图像小块边长 | `VisionTransformer` 构造参数 |
| `self.visual` | 视觉编码器实例 | `CLIP.__init__` 创建，ResNet 或 ViT 二选一 |
| `state_dict` | 参数字典 | `torch.load` 或 `model.state_dict()` |

`nn.Module` 是所有模型层的父类；`super().__init__()` 必须先初始化它，才能把 `self.xxx = nn.Linear(...)` 等层正确登记。`forward` 是模型被调用时执行的函数：写 `model(image,text)` 会通过 `nn.Module.__call__` 间接调用 `forward`，所以通常不要直接写 `model.forward(...)`。`nn.Parameter` 自动进入 `model.parameters()`；普通 `torch.Tensor` 属性默认不会进入优化器。

## 10. 从一句话到整数 ID：`SimpleTokenizer` 完整调用链

很多初学者会把 `clip.tokenize()` 与模型里的 `token_embedding()` 当成一步，其实是两步：

```text
"a dog"（Python 字符串）
  → SimpleTokenizer.encode()：清洗、正则拆词、UTF-8 字节映射、BPE 合并、词表查 ID
  → clip.tokenize()：加 SOT/EOT、补齐为固定 77 长度，得到整数张量 [B,77]
  → model.encode_text()：nn.Embedding 查可训练向量，得到浮点张量 [B,77,D]
```

**SOT** 是 Start of Text（文本起点），**EOT** 是 End of Text（文本终点）。BPE 是 Byte Pair Encoding（字节对编码）：最初把文字表示为较小片段，再按合并规则把常见相邻片段合起来。这样不必为每一种完整单词单独留一个词表位置。这里的 Byte 指 UTF-8 字节；`bytes_to_unicode()` 为全部 256 种单字节值建立可逆的可打印字符映射，防止某些空白或控制字节直接进入 BPE 规则。

[`SimpleTokenizer.__init__`](../项目讲解/四项目教学源码/CLIP-simple_tokenizer-详注.py) 从 `bpe_simple_vocab_16e6.txt.gz` 读取合并规则。`gzip.open` 返回压缩文件对象；`.read()` 得字节；`.decode('utf-8')` 得字符串；`.split('\n')` 得行列表。`merges` 是“相邻哪两个片段能合并”的列表，**列表先后就是优先级**。`bpe_ranks = dict(zip(merges,range(len(merges))))` 把每条规则映到名次。`vocab` 是 token 字符串列表；`encoder` 把 token 映到整数 ID；`decoder` 反向查 ID。`cache` 记住已经切过的词，避免反复计算。

`encode(text)` 中 `text` 最开始是原始句子字符串。`basic_clean()` 修常见乱码、处理 HTML 转义；`whitespace_clean()` 把多个空白压成一个；`.lower()` 变小写。`re.findall(self.pat,text)` 是 regex 匹配，逐段取词、数字或标点；这里导入的是第三方 **regex** 包，别名也叫 `re`，不能误以为一定是 Python 标准库的 `re`。每段的 `token.encode('utf-8')` 返回字节序列，再逐字节查 `byte_encoder`。`self.bpe(token)` 返回空格分隔的子词字符串；`self.encoder[bpe_token]` 才把每个子词变成整数。最终 `bpe_tokens` 是 Python 整数列表，**还不是 `[B,77]` 张量**。

`bpe()` 的 `bigram=min(pairs,key=lambda pair: self.bpe_ranks.get(pair,float('inf')))` 可拆成三步：`pairs` 是当前所有相邻片段对；`get(pair,inf)` 取该对的合并名次，未知规则视为无穷大；`min` 挑名次最小的那一对。然后从左到右扫描，把出现的 `first,second` 合并为 `first+second`，重新计算新的相邻对，直到无法再合并。`</w>` 是词尾标记；它让某个片段在词尾与词中可以对应不同 token。教学副本在 `i`、`j`、`word` 每次重新赋值处都注明了来源。

`clip.tokenize()` 在得到整数列表之后再加 SOT/EOT，并创建全 0 的 `[B,77]` 整数张量。每句话的 ID 写入自己的那一行，其余 0 为补齐槽位。`truncate=False` 且太长会报错；`truncate=True` 会截断并把最后一格重新设为 EOT。最后 `encode_text()` 能用 EOT 位置汇总整句话。**`text.argmax(dim=-1)` 能找到 EOT，只因为这个实现的 EOT ID 在序列里最大；换词表时不要照抄。**

## 11. CLIP 的另一条图片路线：ModifiedResNet

第 4 节解释的是视觉 ViT。`CLIP.__init__` 还可能创建 [`ModifiedResNet`](../项目讲解/四项目教学源码/CLIP-model-详注.py)。当 `vision_layers` 是元组或列表时，视觉骨干用 ResNet；是整数时用 ViT。两种骨干最终都输出**一个整图向量**，供第 6 节和文字向量比较。

`ModifiedResNet` 的三层 `stem` 先处理图片，随后 `layer1..layer4` 是四组残差块。`stem` 是视觉网络开头的特征提取部分，不是 Python 关键字。`_inplanes` 是构建网络时“当前输入通道数”，随着建层逐步更新；前面的下划线表示内部实现属性，`planes` 是当前 Bottleneck 的内部通道宽度。`Bottleneck.expansion=4` 表示第三个卷积后的输出通道数为 `planes×4`。

一个 [`Bottleneck.forward`](../项目讲解/四项目教学源码/CLIP-model-详注.py) 可按这张表读：

| 名字/语句 | 来源与作用 |
| --- | --- |
| `identity = x` | 暂存原输入，后面走旁路相加；不是创建全新图片 |
| `conv1 → bn1 → relu1` | `1×1` 卷积调整通道，BatchNorm 按通道归一化，ReLU 加非线性 |
| `conv2 → bn2 → relu2` | `3×3` 卷积读局部邻域；`padding=1` 在步长 1 时维持高宽 |
| `avgpool` | `stride>1` 时先平均池化做空间降采样；否则是 `nn.Identity()` 原样通过 |
| `conv3 → bn3` | 再用 `1×1` 卷积扩到 `planes×4` 通道 |
| `if self.downsample ...` | 当旁路通道数/高宽与主分支不一致时，也给旁路池化和投影 |
| `out += identity` | 对同形张量逐元素相加，称残差连接；不合形状会报错 |
| `relu3(out)` | 残差相加后再激活 |

这里 `nn.Conv2d(in_channels,out_channels,kernel_size,stride,padding)` 是卷积层构造器；`nn.BatchNorm2d(channels)` 是二维特征图的批归一化层；`nn.ReLU(inplace=True)` 中 `inplace=True` 表示尽量原地改值，节约内存；`nn.AvgPool2d(2)` 按局部窗口求平均并缩小空间尺寸。`nn.Identity()` 不变换输入，常用作“可选层关闭时”的占位对象。`nn.Sequential` 把多个层按顺序串起来；`OrderedDict` 为这些层保留明确名称。

CLIP 的 ModifiedResNet 最后使用 [`AttentionPool2d`](../项目讲解/四项目教学源码/CLIP-model-详注.py)，不是直接平均所有像素。设最后特征图 `x=[B,C,H,W]`：

1. `.flatten(start_dim=2)` 把 H、W 合成 `HW`，得 `[B,C,HW]`；`.permute(2,0,1)` 得 `[HW,B,C]`。
2. `x.mean(dim=0,keepdim=True)` 在所有空间位置求平均，生成一个 `[1,B,C]` 的**汇总查询 token**；`torch.cat(...,dim=0)` 把它放在序列最前面。
3. 加 `positional_embedding` 后，调用 `F.multi_head_attention_forward()`。`query=x[:1]` 只取第 0 个汇总 token；`key=x,value=x` 包含汇总 token 和全部位置。Q 与每个 K 比较得到权重，再加权 V，因此汇总 token 学会关注不同空间位置。
4. `q_proj/k_proj/v_proj` 是三套 Q/K/V 线性投影层；`c_proj` 把结果投影到 CLIP 图文公共维度。`need_weights=False` 表示不返回整张注意力权重表；函数返回 `(输出,可选权重)`，所以代码写 `x,_=...`。`x.squeeze(0)` 删除长度 1 的查询序列维，得到 `[B,output_dim]`。

ResNet 与 ViT 的中间表示不同：ResNet 先是二维特征图，ViT 先切 patch 为 token；二者最终都交出整图向量。这里没有让文字在视觉编码器内部读取图片细节；CLIP 后面的比较依然是**两个编码器各自算向量，再做相似度矩阵**。

## 12. `build_model(state_dict)` 为什么能从权重猜出结构

`state_dict` 是“层名字符串 → 参数张量”的字典。比如 `visual.conv1.weight` 的形状可以透露输出通道数与 patch 边长。[`build_model()`](../项目讲解/四项目教学源码/CLIP-model-详注.py) 先看是否有键 `visual.proj`：有则判断为视觉 ViT；否则走 ModifiedResNet。这不是对任意外来权重都可靠的通用模型识别器，而是按 CLIP 自己的权重命名约定恢复结构。

ViT 分支的 `vision_width = state_dict['visual.conv1.weight'].shape[0]` 读卷积输出通道数；`vision_patch_size = ...shape[-1]` 读卷积核边长；视觉位置向量条数减 1（CLS），开平方得每边 `grid_size` 个 patch，于是 `image_resolution=vision_patch_size×grid_size`。`vision_layers` 是数匹配 `visual.*.attn.in_proj_weight` 的块数。ResNet 分支数 `layer1..4` 各有几个 Bottleneck，形成 `vision_layers` 元组，再从注意力池的位置向量反推最后网格宽度和输入分辨率。

文本侧，`state_dict['text_projection'].shape[1]` 给图文共同 `embed_dim`；`positional_embedding.shape[0]` 给 `context_length`；`token_embedding.weight.shape[0]` 给词表大小；`ln_final.weight.shape[0]` 给文字 Transformer 宽度。`transformer_heads=transformer_width//64` 是当前权重规格采用的头维约定；`transformer_layers` 从权重键中有多少个 `resblocks` 编号推断。之后用这些值 `model=CLIP(...)` 新建同结构空模型，再 `load_state_dict(state_dict)` 把训练好的数值填进去。

`convert_weights(model)` 遍历模型，把适用的卷积、Linear、MultiheadAttention 投影及 `text_projection/proj` 转为 float16。`.half()` 是半精度浮点转换，节省显存；`.data` 是原仓库直接访问参数底层张量的旧写法。`model.apply(fn)` 会递归对每个子模块执行 `fn`，并非只执行一次。`model.eval()` 切换评估模式，使 Dropout 等停止训练期随机行为；**它不表示已经做了评估或得到准确率**。

## 13. 对比损失在哪儿？从分数矩阵到一次更新

官方 CLIP 仓库的 [`CLIP.forward()`](../项目讲解/四项目教学源码/CLIP-model-详注.py) 返回 `logits_per_image,logits_per_text` 两个分数矩阵。若训练 batch 有 B 对正确图文，按同一顺序排列，则第 i 张图与第 i 句是真配对，对角线是正例。下面是这一思路的最小代码，已在本工作区的[教学训练脚本](../小型复现/训练CLIP小样本.py)里实现：

```python
targets = torch.arange(B, device=scores.device)       # [0,1,...,B-1]，每行正确列号
loss_i2t = F.cross_entropy(scores, targets)          # 每张图从 B 句中选正确句
loss_t2i = F.cross_entropy(scores.T, targets)        # 每句话从 B 图中选正确图
loss = (loss_i2t + loss_t2i) / 2                     # 两个方向同等重要
optimizer.zero_grad()                                # 清掉上一批累积梯度
loss.backward()                                       # 对两个编码器和温度等参数求梯度
optimizer.step()                                      # 用梯度更新参数
```

`F.cross_entropy` 接受**未 softmax 的 logits**和整数类别下标，内部做 log-softmax/负对数似然；提前对 `scores` 做 softmax 反而会改变其预期输入。`scores.T` 是二维转置，行列交换后同一对角线仍是真配对。`optimizer.zero_grad()` 在 PyTorch 中清旧梯度；`backward()` 计算并累积新梯度；`step()` 才真正修改参数。

这段代码成立的前提是每个 batch 的图片和描述按相同索引一一对应。如果同一张图片出现多条正确描述，或 batch 行列不是同序，就不能机械把“只有对角线”为唯一正例。官方仓库没有完整训练入口，本工作区的 TinyCLIP 是**教学简化模型**，其代码和已训练小样本结果不能当作官方大模型复现。
