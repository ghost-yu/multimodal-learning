# BEiT-3 论文与代码解释

## 1. 先认清正在读的版本

论文是 **Image as a Foreign Language: BEiT Pretraining for All Vision and Vision-Language Tasks**。本地 [原论文](原论文.pdf) · [中文论文](中文论文.pdf) · [双语论文](双语论文.pdf) 是 arXiv:2208.10442v2，2022 年 8 月 31 日版本，共 18 页。BEiT 名字源于 BERT Pre-Training of Image Transformers；BERT 是 Bidirectional Encoder Representations from Transformers，意为基于 Transformer 的双向编码表示。数字 3 表示这一代模型，而不是只有三层网络。

当前官方 UniLM 仓库提交为 `31c5b904ca1bf2afb4c234a6675c683a4e5fc7cd`。它的 `beit3` 目录主要发布 **Base/Large 模型的下游微调实现**，并使用外部 `torchscale==0.2.0` 骨干。本文没有把源码存在等同于 1.9B 原论文预训练完整发布。

为了让你能沿调用链继续读，我下载了 requirements 中的准确依赖版本，保存在 [torchscale 0.2.0 源码](代码/torchscale-0.2.0/torchscale)。[来源记录](代码/来源记录.json) 保存版本、下载来源与原始包 SHA256。**下载源码供阅读不等于把它安装进当前环境**；原文件 `import torchscale` 实际读取的是对应 Python 环境中的安装包。

### 1.1 有三处重要版本边界

1. 论文是 Giant：40 层、宽度 1408，顶部三层有 VL-FFN（图文专家）；公开下游 Base/Large 与依赖中 `MultiwayNetwork` 是 A/B 两分支。已检查 BEiT3、Encoder、MultiwayNetwork，未找到对应论文“顶部三层独立第三专家”的路径，不能凭示意图给代码虚构第三分支。
2. 论文主预训练数据是 21M 图文对、14M 图像、160GB 文本；README 后来发布的权重还说明了 LAION/COYO 等不同训练来源。论文与后续权重配方不能当作同一实验。
3. 论文 ImageNet Giant 分类使用图像与类别名字的检索式分类；公开 `BEiT3ForImageClassification` 则平均图片 patch，再接线性分类头。它们任务相同，具体适配方式不同。

这是本篇学习的前提：分别说明论文思想和能看到的实现，保持对应边界。

## 3. “图片是外语”是什么意思？【必须会】

一句话可以拆成很多文字 token；一张图片可以拆成很多 patch（小块）。分别变成向量后，二者都可以作为 Transformer 的输入序列。作者把图片语言比喻为 **Imglish**，图文配对比喻为“平行句子”：两种形式表达相关内容，可通过联合上下文学习对应关系。

这个比喻**不表示 RGB 像素直接成为中文字，也不表示图片和文字共用同一个输入词表**。

要区分图像训练中的两条路径：

- **输入表示**：把原始图片分 patch，经可学习卷积投影为连续向量；被遮盖 patch 用 MASK 向量替代。
- **预测目标**：利用 BEiT v2 的视觉 tokenizer 为原图得到离散视觉编号，模型预测这些编号。

视觉 tokenizer 是产生监督目标的工具；patch embedding 是骨干内部把图片变成输入向量的层。即使二者都出现 token 这个词，职责也不同。原版下游分类/检索代码没有实现完整的视觉 tokenizer 预训练数据流水线。

## 4. 三种输入都做“遮盖再预测”

### 4.1 纯文字

遮盖 15% 的文字 token，根据其他词猜回原词。例如“猫坐在 `[MASK]` 上”，模型利用上下文预测“椅子”。预训练是双向上下文，和下一词生成的严格左到右不同。

### 4.2 纯图片

用块状策略遮盖 40% 图片 patch，预测其离散视觉编号。块状遮盖不是把所有图片随机涂成黑色；输入使用 mask token，训练目标来自未遮盖原图的视觉 tokenizer。

### 4.3 配对图文

论文在图文对文字部分遮盖 50%。图片和文字共同参与上下文，图片能提供被遮盖词的线索。这比只遮盖少量词更要求模型使用跨模态信息，但不能由遮盖率单独证明模型一定学会视觉推理。

### 4.4 用一个教学公式理解【必须会】

论文正文以任务描述和结构图说明遮盖预测，没有给这部分一个可直接照抄的编号损失公式。下面是帮助理解的**未编号教学表达式**：

$$\mathcal L_{\mathrm{mask}}=-\frac1{|\mathcal M|}\sum_{i\in\mathcal M}\log p_\theta(z_i\mid\widetilde X).$$

$\mathcal M$ 是被选作预测目标的位置集合；$|\mathcal M|$ 是其数量；$i$ 为位置索引；$z_i$ 是正确文字或视觉离散编号；$\widetilde X$ 是遮盖后的输入；$\theta$ 是网络参数；$p_\theta$ 是模型给正确编号的概率。

假设两个目标的正确概率为 0.8 和 0.4，平均损失为 $[-\log0.8-\log0.4]/2\approx0.570$。提高正确概率能降低损失。文字与视觉目标可能使用不同输出词表/预测头；上式表达统一的任务形式，不意味着共享同一个类别空间。

公开本目录是下游训练，不要把 `utils.ClipLoss` 误认成这里的遮盖预训练目标。检索阶段可以用对比学习，论文也明确采用了后续 ITC 调优。

## 5. Multiway：共享注意力，区分模态处理【必须会】

每个 token 先参加共享 self-attention（自注意力），再通过适合其模态的 FFN。

FFN 是 Feed-Forward Network，前馈网络，通常是两次线性变换与中间激活。MLP 是 Multi-Layer Perceptron，多层感知机；在这里指相近的逐 token 非线性特征变换模块。

共享注意力负责“这些位置之间如何交流”；模态专家负责“交流后的内容怎样加工”。图片 patch 与词的统计特征不同，使用不同 FFN 有助于保留模态特点。

注意这里不是 Uni-Perceiver-MoE 那种通过可学习门控给任意 token 选择 top-k 专家。公开 `MultiwayNetwork` 根据已知模态边界直接分配到 A/B，路由规则确定。

### 5.1 当前公开代码怎样路由？

打开 [MultiwayNetwork](代码/torchscale-0.2.0/torchscale/component/multiway_network.py)：

| `split_position` | 意义 | 执行 |
|---|---|---|
| -1 | 纯视觉 | 全部输入 `self.A` |
| 0 | 纯文字 | 全部输入 `self.B` |
| 正整数 I | 前 I 项为视觉，后面为文字 | split → A/B 各自处理 → cat 恢复序列 |

`A` 与 `B` 只是源代码标识。`copy.deepcopy(module)` 把模块及参数递归复制，使它们为独立对象；不是给同一权重起两个名字。随后重新初始化 B。

`set_split_position` 返回闭包：内层函数记住外层传入的整数，供 `nn.Module.apply` 递归设置所有包含 `split_position` 的子模块。它不是让注意力权重自动学习边界。

### 5.2 一批配对图文的形状

用公开 Base 配置：$B=2$，图片 224×224，patch=16，隐宽 $D=768$，文字长度 $T=10$。

1. 图像 `[2,3,224,224]` 经 patch 卷积得到 14×14=196 个 patch。
2. 展平、交换轴后为 `[2,196,768]`。
3. 添加开头视觉 CLS，为 `[2,197,768]`，记 $I=197$。
4. 文字编号 `[2,10]` 查 Embedding 表，为 `[2,10,768]`。
5. 在序列维拼接，得到 `[2,207,768]`；`multiway_split_position=197`。
6. 共享注意力可以跨图文读取（除非任务掩码限制），A/B FFN 分别处理前 197 与后 10 项。
7. `encoder_out` 的隐藏状态仍为 `[2,207,768]`，任务头决定选哪些位置和输出什么。

论文 Giant 使用 patch 14，224/14=16，得到 256 个 patch，不能把公开 Base 的 196 与论文的 256 混用。

### 5.3 MASK 与 padding 不是一回事

MASK 表示有真实目标但故意隐藏，让模型预测；padding 是为了对齐长度加的空位，通常不应算真实内容。

`text_padding_position=True` 在这份骨干里表示 **应屏蔽的补齐位**；CoCa 的 `text_valid=True` 表示 **真实有效位**。代码名都含 mask，但布尔含义相反，逐项目检查接口。

融合路径先构造全 False 的视觉 padding 标记，再接文字 padding，形状 `[B,I+T]`。`attn_mask` 则是 query/key 之间的连接矩阵，用于控制双向或因果读取；它和 token padding 掩码职责不同。

## 7. 从检索任务看懂完整前向【必须会】

打开 `BEiT3ForRetrieval.forward`。图片与文字分别调用同一个骨干对象：

- 图片调用 `textual_tokens=None`，走视觉分支，取第 0 个视觉 CLS，过 `vision_head`。
- 文字调用 `visual_tokens=None`，走文字分支，取第 0 个输入文字标记状态，过 `language_head`。
- 对两种向量用 `F.normalize(...,dim=-1)` 单位化，得到 `[B,D]`。

head 是投影头；两个 `Linear(D,D,bias=False)` 宽度相同，但参数不共享。两边分别算好向量后可以缓存，检索时只需矩阵点积。

教学表达式为 $S=\alpha VU^\top$：$V,U$ 各为 `[B,D]`，$S$ 为 `[B,B]`，$\alpha=\exp(\text{logit_scale})$ 是正的温度倒数。训练正确配对在对角线上，`ClipLoss` 计算双向分类损失；`only_infer=True` 只返回向量。

`only_infer=False` 又缺少图片或文字时，不能期待正常计算配对损失；只模态推理请明确设 `only_infer=True`。

### 7.1 为什么评估时要按 image_id 去重？

同一图片往往有多条描述，DataLoader 会遇到重复图片。`RetrievalHandler.after_eval` 以图片 ID 保存一次图像向量，文字向量保留各条描述，再计算所有图文相似度。R@1 判断正确目标是否出现在第一候选；不能把训练损失下降直接当作 R@1 上升。

## 8. 融合任务：NLVR2 与 VQA

### 8.1 NLVR2【建议会】

输入是图 a、图 b 与同一句说明，判断说明是否符合这对图片。

`BEiT3ForVisualReasoning` 把图 a/b 在 batch 维拼成 `2B` 张，把文字也复制成 `2B` 条，一次调用融合骨干。注意是**沿样本轴拼接**，不是把两张图片像素左右粘在一起。

每个图文对取视觉 CLS `[2B,D]` 与文字第一项 `[2B,D]`，在特征维拼成 `[2B,2D]`。按 batch 切回 a/b 两组，再按特征拼成 `[B,4D]`，交给两层 MLP 二分类。Handler 使用普通交叉熵。

`bsz`=batch size，`cls_rep`=CLS representation，`multiway_split_position`=文字起始的序列边界。隔几段再看到这些名字时，回到这个形状轨迹。

### 8.2 VQA【建议会】

VQA 是 Visual Question Answering，视觉问答。图像和问题融合编码后，`Pooler` 读取拼接序列第 0 个位置——视觉 CLS 的融合状态。它经过 LayerNorm、Linear、Tanh，再进入答案分类头。

公开代码是 **3129 个常见答案候选分类**，不是自由生成任意回答。训练标签可以包含多个人工答案产生的软分数，所以 Handler 用 `BCEWithLogitsLoss`，逐答案计算二元交叉熵，并乘答案数量调整归约尺度。不能把它误写成普通“单一正确类别的 softmax CE”。

`Pooler` 的名称常见于多个项目：这里直接取 CLS 再投影，和 CoCa 的注意力查询池化器不同。

## 9. Caption：统一注意力掩码怎样实现生成？【必须会】

`BEiT3ForCaptioning.forward` 对拼接序列 `[图片 I 项,文字 T 项]` 构造矩阵：

$$
\text{允许读取}=\begin{bmatrix}
\mathbf1_{I\times I}&\mathbf0_{I\times T}\\
\mathbf1_{T\times I}&\operatorname{tril}(\mathbf1_{T\times T})
\end{bmatrix}.
$$

行表示 query 在哪里，列表示它读取的 key 在哪里。左上：图片互相看；右上：图片不看文字；左下：文字看全部图片；右下：文字只看自己与左侧文字。

为什么图片不能读取未来文字？因为若图片隐藏状态已经含未来答案，文字再读取图片就能间接泄漏答案，即使右下角是三角掩码也没有用。

`torch.tril` 取下三角；`uni_mask=1-uni_mask` 将“1=允许”的构造转换成这份骨干“1=屏蔽”的约定。别与 PyTorch 其他注意力接口的布尔语义混用。

`language_masked_pos` 为 `[B,T]`，标出需要预测的文字位置。布尔索引 `text_feats[language_masked_pos.bool()]` 把这些位置汇成 `[M,D]`，`mlm_head` 输出 `[M,V]`，对应真实目标 `[M]`。`M` 是选中位置总数，不是 batch 数。

这份实现是**遮盖式条件生成微调**。不能机械套 CoCa 的 `logits[:,:-1]` 与 `text[:,1:]` 来解释所有位置；这里首先按遮盖位置选监督目标，推理则在末尾逐步预测。

`incremental_state` 是增量解码缓存，各层可保存历史 key/value。后续步骤可以只输入新词，不再输入图片；相关位置编号遵循 Fairseq 从 2 开始的约定。它属于第二遍工程内容，不能把它理解成 optimizer 的动量状态。

数据与训练调用链的进一步解释见 [数据到训练解释](资料/数据到训练解释.md)，覆盖分词两步、组批、caption 遮盖、VQA 软标签、梯度累积及原仓库验证加载器的调用边界。

| 表 4，COCO METEOR | CoCa 33.9，BEiT-3 32.4 | 下降 1.5；CIDEr 更高不能推出所有 caption 指标都更高 |
| 表 5，COCO 5K 图找文 R@1 | Florence 81.8，BEiT-3 84.8 | +3.0 点；文字找图 63.2→67.2，+4.0 |
| 表 5，Flickr 1K 图找文 R@1 | Florence 97.2，BEiT-3 98.0 | +0.8；文字找图 87.9→90.3，+2.4 |
| 表 6，Flickr zero-shot | CoCa 图找文 92.5，BEiT-3 94.9；文找图 80.4→81.5 | +2.4/+1.1；中间已有 ITC 调优，不是所有训练阶段只使用遮盖损失 |
| 表 7，COCO box AP | DINO 63.3，BEiT-3 63.7 | +0.4；Object365 中间调优、多尺度评价必须计入协议 |
| 表 7，mask AP | Mask DINO 54.7，BEiT-3 54.8 | +0.1；不是训练误差，也不等于分类准确率 |
| 表 8，ADE20K | BEiT-3 单尺度 62.0、多尺度 62.8 mIoU；FD-SwinV2-G 多尺度 61.4 | 同多尺度列 +1.4；不能拿不同列忽略评价成本 |
| 表 9，ImageNet 公共 image-tag 数据组 | FD-CLIP 89.0，BEiT-3 89.6 | +0.6；私人数据组 CoCa 91.0 更高，不能宣称 BEiT-3 超过全部模型 |

mIoU=mean Intersection over Union（类别平均交并比），用于像素分割；AP=Average Precision（平均精度），用于检测/实例分割；R@K=Recall at K，判断前 K 候选是否命中。指标不同，不能把全部列平均成一个“多模态准确率”。

表 1 的检索 R@1 是两个方向的平均。COCO $(84.8+67.2)/2=76.0$；Flickr $(98.0+90.3)/2=94.15$，表中舍入到 94.2；zero-shot $(94.9+81.5)/2=88.2$。理解这个计算，才能把摘要表与分方向表对上。

总体结果同时改变模型规模、预训练数据与训练过程，不能单凭这些跨模型比较断言“所有增益都来自某一个 FFN 专家”。本地 v2 正文没有提供把所有因素逐一控制的完整消融证据，不虚构消融数字。
