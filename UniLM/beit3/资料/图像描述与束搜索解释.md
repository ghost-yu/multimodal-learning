# BEiT-3 图像描述与束搜索解释

## 1. 这条路径解决什么问题

图片描述（image captioning）输入图片，输出一句自然语言描述。一个词表头只能给某个位置的所有词打分；要生成完整句子，还需要安排当前位置、决定选哪个词、保留多个候选、判断什么时候停止，最后把词编号还原成文字。

当前代码的主链：数据集生成遮盖文字 → `CaptioningHandler.train_batch` → `BEiT3ForCaptioning.forward` → 选目标位置 → `BertCaptioningLoss`。推理链：`CaptioningHandler.eval_batch` → 两个当前文字 token + 缓存 → 词表分数 → beam search → 完成候选 → tokenizer decode。

源码入口：[处理器](../engine_for_finetuning.py)、[模型](../modeling_finetune.py)、[损失和候选容器](../utils.py)。三文件本次新增 149 处详细说明；注释前快照和 AST 比较见 [核对](caption注释核对.json)。这些注释不修改原版算法。

## 2. 先认清几个容易混淆的名字

| 名字 | 展开/命名原因 | 当前含义 |
|---|---|---|
| B | batch size，批量大小 | 原始图片数量 |
| K / num_beams | 同时探索的束数 | 每张图片保留 K 个活跃前缀 |
| V / vocab_size | vocabulary size，词表大小 | 所有可输出 token 的数量 |
| T / max_len | maximum length，最大长度 | 输出缓冲容量，包含特殊 token |
| cur_len | current length，当前逻辑长度 | 历史长度，包括待预测 MASK |
| cur_input_ids | current input token IDs | 每轮实际送进模型的两个文字编号 |
| decoding_results | 解码结果缓冲 | 每条候选的完整累计历史，不是短输入 |
| hyp / hypotheses | hypothesis，候选假设 | 一个可能的句子或候选容器 |
| beam_scores | 活跃束分数 | 前缀的累计 log 概率 |
| conf | confidence 的历史短写 | 完成句子的长度归一化 log 分数，不是概率 |
| incremental_state | incremental=增量，state=状态 | 各层缓存的 key/value |
| qid | 常见 question ID 缩写 | 当前代码实际来自 image_id，是图片编号 |

CLS（classification token）在这里作为起始标记；MASK 为待预测位置；SEP（separator）在这条路径用作 EOS（End Of Sequence，结束标记）；PAD（padding）用于补齐。它们各有独立词表编号，不能把 MASK token ID 与布尔注意力 mask 混为一谈。BPE 配置指子词 token 数，不等于英文单词数量。

## 3. 训练如何连接到生成

### 3.1 训练位置和标签

【必须会】`language_tokens` 保存原正确文字 $[B,T]$；`masked_tokens` 是送入模型的遮盖/替换版本；`language_masked_pos` 指哪些位置需要预测。把最后一项转为布尔值，用 `language_tokens[mask]` 取答案，得到 $[M]$，其中 $M$ 是整批被选中的位置数。

模型把文字隐藏状态 $[B,T,D]$ 按同一布尔 mask 选为 $[M,D]$，再用词表线性头得到 $[M,V]$。标签顺序与 logits 顺序必须一致。这条代码不是把整句固定错开一位再预测的 CoCa 写法，不能直接把另一个项目的标签切片照搬过来。

### 3.2 统一注意力掩码

将视觉 token 放在文字 token 前面，设视觉序列长度为 $I$，整体长度为 $I+T$。注意力矩阵行是 query（谁正在读取），列是 key（读谁）：

| query → key | 视觉 | 文字 |
|---|---|---|
| 视觉 | 全可见 | 不可见 |
| 文字 | 全可见 | 只可见当前位置和更早位置 |

文字不能看右边正确答案；视觉不依赖未来文字，才能缓存并复用。源码先以 1 表示允许，再 `1-uni_mask` 反转为骨干的屏蔽约定：0 允许、1 禁止。其他框架的布尔 mask 约定可能相反。

当前被预测位置的输入是 MASK，所以允许看自己不等于泄露正确词。训练预处理仍可能按其遮盖策略使用替换/原词，需与数据章节一起读；单看下三角并不能证明所有数据构造没有信息泄露。

### 3.3 标签平滑 KL 损失

【必须会】原类 `BertCaptioningLoss` 使用平滑目标：正确词概率 $1-\epsilon$，其余 $V-1$ 个词各 $\epsilon/(V-1)$。

$$q_{mc}=\begin{cases}1-\epsilon&c=y_m\\\epsilon/(V-1)&c\ne y_m\end{cases},\quad p_m=\operatorname{softmax}(z_m).$$

$m$ 是第几个被预测位置，$c$ 是词表索引，$y_m$ 是正确词 ID，$z_m$ 是该位置的词表 logits。计算：

$$\mathcal L=\frac1M\sum_{m=1}^M\sum_{c=1}^Vq_{mc}(\log q_{mc}-\log p_{mc}).$$

`nn.LogSoftmax(dim=1)` 稳定求 $\log p$；`nn.KLDivLoss(reduction='none')` 接收 log 预测概率与普通目标概率。词表维 sum 后得到每个位置的损失，再 mean。KL 等于平滑交叉熵减去目标熵；目标固定时梯度一致，损失数值相差常量，不能逐值当成完全同一个损失。

数字例：$V=3,\epsilon=0.1$，正确词为0时目标是 $[0.9,0.05,0.05]$。两行 logits 为 $[2,0,-1]$ 和 $[0,1,-1]$，标签为0和1，本次原损失类实际运行结果约 **0.09432826**，与按公式手算一致，反传梯度有限。

`drop_worst_ratio` 在超过 `drop_worst_after` 后保留最小损失的若干目标位置，`largest=False` 是关键。保留数为 `int(M*(1-r))`：若 $M$ 很小或 $r$ 很大，可能变0，空损失 mean 会是 NaN；零目标也有风险。本次未改原代码，只说明配置需要避免的边界。过滤难位置也不等于清洗出错数据的严格证据。

## 4. 为什么每轮只输入两个 token

【必须会】初始文字为 `[CLS,MASK]`，`cur_len=2`。第一步输入图片和这两个文字 token，模型预测 MASK，选出词 A。接着输入变为 `[A,MASK]`，但图片和 CLS 的 key/value 已在缓存里。因此本次实际输入还是2项，逻辑总长度却变3。

下一步选出 B 后，输入 `[B,MASK]`，逻辑长度变4。缓存保存图片、CLS、此前已确定词，模型无需每次重新处理完整历史。

| 轮次 | 本次文字输入 | 逻辑长度 | 图片是否传入 |
|---|---|---:|---|
| 1 | CLS, MASK | 2 | 是 |
| 2 | A, MASK | 3 | 否，使用缓存 |
| 3 | B, MASK | 4 | 否，使用缓存 |

每轮预测输出索引1，即短输入最后的 MASK；不是用 `cur_len-1` 索引短张量。`BEiT3ForCaptioning.forward` 后续只取统一掩码最后两条 query 行，key 列仍覆盖完整视觉/文字历史。

位置编号也要延续历史。文字位置表采用从2开始的约定：第一轮 CLS/MASK 在2/3；第二轮 A/MASK 在3/4。后续 `arange(text_len,text_len+2)` 与这个偏移相配合，不能每轮都重置为0/1。

## 5. K 条 beam 的展开与选择

### 5.1 批量怎么变成 BK

每张图片原来一条起点；`unsqueeze(1)` 增加 beam 轴，`expand` 得 $[B,K,\ldots]$，再 `contiguous().view(...)` 合并为 $[BK,\ldots]$。`expand` 常是共享内存视图，后续 contiguous 才可能复制。图片会相应扩为 $[BK,3,H,W]$，显存和首轮视觉计算随 beam 数增加。

起始 `beam_scores` 为 $[B,K]$，每图第0条是0，其余为 $-10^9$。虽然 token 起点复制了 K 份，但只允许第一条作为有效起点，防止重复前缀占满候选槽。

### 5.2 评分和词编号

模型在当前 MASK 给分数 $[BK,V]$。`F.log_softmax` 把它变成 $\log p(w\mid\text{prefix},I)$；每格再加此前 beam 的累计分数：

$$S(\text{prefix}+w)=S(\text{prefix})+\log p(w\mid\text{prefix},I).$$

加 log 概率等于乘各步概率，数值更稳定。累计 log 概率一般非正，数值越大（越接近0）越好。

然后合成 $[B,KV]$，每图在 K 个父候选和 V 个新词的所有组合里共同选取 `3*K` 个最高分。源码名称 `TOPN_PER_BEAM=3` 不表示每个父候选强制独立选3项。

`topk` 返回值与展平索引。若 $V=10$，索引17代表父候选 $17//10=1$、新词 $17\%10=7$；它不是词17。全局父行号为 `batch_ex*K+beam_id`。

举例两条父前缀分数为 -0.2、-1.0；对某词的新 log 概率为 -0.3、-0.1，扩展总分为 -0.5、-1.1。不能只看新词 -0.1 更高就选第二条，必须加上历史。

### 5.3 活跃候选与完成候选

普通词候选进入 `next_sent_beam`，继续探索；EOS 候选进入 `generated_hyps`，保存完成句子。每图活跃候选仍需凑满 K。`num_keep_best=1` 只表示最后输出一条，和 K 条活跃 beam 是两件事。

`BeamHypotheses.add` 用 $S/L^\alpha$ 评分并保留至多 `n_hyp` 条完成句；$L$ 是其接到的保存 token 序列长度。它不返回概率，`conf` 不能直接解释为“置信度80%”。因为 log 概率通常非正，除以较大的正长度幂会更接近0，能减轻短句偏好；并非每个词减固定罚分。

`is_done` 在完成候选足够时，用最大长度估计活跃候选的分数上界；当前 `early_stopping=False`，不是见到第一次 EOS 就整个批量停。已经完成的图片用 PAD 占位维持 BK 张量尺寸，直到所有图结束或长度耗尽。

## 6. 缓存为什么需要重排和截掉最后一位

【建议会】新的候选可能来自同一个父 beam。例如父行号 `[1,1]` 表示该父句分成两个不同新词。结果缓冲、当前输入、每层缓存都必须用同一个 `beam_idx` 复制/重排；只改文字而不改缓存会把新词接到错误历史。

此依赖版本使用的缓存形状为 $[BK,h,L_c,d_h]$：$h$ 是头数，$L_c$ 是缓存序列长，$d_h$ 是每头宽度。`index_select(0,beam_idx)` 按批量轴重排；`result[:,:,:-1,:]` 沿缓存序列轴删除最后一个位置。

被删的是刚用来预测的临时 MASK。下一轮把选出的真实词重新编码，替换它；图片、CLS 与更早文字保留。若不删 MASK，模型会在缓存里积累一串临时占位，既改变位置长度，也改变注意力上下文。

原 Handler 假设缓存内各项都是此种4维张量。升级依赖后若缓存包含其他对象/不同布局，不能继续无条件应用相同裁剪。当前局部检查用匹配这个协议的模拟 key/value，未证明真实骨干所有层数值正确。

## 7. 当前代码的结束边界

EOS/最大长度分支调用 `generated_hyps.add` 时，保存 `decoding_results[:cur_len]`，而这轮新词尚未经过后面的赋值写入缓冲。因此：

- 正常 EOS 分支保存的末位可能还是 MASK，后面显式再加 EOS，decode 使用 `skip_special_tokens=True` 去掉它。最终文本可以正常，但长度归一化包含这个占位长度。
- 达最大长度时，即使新词不是 EOS，也走完成分支。刚选中的普通词没有写入保存序列，可能被丢掉。

本次运行原 Handler 的固定输出模拟模型，正常容量8输出 `a dog`；容量4在选到 dog 时到边界，最终输出 `a`。这是观察到的原版行为，尚未对真实检查点估计影响，也没有擅自修补原实现。最终缓冲最后再添加 EOS 和 PAD，`batch_decode(...,skip_special_tokens=True)` 转成文本。

另一个接口边界：`eval_batch` 签名 `image_id=None`，但末尾 `zip(image_id,captions)` 实际要求可遍历编号；真实调用必须提供 image_id。`squeeze(1)` 也依赖最终保留数1，若扩展为多句输出，decode 输入处理需要同步改。
