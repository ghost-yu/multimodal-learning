# BEiT-3 数据到训练解释

本文接续 [主讲解](../解释.md)，对照 `datasets.py`、`utils.merge_batch_tensors_by_dict_key` 和 `engine_for_finetuning.py`。以下是静态源码阅读，尚未运行 BEiT-3 训练。

## 1. 先看完整调用链【必须会】

`create_downstream_dataset → create_dataset_by_split → build_transform / tokenizer / Dataset → create_dataloader → collate → train_one_epoch → Handler.train_batch → model.forward → criterion → backward/step`。

Dataset 是“单条样本怎样读取”的规则；DataLoader 是“哪些样本组成一批”的规则；Handler 是“当前任务怎样给模型传参数、怎样取损失”的规则。三者都不是骨干 Transformer。

`args` 是命令行解析的配置对象，例如 `args.task` 是任务字符串，`args.input_size` 是图像边长，`args.batch_size` 是每个进程的批大小。字段本身不训练。

## 2. 单条样本与批次不是同一种形状【必须会】

| 字段 | 单条样本 | 组批后 | 名称与用途 |
|---|---|---|---|
| image | float Tensor `[3,H,W]` | float Tensor `[B,3,H,W]` | RGB 图像；B=batch，H/W=高/宽 |
| language_tokens | 长度 T 的整数 list | int64 Tensor `[B,T]` | language=语言，tokens=词元；词表编号不是概率 |
| padding_mask | 长度 T 的 0/1 list | int64 Tensor `[B,T]` | padding=补齐；1 是补齐位置，0 是真实位置 |
| image_id | 整数 | int64 Tensor `[B]` | id=identifier，样本对应图像标识，用于配对或结果保存 |
| masked_tokens | 长度 T 的整数 list | int64 Tensor `[B,T]` | masked=被遮盖后的输入；caption 微调使用 |
| language_masked_pos | 长度 T 的 0/1 list | int64 Tensor `[B,T]` | pos=position；1 是计算文字监督的位置 |

这里 `T` 表示固定文本长度，含特殊词与 PAD。`B` 表示当前进程中的样本数，不自动等于所有 GPU 的样本总数。

`utils.merge_batch_tensors_by_dict_key(batch)` 接收长度 B 的样本字典列表。它遍历第一条字典中的键；如果该字段已经是 Tensor，就用 `torch.stack` 新增批次轴。如果不是 Tensor，就用 `torch.tensor(..., dtype=torch.long)` 将嵌套数字转成整型 Tensor。由此要求同一批字段结构一致、文本已是数字、长度可以对齐。任意字符串不能直接经过这个组批函数。

`stack` 新增轴，例如两个 `[3,H,W]` 变 `[2,3,H,W]`；`cat` 沿已有轴拼接，例如两个 `[1,3,H,W]` 沿第 0 轴变 `[2,3,H,W]`。不能只看最后形状相同就认为操作可互换。

## 3. 分词的两步与索引文件【必须会】

JSONL=JSON Lines，每行独立一个 JSON 对象。索引保存图片路径、整数词列表、标签等元数据。`BaseDataset.__init__` 读入索引字典，取样时才加载图像，不是在初始化阶段读入全部图像像素。

`XLMRobertaTokenizer` 来自 transformers 库，使用 SentencePiece 模型。这里只实例化分词器，没有创建 XLM-R 语言模型。分词模型的词表编号要和神经网络 Embedding/checkpoint 匹配。

- `tokenizer.tokenize(text)`：字符串 → 子词字符串列表。
- `tokenizer.convert_tokens_to_ids(tokens)`：子词字符串列表 → 整数编号列表。

COCO 索引制作函数实际执行这两步后把 `token_ids` 写入 `text_segment`。`_get_text_segment` 的字符串分支却只调用第一步；因此直接给它原始文本不能假设后续整数组批和 Embedding 会成功。这里保留原源码并注释这个边界，没有把阅读注释变成未经验证的功能修复。

`num_max_bpe_tokens` 中 num=number，max=maximum，BPE=Byte Pair Encoding。它是沿用的字段名；当前 tokenizer 使用 SentencePiece，不应只凭变量名推断所有分词细节。

## 4. 截断、特殊词、补齐【必须会】

假设上限 `max_len=6`，内容词编号是 `[10,11,12]`，BOS=0、EOS=2、PAD=1（这只是说明例子，实际从 tokenizer 读取）。

1. 最多保留 `max_len-2=4` 个内容词，为 BOS/EOS 留位置。
2. 前后加特殊词：`[0,10,11,12,2]`。
3. `num_tokens=5`，表示真实长度，包括 BOS/EOS、不含补齐。
4. 补成 `[0,10,11,12,2,1]`。
5. `padding_mask=[0,0,0,0,0,1]`。

注意 PAD 的词编号是 1，与 padding_mask 的 1 表示“屏蔽”只是本例数值碰巧相同；两个变量有不同用途。实际编号取决于词表；不能把这个例子的 BOS/PAD/EOS 数值当作所有模型通用约定。

`tokens[:]` 是列表浅拷贝。当前元素是整数，复制列表即可避免后续改列表位置时修改长期索引；对于含嵌套可变对象的列表，浅拷贝不会递归复制内部对象。

## 5. Caption 遮盖微调【必须会】

`language_tokens` 保存原答案；`masked_tokens=language_tokens[:]` 保存独立的输入列表。先复制再替换，否则正确答案也会被改掉。

`language_masked_pos` 记录哪些位置被选为监督目标，与 `padding_mask` 不同。选为目标的词可以被换成 MASK、保留原词或换成随机词，仍然计算监督。

选位数量为 `min(int(num_tokens*mask_prob+0.5), num_tokens-1)`，再至少取 1。`random.randint(1,num_tokens-1)` 两端都包含：排除位置 0 的 BOS，包含 EOS，排除末尾 PAD。重复选中的位置不会重复计数。

对已经选中的位置，`random.random()` 决定输入：80% 换 MASK，10% 保留原词，10% 随机换词。这个 80/10/10 是**条件于已选中的位置**，不是全句中 80% 的词一定遮盖。

Handler 中 `masked_labels=language_tokens[language_masked_pos.bool()]`：`bool()` 将 0/1 转为布尔掩码；布尔索引把 B 条句子的选中位置依次取出成为 `[M]`，其中 M 是总选位数。模型返回 `[M,V]` 分数，V=vocabulary size（词表大小）。监督答案与模型分数的选择顺序必须相同。

这条路径是遮盖文字位置的训练，不能把 CoCa 的下一词位移标签机械套上来；因果可见性由 BEiT-3 caption 模型自己的注意力掩码负责。

## 6. VQA 的软目标与损失【建议会】

VQA=Visual Question Answering（视觉问答）。同一问题有多位标注者答案，因此 `labels` 不是单个整数类别，而是 `[B,A]` 的答案候选分数，A=answer vocabulary size。

`BCEWithLogitsLoss` 的 BCE=Binary Cross Entropy；WithLogits 表示它接受原始 logits，内部稳定合入 sigmoid，不要先手工 sigmoid 再喂给这个损失。它对每个答案候选独立计算，不是要求所有候选概率之和为 1 的 softmax 交叉熵。

默认 mean 对 B×A 个项平均。源码再乘 `labels.shape[1]=A`，得到每样本所有答案项之和，再对 B 个样本平均。若逐项损失为 0.2、0.4、0.6，B=1、A=3，mean 为 0.4，乘 A 后为 1.2。

`logits.float()` 转为 float32，不会切断梯度；`detach()` 才会从当前求导图分离张量。

## 7. 训练循环与梯度累积【建议会】

`data_iter_step` 是数据迭代的微批次编号；`update_freq` 是积累多少次再更新；`step=data_iter_step//update_freq` 是优化步编号。`//` 是整除。四个微批次 0、1、2、3 在 update_freq=4 时都属于 step=0。

`global_step=start_steps+step` 继续前面 epoch 的编号，用于学习率等调度。`lr_schedule_values[global_step]*param_group['lr_scale']` 将全局学习率乘当前参数组的比例；lr=learning rate，scale=缩放，param_group=优化器中的参数及超参数组。

`loss/=update_freq` 将每个微批次损失按次数缩小，使累积梯度接近有效大批次的平均尺度。这个对应依赖微批次规模及损失归约方式，不是任意不同大小微批次都严格等价。

当前训练函数区分两条路径：

- `loss_scaler is None`：`model` 预期是 DeepSpeed engine；调用 `model.backward(loss)` 与 `model.step()`。普通 nn.Module 没有这套训练接口。
- 存在 `loss_scaler`：在 CUDA autocast 中前向，再由 scaler 管缩放、反传、裁剪以及累积边界更新。

`model.train(True)` 改变 Dropout 等模块行为，不是开启自动求导的唯一开关。评估同时使用 `model.eval()` 和 `@torch.no_grad()`：前者改模块行为，后者不记录求导图。

`torch.cuda.synchronize()` 等待 GPU 运算完成，说明原训练入口有显式 CUDA 假设；不能只把 device 改成 cpu 就宣称已兼容 CPU。

## 8. 图像增强与调用边界【建议会】

训练的 RandomResizedCrop 随机裁剪再缩放；RandomHorizontalFlip 随机左右翻转；ToTensor 将 PIL RGB 变成 `[3,H,W]`；Normalize 按通道做 `(x-mean)/std`。这些操作顺序有意义，Normalize 需要先有浮点像素 Tensor。

多模态任务使用 INCEPTION 均值/标准差；ImageNet 分支使用 DEFAULT 均值/标准差。权重对应的预处理应保持一致，不要把库里所有 mean/std 当作可随意互换。

`Resize((S,S))` 直接变正方形；`Resize(S)` 通常按短边缩放并保持比例。ImageNet 评估中先 `size=int(input_size/crop_pct)` 缩放，再 CenterCrop。两条路径含义不同。

分布式 sampler 的 `num_tasks` 实际是 world_size（进程总数），不是学习任务数量。默认会为等长分片补重复样本，评价时须注意汇总/去重。`drop_last=is_train` 则丢掉不完整尾批。

**源码边界：** `create_downstream_dataset` 非 is_eval 分支给 train 和 val 都传 `is_train=True`。这会使 val 加载器使用训练增强、抽样及 drop_last；`split='val'` 本身不会覆盖这些开关。当前记录原始行为，正式评价应继续核查入口及协议，不能凭 val 名称假定完整确定性评估。
