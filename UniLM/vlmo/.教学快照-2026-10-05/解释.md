## 论文先解决什么问题【必须会】

假设有 10 万张图、10 万句文字。若让融合模型为每一种图文组合都跑一次深层网络，组合有 $10^5\times10^5=10^{10}$ 个，检索成本很高。双编码器各算 10 万个向量，然后批量点积，可以重用表示；但只看两个全局向量，回答“球员手里的是什么”等细粒度问题时信息可能不够。VLMo 让**同一组分层参数**服务两条调用路径：分开输入时是双编码器，拼接输入时是融合编码器。关键不是临时训练两个完全不同的模型，而是每层共享注意力、按 `modality_type` 选不同 FFN 专家。

论文图 1 的 `MoME`（mixture of modality experts）不要误读成按概率随机选专家的门控 MoE。此实现的分路由输入类型和层号决定：`image` 选 `mlp_imag`，`text` 选 `mlp_text`；图文输入在较低层按文字／图片两段走各自专家，较高层可选 `mlp_vl`。每层自己的 `self.attn` 对这三种调用共用，但第 0 层和第 1 层仍有不同注意力权重。

## 纸上例子：一张图一句话如何走完【必须会】

以默认预训练 `image_size=224`、patch 边长 16、文字长度 `T=40`、Base 隐藏宽度 `D=768` 为例。224÷16=14，所以图片成为 14×14=196 个 patch；加图片 `[CLS]` 得 197 个图像 token。文字最多 40 个 token（含特殊 token 与补齐位置）。若当前进程批量 `B=2`，图像像素为 `[2,3,224,224]`，图片序列 `[2,197,768]`，文字 ID `[2,40]`，文字 embedding `[2,40,768]`。联合序列沿 token 维拼成 `[2,237,768]`；一个拥有 12 个注意力头的层，其每头宽度 $768/12=64$，注意力矩阵 `[2,12,237,237]`。最后一维的 237 代表每个 query 可读的 key 数。

ITC 不拼这两条序列，分别取图像和文字的 CLS，投影并单位化成 `[2,768]`，得到相似度矩阵 `[2,2]`。正确图文按相同下标配对，所以目标索引 `[0,1]`。ITM 则先构造 2 个正例、2 个“错图”例、2 个“错文”例，三组融合 CLS 拼成 `[6,768]`，ITM 分类头输出 `[6,2]`。MLM 对文字的 40 个位置逐个预测 BERT 词表，logits 大约 `[2,40,30522]`；标签为 `-100` 的位置不计损失。

上面的 `B=2` 是帮助看形状的小例子，不代表原论文的实际训练设置。原论文总批次为 1024；代码还可以由多 GPU 汇总更大的负例集合。

对应 [pdf2zh 中文论文](中文论文.pdf)与[论文逐节说明](论文逐节说明.md)、[多路 Transformer](vlmo/modules/multiway_transformer.py)、[VLMo 主模块](vlmo/modules/vlmo_module.py)、[损失目标](vlmo/modules/objectives.py)。这里讲本地源码的核心调用链；模型还有 checkpoint 转换、位置偏置插值、完整检索评估等工程支线，第一次可沿函数名以后再读。

## 0. 先用一层的结构理解 MoME

MoME = **Mixture of Modality Experts**，模态专家混合。每层先用一套共享自注意力让 token 交换信息，随后按输入模态选择不同前馈网络 FFN。`image` 用图像 FFN，`text` 用文字 FFN，`vl`（vision-language，图文）可以用图文 FFN；若当前层未创建图文 FFN，则把混合序列中的文字和图像段拆开，各走对应专家。

这不是随机挑一个专家的门控 MoE。此源码中的选择主要由明确的 `modality_type` 字符串和层配置决定。`self.attn` 在同一 Block 内被图像、文字、图文路径共用；`self.mlp_text`、`self.mlp_imag`、可选 `self.mlp_vl` 是参数不同的网络。

下文 `B` 批量数、`N` token 总数、`T` 固定文字长度、`P` 图像 token 数、`D` 特征宽度、`H` 注意力头数、`d=D/H` 每头宽度。

## 1. 导入与库函数地图

| 名字 | 来源、命名含义 | 常用调用在本源码的作用 |
|---|---|---|
| `torch` | PyTorch 张量库 | `torch.cat` 拼 token；`torch.linspace` 建逐层递增概率；`torch.ones` 建 mask |
| `torch.nn as nn` | neural network 可训练层 | `nn.Linear`、`nn.LayerNorm`、`nn.ModuleList`、`nn.Parameter` |
| `torch.nn.functional as F` | functional 无状态函数 | `F.linear` 一次算 Q/K/V；`F.cross_entropy` 算分类损失 |
| `functools.partial` | 标准库预填参数 | `partial(nn.LayerNorm,eps=1e-6)` 给 LayerNorm 设置默认 eps |
| `DropPath`（timm） | stochastic depth 随机深度 | 训练时按概率跳过一个残差分支；与逐元素 `Dropout` 不同 |
| `to_2tuple`（timm） | 尺寸参数规范化 | 使 `224` 变 `(224,224)`，便于处理高与宽 |
| `trunc_normal_`（timm） | 截断正态初始化 | 原地初始化 CLS、位置向量和层权重 |
| `register_model`（timm） | 模型注册装饰器 | 令 `timm.create_model` 可按名字创建 `vlmo_base_patch16` |
| `rank_zero_info`（Lightning） | 只在主进程打印日志 | 避免多 GPU 重复输出 |
| `pytorch_lightning as pl` | 训练框架 | `LightningModule` 的 `training_step` 等回调 |
| `torch.distributed as dist` | 多进程通信 | `get_world_size`、`all_gather` 扩大对比学习负例池 |

`nn.ModuleList([...])` 与普通 Python 列表的区别：它把每个 Block 正式登记为模型子模块，这样优化器、`.to(device)`、`state_dict()` 才会处理其中参数。`nn.Parameter` 把一个张量登记为可训练参数；`register_buffer` 则登记需保存/迁移但不训练的张量。末尾 `_` 的函数一般原地修改，例如 `masked_fill_`。

## 2. `Mlp`：最简单的专家

位置：[multiway_transformer.py 的 `Mlp`](vlmo/modules/multiway_transformer.py)。`MLP` 是 multilayer perceptron，多层感知机；这里实质是两层线性层和一次 GELU 激活。`in_features=D` 是输入宽度；`hidden_features` 是中间宽度，通常 `int(D*mlp_ratio)`；`out_features` 默认回到 D，才能与原输入做残差相加。

```text
x [B,N,D] → fc1 [B,N,hidden] → GELU → Dropout
          → fc2 [B,N,D]      → Dropout → 返回
```

`nn.Linear` 会把所有前导维保持不变，只变最后一维，所以不必写循环逐个 token 处理。`GELU` 给网络非线性；没有它，两层线性层可以合并成一层线性变换。`Dropout` 仅在训练模式随机置零部分激活，评估模式不随机丢弃。`x` 是各行不断更新的当前特征，切勿认为始终是入口值。

## 3. `Attention.forward`：逐行拆 Q、K、V

位置：[multiway_transformer.py 的 `Attention.forward`](vlmo/modules/multiway_transformer.py)。`B,N,C=x.shape` 是 Python 解包，`C` 指本层 feature channels，等于前述 D。字母 Q/K/V 分别是 query（我想找什么）、key（我能提供什么）、value（实际取出的内容）。

1. `qkv_bias=None`：默认不用偏置。如果有 `self.q_bias`，`torch.cat((q_bias, zeros_like(v_bias), v_bias))` 合出长度 `3D` 的偏置；中间的 K 偏置固定为零。`zeros_like` 复制形状和设备，不复制数值。
2. `F.linear(input=x,weight=self.qkv.weight,bias=qkv_bias)` 一次把 D 映射到 3D，结果 `[B,N,3D]`。与建立三次 `nn.Linear` 的功能相似，但共享一次大矩阵乘。
3. `.reshape(B,N,3,self.num_heads,-1)` 划分为 Q/K/V、H 个头、每头 d；`-1` 让 PyTorch 算 d。`.permute(2,0,3,1,4)` 调整为 `[3,B,H,N,d]`，便于 `qkv[0]`、`[1]`、`[2]` 分别取 Q/K/V。
4. `q=q*self.scale`，其中常见 `scale=d**-0.5`，避免点积数值随维度变大。`q.float() @ k.float().transpose(-2,-1)` 产生 `[B,H,N,N]` 的每对 token 分数；`.float()` 临时提升到 float32 以增加计算稳定性。
5. 若有 `relative_position_bias`，`.unsqueeze(0)` 增一个 batch 轴，再广播加到每头分数上。它表达两个 token 相对位置，不等于输入 token 自身的绝对位置 embedding。
6. `mask.bool()` 将有效位转布尔。`~mask[:,None,None,:]` 的形状为 `[B,1,1,N]`：`None` 在索引里插入长度为 1 的轴。`masked_fill(...,-inf)` 把无效 key 的分数设为负无穷，softmax 后其概率为零。
7. `attn.softmax(dim=-1)` 在“被关注的 N 个 key”方向归一化。`.type_as(x)` 把输出转回入口精度。`attn @ v` 做加权求和，接着 `.transpose(1,2).reshape(B,N,C)` 把 H 个头拼回 D。最后 `self.proj` 做线性投影，`self.proj_drop` 做 dropout。

注意 `mask` 阻止其他位置**读取无效 key**；代码没有在这里把无效 query 行直接删除。`attn` 变量先表示未归一化分数，后又被赋值为概率，最后返回的却是输出 `x`，不返回注意力矩阵。读代码时看每次赋值之后的新含义。

## 4. `Block.forward`：共享与专家到底在哪行

```python
x = x + self.drop_path(self.gamma_1 * self.attn(self.norm1(x), mask=mask,
                                                relative_position_bias=relative_position_bias))
```

最里面 `norm1(x)` 做 LayerNorm；`attn(...)` 是**同一个**共享注意力对象；`gamma_1` 是 LayerScale，可训练的逐特征缩放；`drop_path` 在训练时可能跳过整条残差分支；最后与原 `x` 相加保留信息。此行执行完，`x` 已是结合新注意力结果的张量。`gamma_2` 对后面的 FFN 分支做类似缩放。

```python
if modality_type == 'image':
    x = x + drop_path(gamma_2 * mlp_imag(norm2_imag(x)))
elif modality_type == 'text':
    x = x + drop_path(gamma_2 * mlp_text(norm2_text(x)))
else:
    # 图文混合：有 mlp_vl 时整条序列走它；没有则按固定文字长度切开
```

以上是简写帮助阅读，完整精确语句在源码。`norm2_imag`、`norm2_text`、`norm2_vl` 也各有独立参数；“专家”不仅是 MLP 权重不同。没有 `mlp_vl` 时，`x_text=x[:,:self.max_text_len]`、`x_imag=x[:,self.max_text_len:]`；分别经两个 FFN，`torch.cat([x_text,x_imag],dim=1)` 按原顺序接回。这里**要求输入混合序列前段的文字 token 数与 `max_text_len` 的布局约定一致**。图文 token 在共享注意力阶段已交互，拆开走 FFN 并不抹掉已有的信息。

`with_vlffn` 由 `i >= vlffn_start_layer_index` 决定，所以靠后层可有专用图文 FFN；在 `textmlm` 纯文字阶段，代码把起始层设为 `depth`，相当于该阶段不创建图文 FFN。`modality_type='vl'` 不是一种张量类型，只是 Python 字符串，供 `if/elif/else` 选路径。

## 5. 图片变 token 与 `MultiWayTransformer`

`PatchEmbed` 用核大小与步长等于 patch 大小的卷积，把 `[B,3,H,W]` 变 `[B,D,H/p,W/p]`。`visual_embed(_x)` 随后 `flatten(2)` 把二维网格展平，`transpose(1,2)` 成 `[B,P,D]`；`self.cls_token.expand(B,-1,-1)` 把同一个可训练 CLS 参数显示为 B 行，`-1` 意味该维不变。`torch.cat((cls_tokens,x),dim=1)` 把 CLS 放最前。可选的 `pos_embed` 是绝对位置向量；`relative_position_bias` 则在每层注意力分数里使用。`x_mask=torch.ones(B,P+1)` 因没有图像 padding，所有位置有效。

构造器里 `num_patches=self.patch_embed.num_patches` 由图像尺寸和 patch 大小计算。`dpr=[x.item() for x in torch.linspace(0,drop_path_rate,depth)]` 给每层逐渐增大的 DropPath 概率；`.item()` 从零维张量取 Python 数字。`nn.ModuleList([Block(...) for i in range(depth)])` 建 depth 层，每层参数独立。`self.norm` 在所有层后做末归一化。`no_weight_decay()` 返回不需权重衰减的参数名字集合，供优化器构建逻辑查询。

## 6. 从 batch 到三种推理函数

在 [VLMo.infer](vlmo/modules/vlmo_module.py)：`batch` 是数据整理后的字典，`text_ids` 是 `[B,T]` 整数，`text_masks` 表示有效字词；`img=batch[imgkey][0]` 从图片视图列表取张量。`text_embeddings(text_ids)` 得 `[B,T,D]`，`visual_embed(img)` 得 `[B,P,D]`；分别加类型 embedding，再 `torch.cat(...,dim=1)` 得图文联合序列 `co_embeds [B,T+P,D]`。`co_masks` 也按同序拼。每层 `blk(x,mask=co_masks,modality_type='vl',relative_position_bias=...)` 执行共享注意力与对应专家。最终从 `x` 前 T 位置取 `text_feats`、后 P 位置取 `image_feats`，`self.pooler(x)` 给整对图文 `cls_feats`。

`infer_text` 只编码文字并走 `modality_type='text'` 路线；`infer_image` 只编码图片并走 `modality_type='image'` 路线。它们输出的 `cls_feats` 可做 CLIP 风格的 ITC。`infer` 的融合 `cls_feats` 则适合 ITM/VQA 等需要细粒度交互的任务。`infer_text_mlm` 是纯文字遮词阶段路径；不要把“同名 `infer`”理解为只能在推理时使用，这些函数训练时一样会调用。

## 7. ITC、ITM、MLM：为什么顺序重要

在 [VLMo.forward](vlmo/modules/vlmo_module.py)，`self.current_tasks` 是本轮要做的任务名列表；`ret.update(objectives.compute_itc(...))` 把返回字典并入 `ret`。当同时启用 ITC 与 ITM，先算 ITC：因为 `compute_itm_hardneg` 需要 `ret['itc_i2t_logits']` 与 `ret['itc_t2i_logits']` 用作难负例采样概率。如果只配置 `itm` 而未产生这些键，原实现会 `KeyError`。

`compute_itc` 先调用 `infer_image` 和 `infer_text` 各自编码，取单位向量 `image_features/text_features [B,D]`，`logit_scale.exp().mean()` 将对数尺度变正。多卡时 `dist.all_gather` 收集其他卡向量以增加负例。矩阵 `logits_per_image=scale*all_image_features@all_text_features.t()`，其对角线是正确配对；`ground_truth=torch.arange(总样本数)` 给每行的正确列。图找文和文找图各用 `F.cross_entropy` 算一次，再平均。源码还针对 `cls_vlffn_feats` 计算第二套对比损失，最后两套再平均。这是读 VLMO 与简单 CLIP 实现时的重要区别。

`compute_itm_hardneg` 根据上述相似度选错图/错文，调用融合 `infer` 对真图文与两类错配分别编码，得到三组 CLS；`itm_score` 输出真假分数，用交叉熵训练。`compute_mlm` 用遮词版 `text_ids_mlm` 与图片共同编码，再由 `mlm_score` 对每个文字位置预测词表，`ignore_index=-100` 跳过无须预测的位置。训练钩子 `training_step` 以 `vlmo_utils.set_task(self)` 设任务，调用 `self(batch)`，然后把返回字典中键名含 `loss` 的值加总交给 Lightning 反传。

### 小型复现的真实边界

`compute_itc(...,aggregate=True)` 默认会调用 `dist.get_world_size()`，依赖初始化的分布式进程组。原文件中 `aggregate=False` 分支没有创建后续还要读取的 `logits_per_vlffn_image`，直接改成 False 并不是完整的单卡解决方案。学习时可先追模型前向与形状；要跑单卡小实验，需要对这一分支作明确补全或按项目训练入口初始化分布式环境。

## 8. 隔很远再次出现的名字

| 名字 | 初始来源 | 后面读到时应回想 |
|---|---|---|
| `self.blocks` | `MultiWayTransformer.__init__` 创建的 `ModuleList` | 每个元素是一层共享注意力＋多路 FFN |
| `blk` | `for i,blk in enumerate(self.transformer.blocks)` | 当前第 i 个 Block；不是整个 Transformer |
| `x` | 当前函数入口或 `co_embeds` | 每层都会重新赋值；只能根据当前位置确定是否已融合 |
| `text_embeds` | `self.text_embeddings(text_ids)` | 尚未进共享注意力的文字向量 |
| `text_feats` | 联合 `x` 的前 T 个位置 | 已融合图像信息，可给 MLM |
| `image_features` | `infer_image()['cls_feats']` | 全局图像单位向量，给 ITC |
| `cls_vlffn_feats` | 单模态路径再走后段图文 FFN 得到 | 第二套 ITC 对比向量，不等于首套 `cls_feats` |
| `ret` | `forward` 开头的空字典 | 各目标函数用 `update` 逐渐加入损失、logits、标签 |

自检：如果 `B=2,T=40,P=197,D=768`，联合序列为 `[2,237,768]`；共享注意力的分数矩阵对每个头是 `[2,237,237]`；后面没有专用图文 FFN 的层会按前 40 个文字位置与后 197 个图像位置拆开。

## 9. 论文式（1）（2）与源码逐项对应【必须会】

论文式（1）为 $H'_l=\operatorname{MSA}(\operatorname{LN}(H_{l-1}))+H_{l-1}$。`H` 是一层所有 token 的隐藏向量矩阵；下标 $l-1$ 表示进入第 $l$ 层前，撇号 $H'_l$ 表示**本层注意力结束但 FFN 尚未结束**。对批量代码而言可写为 `[B,N,D]`，其中 `N` 随输入变成纯图像的 197、纯文字的 40 或联合的 237。`LN` 逐 token 按特征维归一化，`MSA` 用同一层的多头自注意力让各 token 读取其他 token；末尾相加是残差连接，保证旧信息有直接通道。

在 [Block.forward](vlmo/modules/multiway_transformer.py) 中，对应语句是：

```python
x = x + self.drop_path(self.gamma_1 * self.attn(
    self.norm1(x), mask=mask, relative_position_bias=relative_position_bias))
```

从内向外读：`self.norm1(x)` 相当于 `LN`；`self.attn(...)` 相当于 `MSA`；`gamma_1` 是每个特征维的可训练缩放，`drop_path` 是训练时可能跳过整条残差分支；外层原 `x + ...` 是论文中的 $+H_{l-1}$。论文把实现中的 LayerScale、DropPath 和相对位置偏置省略在概括公式里，不能据此说实现与公式矛盾。`self.attn` 的 `mask` 使 PAD 位置不能被当作 key 读取；`relative_position_bias` 给注意力分数额外添加位置相关项。

论文式（2）为 $H_l=\operatorname{MoME\!\mbox{-}\!FFN}(\operatorname{LN}(H'_l))+H'_l$。`Block.forward` 中的 `modality_type` 控制专家选择。`'image'` 经过 `norm2_imag` 与 `mlp_imag`，`'text'` 经过 `norm2_text` 与 `mlp_text`。`'vl'` 且该层有 `mlp_vl` 时，整条联合序列经过 `norm2_vl` 与 `mlp_vl`；该层没有 `mlp_vl` 时，先按固定 `max_text_len` 切成文字段 `x_text` 与图像段 `x_imag`，各自经过其专家，再 `torch.cat(...,dim=1)` 拼回。这里 `self.max_text_len` 是切分位置，而非本句真实非 PAD 词数；batch 必须遵守文字统一填充到这个长度的布局。

**两行原理连起来：** 注意力决定“一个 token 能从哪些 token 汇集信息”，专家 FFN 决定“汇集后如何对每个 token 的特征做非线性加工”。FFN 的 `nn.Linear` 只变最后一维，不会自己把第 1 个词与第 5 个 patch 混合；真正的跨 token 交互发生在注意力。下层图文虽然走不同 FFN，但它们在此前共享注意力里已经交流。

## 10. 论文式（3）（4）与 ITC 实现【必须会】

论文对第 $i$ 张图和第 $j$ 句话定义 $s^{i2t}_{i,j}=(\hat h_i^v)^\top\hat h_j^w$；上标 `i2t` 是 image to text，即“给图找文”，`t2i` 是反方向。帽子 $\hat h$ 指单位长度向量。代码在 [VLMo.infer_image](vlmo/modules/vlmo_module.py) 与 [VLMo.infer_text](vlmo/modules/vlmo_module.py) 先取得 CLS 的隐藏向量，经 `itc_image_proj`／`itc_text_proj` 线性投影，再除以自己的 `norm`。`norm(dim=-1,keepdim=True)` 在最后的特征维求长度，并保留长度为 1 的轴，方便广播相除。归一化后的向量 `cls_feats` 已经不是整条 token 序列。

[compute_itc](vlmo/modules/objectives.py) 中的相似度语句是：

```python
logits_per_image = logit_scale * all_image_features @ all_text_features.t()
logits_per_text = logits_per_image.t()
ground_truth = torch.arange(len(logits_per_image)).long().to(device=logits_per_image.get_device())
```

`all_image_features [G,D]` 与转置后的 `all_text_features.t() [D,G]` 做矩阵乘，输出 `[G,G]`；`G` 是汇总各进程之后的图文对数。第 `(i,j)` 个元素对应第 `i` 张图和第 `j` 句话。`.t()` 只转置二维矩阵，`logits_per_text` 是文找图方向。`torch.arange(G)` 产生 `0,1,...,G-1`，用作每一行正确配对的列号。`.long()` 使索引为整数类型；`.to(device=...)` 把标签放到与分数矩阵同一设备上。`F.cross_entropy` 在内部处理 softmax 与负对数似然，故外面**不必先手动 softmax**。`logit_scale` 在模型中存为可训练的对数尺度，`.exp()` 后为正，扮演论文 $1/\sigma$ 的作用。

举个两对图文的数值例子。若点积矩阵为 $\begin{bmatrix}2&0\\1&3\end{bmatrix}$，温度取 1，第 0 张图找到正确句子的概率是 $e^2/(e^2+e^0)\approx0.881$，第 1 张图是 $e^3/(e^1+e^3)\approx0.881$；错误配对分数升高会降低正确概率，交叉熵便会增大。反方向需对矩阵转置后重新逐行计算，不能只把前两个概率复制过去。

**论文简式与当前代码的差别：** 实现另从倒数若干层分叉，以 `VL-FFN` 路径分别处理纯图／纯文向量，得到 `cls_vlffn_feats`，再算第二套双向交叉熵。`itc_total_loss=(itc_loss+itc_vlffn_loss)*0.5`。论文式（3）（4）概括主要对比目标，没有在公式中展开这套双分支实现。`aggregate=True` 的分布式汇总用于扩大负例池；若无已初始化的进程组，直接独立调用 `compute_itc` 会失败。原始 `aggregate=False` 分支没有计算第二套 `logits_per_vlffn_image`，而后文仍要用它；小实验不能只把这个参数改为 False 就认为解决。

## 11. ITM、MLM 与总损失【必须会】

ITM 是 **image-text matching**：一组图文是否真的匹配。代码中的 `compute_itm_hardneg(pl_module,batch,sim_i2t,sim_t2i)` 有四个输入：`pl_module` 是 VLMo 模型对象；`batch` 是带图像、文字 ID、mask 的字典；后两个 `[G,G]` 分数来自前面 ITC。它先调用 `pl_module.infer(batch)` 融合当前批次的正确图文，再用 `dist.all_gather` 从所有进程收集供采样的**文字 ID、文字 mask 和图片张量**。`F.softmax` 把相似度变成抽样权重，`fill_diagonal_(0)` 禁止把正确配对当负例；`torch.multinomial` 按权重抽错图和错文。分数很高的错误候选更有机会被抽到，称“难负例”。最后 `torch.stack` 把抽到的单个张量组成批次；`torch.cat` 将正例、错图例、错文例沿 batch 轴接起来。`itm_score` 输出 `[3B,2]` 的两类 logits，用 `F.cross_entropy` 对二分类标签计算损失。带下划线的 `fill_diagonal_` 会原地修改张量，而 `torch.cat` 返回新张量。

MLM 是 **masked language modeling**，训练模型补出隐藏的文字 token。图文版 `compute_mlm` 在 `infer(...,mask_text=True)` 里拿到被遮词版 ID，融合图片与文字，`mlm_score` 把 `[B,T,D]` 映射到 `[B,T,V]`，其中 `V=30522` 是当前 BERT 词表大小。`mlm_logits.view(-1,V)` 把 batch 和位置合成一维 `[B×T,V]`；标签也展平成 `[B×T]`。`ignore_index=-100` 让非目标位置不参与平均损失。源代码中图文 MLM 损失另乘 `0.25`，而纯文字阶段 `compute_textonly_mlm` 不乘；这个系数是实现中的目标权重，不是“遮盖 25% 的词”。遮盖概率由配置 `mlm_prob=0.15` 控制。

`VLMo.forward` 先计算 MLM、再 ITC、再 ITM（启用时）；ITM 用 ITC 返回的相似度，所以 `loss_names` 不能只开 ITM 而关 ITC。`training_step` 从 `forward` 返回字典中找键名含 `loss` 的值求和，Lightning 接管反向传播和优化器步骤。读这段时留意：`ret` 是反复 `update` 的结果字典，`itc_loss`、`mlm_loss`、`itm_loss` 是不同标量，`logits` 和 `labels` 则主要供采样与指标统计，不是自动加进总损失的对象。

## 12. 从入口命令到数据字典【建议会】

官方 [README](README.md) 的第三阶段命令形式是：

```bash
python run.py with data_root=<ARROW_ROOT> num_gpus=<NUM_GPUS> num_nodes=<NUM_NODES> task_mlm_itm_itc_base whole_word_masking=True step200k per_gpu_batchsize=<BS_FITS_YOUR_GPU> load_path=<LAST_STAGE_CKPT> log_dir=<OUTPUT>
```

`python` 运行入口，`run.py` 是训练程序，`with` 是 Sacred 配置语法，`task_mlm_itm_itc_base` 选择具名配置，`step200k` 选择 20 万步设定；后面 `key=value` 覆盖配置。`data_root` 指转换后的 Arrow 数据根目录，不是仓库源码目录；`load_path` 指上一阶段 checkpoint；`num_gpus` 和 `num_nodes` 控制并行进程；`per_gpu_batchsize` 是单卡每次处理的样本数。`run.py` 以 `batch_size // (per_gpu_batchsize*num_gpus*num_nodes)` 计算梯度累积次数；例如目标批次 1024、每卡 4、共 8 卡，累积次数是 32。较大的总批次因此不等于一次性在某一张卡中塞入 1024 张图片。

`@ex.automain` 是 Sacred 装饰器，运行脚本时自动把合并后的 `_config` 交给 `main`。`MTDataModule` 是 Lightning 的数据组织对象；原图文文件需按 [DATA.md](DATA.md) 预处理成 Arrow，随后 `BaseDataset` 用 PIL 从字节解码图片，经变换得到 `[3,H,W]`。数据集的一条样本是字典，`collate` 将一组样本整理为张量批次。`batch['image']` 在此项目是图片视图列表，通常第 0 个元素为 `[B,3,H,W]`；`batch['text_ids']` 是整数 `[B,T]`；`batch['text_masks']` 在真实 token 处为 1、补齐处为 0；`batch['text_ids_mlm']` 是遮词版。模型 `infer` 取 `batch['image'][0]` 的两个索引含义分别是字典键与列表中第 0 个增强视图，不是“取第 0 张图片”。

`config.py` 中 `_loss_names` 把所有任务名的默认权重设为 0，再覆盖需要启用的任务；`task_mlm_itm_itc_base` 把三个图文损失设为 1。`__init__` 是类对象构造时调用的初始化方法；`super().__init__()` 先让父类 `LightningModule` 正常登记模型状态；`self.xxx` 是这个模型对象后续函数都能读取的属性。`self.save_hyperparameters()` 使配置进入 `self.hparams`。`create_model` 从 timm 注册表通过字符串模型名建立 `MultiWayTransformer`；这里实际注册函数在导入 `multiway_transformer.py` 时执行。`nn.ModuleList` 而非普通列表存放各层 Block，是为了让 `.parameters()`、`.to(device)`、checkpoint 看见每层可训练参数。

## 13. 输入张量与变量名追踪【必须会】

| 变量或字段 | 名字为什么这样写、从哪来 | 当前类型／形状 | 下一步去向 |
| --- | --- | --- | --- |
| `image_size` | 预处理后正方形图像边长，配置为 224 | Python 整数 | 决定变换尺寸和 patch 数 |
| `img` | `batch[imgkey][0]` 得到的 image 张量 | float `[B,3,224,224]` | `visual_embed` |
| `image_embeds` | image embeddings，每个图像 patch＋CLS 的表示 | float `[B,197,D]` | 联合编码或纯图编码 |
| `image_masks` | 每个图像 token 是否有效 | 整数 `[B,197]` | 注意力 `mask` |
| `text_ids` | tokenizer 赋给每个词／子词的词表编号 | long `[B,T]` | `BertEmbeddings` |
| `text_masks` | 文字 token 有效位置，区别于遮词操作 | 整数 `[B,T]` | 联合注意力 `mask` |
| `text_embeds` | 词 ID 经 BERT embedding 加位置等所得向量 | float `[B,T,D]` | `co_embeds` |
| `co_embeds` | `co` 是 combined，文字＋图像的联合序列 | float `[B,T+197,D]` | 各层 `Block` |
| `blk` | 当前循环中的一个 Transformer block | `Block` 对象 | 调用 `blk(x,...)` |
| `x` | 本层正在更新的序列；每次赋值含义随位置变 | float `[B,N,D]` | 下一层或输出 |
| `cls_feats` | `[CLS]` 的全局特征，可能已通过投影／池化 | float `[B,D]` | ITC、ITM、VQA 等 |
| `cls_vlffn_feats` | 经过 VL-FFN 后段分支的第二套 CLS 向量 | float `[B,D]` | 第二套预训练 ITC |
| `sim_i2t` | image-to-text 图找文的候选得分 | float `[G,G]` | ITM 难负例抽样 |
| `ground_truth` | 第 i 行正确候选为第 i 列的整数目标 | long `[G]` | ITC 交叉熵 |
| `itm_labels` | 正例 1、负例 0 | long `[3B]` | ITM 交叉熵 |

同一个 `cls_feats` 键在不同 `infer_*` 函数里指不同路径的最终全局向量，不能脱离调用函数解释。隔很久再次见 `x` 时应回查最近的赋值；`text_masks` 是 PAD 有效位，`mask_text=True` 则是**启用遮词输入**的布尔开关，两者不是一回事。`_ft` 后缀是 fine-tuning（微调），如 `infer_image_ft`；`vlffn` 是 vision-language feed-forward network（视觉语言前馈专家）。

## 14. 高频 Python／PyTorch／训练库函数解释【建议会】

| 写法 | 归属、参数和返回值 | 这里为什么用 |
| --- | --- | --- |
| `from functools import partial` | Python 标准库；固定函数的一部分参数，返回可调用对象 | `partial(nn.LayerNorm,eps=1e-6)` 统一构造归一化层 |
| `nn.Linear(a,b)` | PyTorch 模块；保持前导维，只把最后一维 `a→b` | FFN、QKV、分类头都需改变特征宽度 |
| `nn.Conv2d(3,D,kernel_size=16,stride=16)` | 二维卷积层；核与步长相同，产生不重叠 patch 网格 | 图片像素→patch embedding |
| `F.linear(x,weight,bias)` | `torch.nn.functional` 的函数式线性变换；直接用给定权重 | `Attention` 一次算 Q、K、V，不另建三个层 |
| `reshape`／`permute` | 改形状／重排轴；`permute` 要列出全部维度顺序 | 把 `[B,N,3D]` 变为 Q/K/V 各 `[B,H,N,d]` |
| `torch.cat(items,dim)` | 沿既有轴拼接，其他轴须一致 | 文字图像 token、三组 ITM 样本拼接 |
| `torch.stack(items,dim)` | 新建一个轴，输入张量形状须一致 | 抽到的 B 个负图重新组成 `[B,3,H,W]` |
| `torch.no_grad()` | 上下文管理器，块内不记录梯度 | 抽难负例的索引和候选汇总不需反传 |
| `F.softmax(x,dim=-1)` | 沿指定轴转成总和为 1 的概率 | 注意力与负例抽样概率 |
| `F.cross_entropy(logits,target)` | 分类交叉熵，输入原始 logits、整数目标 | ITC、ITM、MLM；内部完成 softmax |
| `nn.Parameter(t)` | 把张量登记为可学习参数 | CLS、温度尺度、LayerScale |
| `register_buffer(name,t)` | 登记需随模型搬设备和保存、但不训练的张量 | 位置索引等非参数状态 |
| `dist.all_gather(dst,src)` | PyTorch 分布式；所有进程互换同形状张量 | ITC 扩大负例池、ITM 全局候选 |
| `pl.Trainer.fit(model,datamodule=dm)` | Lightning 接管训练循环 | 自动调用 `training_step` 等钩子 |
| `@ex.named_config` | Sacred 的具名配置装饰器 | 命令中选定 VLMo 某任务设置 |
| `getattr(obj,name)` | Python 内置；由字符串动态取属性 | `train_mlm_loss`／`val_mlm_loss` 复用统计逻辑 |

`with torch.no_grad():` 的 `with` 管理块的运行上下文；退出缩进块时恢复原来的梯度模式。`@register_model`、`@ex.named_config` 前面的 `@` 是装饰器，函数定义时先登记到框架，以后才能按名字查到。`**kwargs` 是收集额外关键字参数的字典，`*args` 是额外位置参数；这里只要能读懂构造函数把配置转交下去即可。`self` 不是特殊关键字，而是 Python 约定的当前对象名字；调用 `model.forward(batch)` 时 Python 会自动把 `model` 绑定为 `self`。

## 15. 论文图表怎样读【建议会】

论文图 1 的三条路径并不表示要建立三个互不相关的主干模型。图 2 的第一阶段 BEiT、第二阶段纯文字、第三阶段图文对应 [README](README.md) 三步说明；[run.py](run.py) 的纯文字冻结规则把非文字参数 `requires_grad=False`，再放开文字 embedding、文字专家与 MLM 头等。图 3 的检索双编码器对应 `infer_image_ft`、`infer_text_ft` 和 `compute_irtr`；分类融合编码器对应 `infer`、`compute_vqa`、`compute_nlvr2`。VQA 的答案分类头和 NLVR2 的双图特征拼接在各自损失函数中实现，不能用检索的点积公式代替它们。

论文表 1 中，相同约 4M 预训练图片组的 VQA test-dev：ALBEF-Base 74.54、VLMo-Base 76.64，相差 2.10 个百分点；NLVR2 test-P：80.50 对 83.34，相差 2.84 点。指标越高越好，但不同论文的预训练细节、初始化、微调设置不完全相同，不能单凭差值断言只有 MoME 造成提升。表 2 的 COCO 5K 检索，VLMo-Base 的 TR R@1 为 74.8、IR R@1 为 57.2；ALBEF-Base 为 73.1、56.8。Flickr30K 1K 测试集上，ALBEF-Base 的 TR R@1 为 94.3，VLMo-Base 为 92.3，所以不能概括成“VLMo 所有检索指标都更高”。它的双编码器不需要为每个候选都运行融合网络，是推理效率优势的主要机制；论文没有在表 2 给出统一硬件下的毫秒级延迟对照。

表 4 比较分阶段初始化：额外的纯文字阶段把 NLVR2 dev 从 80.33 提高到 82.09（+1.76 点），Flickr IR 的三项 Recall 平均从 87.69 到 88.52（+0.83 点）。表 5 的完整 MoME＋三损失设置 [6] 在 NLVR2 dev 80.13、Flickr IR 平均 87.25；只开 ITC 的 [1] 是 58.51、84.24。表 6 在 32 张 V100、单卡 32 个样本的特定设定下，全局难负例把 NLVR2 dev 从 77.70 提到 79.54（+1.84 点）。这些是论文报告值，**不是本机运行结果**；表 5 不同训练目标行同时改变了学习信号，结果支持组合有效，但不保证任意模型或数据集上同样变化。
