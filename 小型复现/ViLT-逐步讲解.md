# ViLT 小型复现：从零读代码

先运行：

```powershell
py -3.13 小型复现/vilt_tiny.py --steps 120
```

读代码的顺序是 [data.py](data.py) → [vilt_tiny.py](vilt_tiny.py)。源码每一条关键语句旁都有中文注释；这里把各语句的**原因和张量形状**串起来。

## 1. 什么是一个样本？

一张图片是一个数字数组 `[3,16,16]`。第一维有红、绿、蓝三层；某个像素的红色值为 1，意味着那个位置很红。文字不会直接作为汉字进模型，而是变成四个整数。例如“红色 方形”会变成 `[CLS, RED, SQUARE, SEP]` 对应的 `[1,3,5,2]`。

`data.py` 中的 `make_pairs()` 一次生成 8 对样本。前四对是正确配对，标签为 1；后四对保留原图、换成错误文字，标签为 0。所以 `images` 是 `[8,3,16,16]`，`texts` 是 `[8,4]`，`labels` 是 `[8]`。

## 2. `__init__()` 创建了什么？

- `nn.Conv2d(3,32,kernel_size=4,stride=4)`：同时负责**切图**和**把每块映射到 32 维**。16×16 的图分成 4×4 网格，共 16 块。
- `nn.Embedding(7,32)`：一个有 7 行、每行 32 个数的可训练表。`RED=3` 就取第 3 行。这一步把离散整数变成可计算的词向量。
- `nn.Parameter(...)`：声明“这个张量也要由优化器更新”。CLS 和位置向量都属于这种参数。
- `nn.TransformerEncoderLayer(...)`：共享的自注意力层。图片块可以关注词，词也可以关注图片块。
- `nn.Linear(32,2)`：输出两个数，分别是不匹配与匹配的分数。

## 3. `forward()` 一行行走

| 语句 | 形状变化 | 含义 |
|---|---|---|
| `self.patch_embed(images)` | `[B,3,16,16] → [B,32,4,4]` | 提取图片小块 |
| `.flatten(2).transpose(1,2)` | `[B,32,4,4] → [B,16,32]` | 把空间网格改成 token 序列 |
| `self.word_embed(texts)` | `[B,4] → [B,4,32]` | 把词编号变成词向量 |
| `self.cls_token.expand(...)` | `[1,1,32] → [B,1,32]` | 每对图文前放一个汇总向量 |
| `torch.cat(...,dim=1)` | `1+4+16 → [B,21,32]` | **把图文放进同一个序列** |
| `self.encoder(tokens)` | `[B,21,32] → [B,21,32]` | 让所有 token 通过注意力交换信息 |
| `mixed[:,0]` | `[B,21,32] → [B,32]` | 取融合后的 CLS |
| `self.classifier(...)` | `[B,32] → [B,2]` | 产生分类分数 |

其中 `B` 是批量大小，本项目训练时为 8。`transpose(1,2)` 并没有改动数据语义，而是调换两个轴；Transformer 要求特征维 `32` 放最后。`dim=1` 选的是序列轴，因此 `torch.cat` 会加长序列，不会增加批量大小。

## 4. 为什么损失可以让模型学习？

`F.cross_entropy(logits, labels)` 读取模型给出的 `[8,2]` 分数和 8 个正确标签。预测错时，损失较大；预测对且有把握时，损失较小。`loss.backward()` 计算每个参数如何影响损失，`optimizer.step()` 让参数沿着减小损失的方向更新。

训练输出中的“本批准确率”只是这 8 对小样本的结果。程序每步重新生成带随机噪声的图片，最后也生成新的一批做检查。四类图文过于简单，因此 100% 不能理解为模型已经具备真实场景理解能力。

## 5. 和真正 ViLT 的关系

本项目保留了“图片 patch + 文字 token → 同一个 Transformer → 图文匹配头”。原论文的视觉骨干、数据、模型容量和预训练任务更复杂。读完本项目，再去 [原版 ViLT 源码讲解](../项目讲解/02-ViLT.md) 对照 `visual_embed()`、`infer()` 与 `compute_itm()`。
