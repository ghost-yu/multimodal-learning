# ALBEF 小型复现：从零读代码

先运行：

```powershell
py -3.13 小型复现/albef_tiny.py --steps 250
```

读代码的顺序是 [data.py](data.py) → [albef_tiny.py](albef_tiny.py)。每行较难的代码都已写中文注释，这篇解释为什么要分成**对齐**与**融合**两步。

## 1. 一批数据长什么样？

每一步抽取红方、红圆、蓝方、蓝圆各一张，顺序会打乱。四张图片形状 `[4,3,16,16]`，四句话形状 `[4,4]`。第 `i` 张图和第 `i` 句话是正确配对。因为一批里四个类别都不同，其他三句话就是它的错误候选。

## 2. 为什么需要两个编码器？

`encode_image()` 将图片切成 16 个 patch，并让 patch 之间通过自注意力交流，返回 `[4,16,32]`。`encode_text()` 先把四个词编号转成向量，再做文字自注意力，返回 `[4,4,32]`。这时两边还没有直接交互：图片只看图片，文字只看文字。

这与 ViLT 的早期拼接不同。先分别编码，才能得到“整张图”和“整句话”两组向量，计算它们是否对齐。

## 3. ITC：图文对比学习

`image_tokens.mean(dim=1)` 把 16 个 patch 平均成 `[4,32]` 整图向量。`text_tokens[:,0]` 取 CLS，得到 `[4,32]` 整句向量。两个向量都经 `F.normalize(...,dim=-1)` 缩放为单位长度。

```text
图片向量 [4,32] @ 文字向量转置 [32,4] = 相似度 [4,4]
```

例如矩阵第 2 行第 3 列，就是“第 2 张图与第 3 句话”的相似度。正确匹配在对角线：`(0,0)`、`(1,1)`、`(2,2)`、`(3,3)`。`F.cross_entropy(similarity, target)` 让每张图挑中自己的文字；再对 `similarity.T` 做一次，让每句话挑中自己的图片。二者平均，就是本项目的 ITC 损失。

`temperature` 是温度系数。代码把相似度除以 `0.1`，再交给交叉熵。你可以先把它理解为调节模型对相似度差异的敏感程度。

## 4. ITM：图文匹配

`text_tokens.roll(shifts=1,dims=0)` 沿批量轴移动文字，使原本第 `i` 张图搭配另一类文字，造出四个负例。然后把四个正例和四个负例拼成八对。

`self.cross_attention(text_tokens,image_tokens,image_tokens)` 是关键：第一个参数是 Query，后两个是 Key 和 Value。可以理解为“文字里的每个词向图片的 16 个位置提问，读出与自己相关的图片信息”。输出与原文字特征相加后，取 CLS 交给二分类头。

ITM 输出 `[8,2]`，表示八对图文各自的“不匹配/匹配”分数。前四个标签为 1，后四个为 0。`F.cross_entropy` 训练模型识别它们。

## 5. 两个损失为什么相加？

`total_loss = itc_loss + itm_loss` 让一次 `backward()` 同时更新图像编码器、文字编码器和融合模块。ITC 关注整张图与整句话是否接近；ITM 允许文字 token 直接读取图片 patch，更细致地判断配对。打印结果分别列出 ITC 与 ITM，便于观察是哪一部分尚未学好。

## 6. 这和论文还差什么？

原版 ALBEF 还有动量教师、特征队列和掩码语言建模。本项目刻意只保留能在小数据上清楚运行的两条主路径，因此它是**核心机制的小型复现**。读懂这里后，再去 [原版 ALBEF 源码讲解](../项目讲解/03-ALBEF.md) 看教师、队列和完整预训练目标。
