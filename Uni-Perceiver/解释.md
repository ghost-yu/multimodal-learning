## 2. 它想解决什么问题【必须会】

普通分类网络常用固定类别线性头；检索网络输出图文相似度；文字生成网络输出词表分数。Uni-Perceiver 希望尽可能让这些任务共享模型和预测形式：把输入 x 和候选目标 y 都编码为向量，找出最匹配的候选。

例如图片分类时 x 是图片，候选 y 可以是“猫”“狗”等类别文字；图找文时候选是句子；预测一个词时候选是词表中的词。候选集合不同，但相似度打分的规则相同。

“统一”不表示所有原始数据共用同一个读取函数，也不表示无需区分任务。图片、视频、文字的 tokenizer 不同，注意力可见范围不同，训练样本与标签不同。共享的是主要编码器参数和候选匹配建模。

它也不是任意输出都能直接处理：当前形式依赖可列举或可搜索的候选集合。连续坐标回归、任意动作等不能仅靠改一个 task_name 就宣称实现。

## 4. 仓库地图和阅读顺序【必须会】

`main.py → 配置合并 → trainer → Dataset/组批 → MultiTaskTransformerEncoder._forward → _forward_data → tokenizer → fused_encoder → loss_prepare/predictor → loss → 优化器`。

| 文件/目录 | 名称解释 | 作用 |
|---|---|---|
| main.py | main=程序入口 | 加载命令行/config，组织运行 |
| configs/ | configuration 的缩写 | 模型宽度、层数、任务、数据路径、训练策略 |
| modeling/meta_arch/unified_transformer.py | meta architecture=整体模型装配 | 将嵌入、编码器、预测器、损失接起来 |
| modeling/embedding/token_embed.py | embed=embedding | 文字编号到特征，加入位置/类型信息 |
| modeling/embedding/video_embed.py | video=视频 | 图像/视频 patch 到特征，包含时空位置 |
| modeling/encoder/unified_bert_encoder.py | unified=统一，encoder=编码器 | 共享 Transformer 层及注意力 mask |
| modeling/predictor/embed_cls_predictor.py | cls=classification | 把分类、词预测和检索转为候选分数 |
| losses/cross_entropy.py | cross entropy=交叉熵 | 用正确候选编号监督 logits |
| task_moe/ | mixture of experts=专家混合 | MoE 路由和专家；原版稠密路径不要直接当成 MoE |

`class A(nn.Module)` 是继承：对象可以持有可训练参数与子模块。`self` 是当前实例，`self.foo` 把数据/模块留在对象里。`super().__init__()` 先完成父类初始化，否则模块注册可能出错。

`@REGISTRY.register()` 把类登记到本地工厂；不是开始训练。`@configurable` 让项目把 cfg 配置转换成构造参数。理解这些装配后，再追具体张量计算。

## 5. 式 1：从候选集合选答案【必须会】

\[
\hat y=\arg\max_{y\in\mathcal Y}P(x,y).
\]

x 是当前输入；y 是一个候选；集合 \(\mathcal Y\) 是所有候选；\(\hat y\) 是预测结果。argmax 返回分数最大的候选/下标，不是最大分数本身。

如果候选顺序是 `[猫,狗,车]`，分数是 `[0.7,0.2,0.1]`，最大下标是 0，映射回“猫”。候选顺序与训练标签整数必须一致，不能随意重排候选却保留旧标签。

分类候选可有 C 类，检索候选可以是当前批次或全库，词预测候选有 V 个词。C/V 描述候选数量，D 描述向量宽度，不可混用。

## 6. 式 2：共享编码与相似度【必须会】

\[
P(x,y)\propto\exp\{\cos(f(x),f(y))/\tau\}.
\]

f 是共享参数编码器；输入与候选调用同一套编码权重，不是把原始图片和字符串直接点乘。\(\tau>0\) 是温度；越小，相同相似度差距产生的分数差越大。比例符号表明右侧是未完成归一化的量。

令输入特征 \(G\in\mathbb R^{B\times D}\)，候选特征 \(C\in\mathbb R^{K\times D}\)。B=batch size，K=候选数量，D=hidden dimension。

1. 每行除以 L2 范数得到单位向量，形状不变。
2. 候选转置成 `[D,K]`。
3. `G @ C.t()` 得到 `[B,K]` 的余弦分数。
4. 乘 \(1/\tau\) 得 logits。

代码中的 `cls_name` 已是候选特征 Tensor，不是 Python 类别名字字符串。`q1_hidden_states` 与 `q2_hidden_states` 分别是输入侧和目标侧，也不是注意力内部 Q/K/V。

**命名陷阱：** `_forward` 的 `temperature` 来自 `temperature_task`，后者返回 `exp(logit_scale)`。初始化 `logit_scale=log(1/τ)`，因此这个变量实际是倒数温度。`temperature_dict` 才通过 `1/exp(logit_scale)` 报告真实 τ。

例子：单位输入 `[1,0]`，候选分别 `[1,0]`、`[0,1]`，余弦为 `[1,0]`。τ=0.5 时 logits=`[2,0]`，softmax 第一项约 0.881；τ=1 时约 0.731。温度使分布变尖或变平，不直接增加向量维度。

当 use_norm=False 时，源码改为普通内积打分，不再严格等于式 2 的余弦形式。原始除范数代码没有 eps，零向量可能产生非有限数。固定温度分支显式 `.cuda()`，不能视为开箱即用的纯 CPU 代码。

## 7. 式 3：为什么损失是交叉熵【必须会】

\[
\mathcal L=\sum_{i=1}^{n}\mathbb E_{(x,y)\in(\mathcal X_i,\mathcal Y_i)}
\left[-\log\frac{P(x,y)}{\sum_{z\in\mathcal Y_i}P(x,z)}\right].
\]

n 是任务数；i 是任务编号；期望表示对任务样本平均；y 是正确目标；z 遍历候选。分母把未归一化得分变成候选概率。负对数惩罚模型给正确目标低概率。

前面的 logits `[2,0]`，正确标签=0 时损失约 `-log(0.881)=0.127`；如果正确标签=1，损失约 2.127。模型通过反传调整表示，使正确候选更接近输入。

`nn.CrossEntropyLoss` 接收 logits 和整数目标，内部稳定处理 log-softmax，不需要在 Predictor 先 softmax。`ignore_index=-1` 跳过指定目标，`reduction='mean'` 取平均。源码 criterion 最后还有 `.mean()`：即使设置 reduction='none'，返回仍被平均，不能认为会一路保留逐项损失。

`loss_weight` 是损失系数；它缩放梯度贡献，与 softmax 温度不同。原构造只接受 float 系数，否则置 1.0，因此整数配置值的行为值得核查。

`forward(outputs_dict)` 用 zip 同时遍历 logits、targets、loss_names 列表。zip 只到最短列表，三者长度应匹配。双向检索通常有两份分数、两份标签、两个名称，输出字典由训练引擎继续合并使用。

## 8. 不同任务如何取表示【必须会】

| 任务 | 输入特征如何取 | 候选 |
|---|---|---|
| 图像/视频分类 | `[B,L,D] → [:,0] → [B,D]` | 类别文字编码向量 |
| 图像/视频检索 | 输入与目标两侧各取汇总 token | 成对图像/句子，评价可返回归一化特征 |
| text_mlm | target_idx!=-1 选中位置 | 词表 |
| caption 训练 | 取文字预测部分，再按标签有效位筛选 | 词表 |
| caption 推理 | 取最后位置 | 下一个词的候选 |
| VQA/text classification | 可能按每条样本 spe_index 定位 | 当前任务定义候选 |

MLM=Masked Language Modeling（遮盖语言建模）。若 mask 是 `[B,T]`，布尔选择会将各句选位压成 `[M,D]`，标签变 `[M]`；M 是总有效预测位置数，不等于句长 T。

`target_idx_list[0]` 在筛选时被原地重绑定为筛选后的标签。这是调用数据字典的状态变化，读函数时要看返回值之外的修改。

SPE=special token 的项目记号。图 2 中是序列汇总 token；语言预测也会在待预测位置使用 SPE，所以不能把所有任务都解释成只读取第 0 位。

## 9. 双向检索与跨进程特征【建议会】

成对批次中的第 i 条图与第 i 条文字对应，`target=arange(B)` 得 `[0,1,...,B-1]`。分数矩阵 `[B,B]` 的对角线是正配对。转置矩阵让文字也查询图像。

`dist.all_gather` 收集各进程的图文向量。当前代码把本地可求导 packed_feature 放在首位，并排除收集列表中的本进程副本；远端收集结果不保留其原计算图。两侧用同样顺序拼接才能使 arange 标签继续正确。

memory bank 用历史候选增加负例，register_buffer 将队列保存为模型状态但不让优化器更新它。`.clone().detach()` 取队列独立数值，历史向量不反传。queue_ptr=队列写入指针，按 `% queue_len` 回到开头。原实现对批大小整除等有约束，不能任意改 batch 后推断缓存仍正确。

共享编码器、caption 掩码、Q/K/V、FFN 与深层提示的进一步说明见 [共享编码器与注意力解释](资料/共享编码器与注意力解释.md)。
