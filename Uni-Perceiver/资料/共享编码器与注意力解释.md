# Uni-Perceiver 共享编码器与注意力解释

对照 `UnifiedBertEncoder` 与 `TransformerEncoderLayer`，接续 [主讲解](../解释.md)。这里的重点是编码器实际做什么、数据形状如何保持，以及 caption 如何避免答案泄漏。

## 1. 共享骨干不等于所有位置互相可见【必须会】

图像分类可以让图像 patch 相互交流；文字生成必须按顺序预测，不能让预测位置直接读到正确未来词。共享权重可以在不同任务使用不同 mask。mask=掩码，是规定位置可见性的规则，没有可训练参数。

`UnifiedBertEncoder.forward` 输入 data 通常为 `[B,L,D]`：B=批大小，L=序列长度，D=隐藏宽度。每层注意力混合位置，FFN 改变每个位置的特征，最终仍返回同样形状。相同形状不表示数值没变化。

`invalid_mask` 是 `[B,L]`，用来屏蔽每条样本的无效 key/PAD；`attn_mask` 是 `[Lq,Lk]`，控制一个 query 位置能读哪些 key 位置。前者随样本不同，后者表达任务结构。此处布尔 True 表示禁止关注，False 表示允许。

## 2. caption 的三段长度与四块矩阵【必须会】

开启 text_spe_cat 时，特征排列可写成：

`[首部 SPE/视觉 P 个位置 | 真实文字 T 个位置 | 预测 SPE T 个位置]`。

源码把 `spe_length + img_length` 记为首部长度 P，把 `text_total_length//2` 记为 T，因此总长 `L=P+2T`。img_length 是视觉 token 数，不是图片像素边长。

矩阵**行=query（谁在读取）**，**列=key（谁被读取）**。首先全填 True，再按以下规则开放：

1. 所有位置可以读首部 SPE/视觉列。
2. 真实文字位置 i 可以读真实文字 0..i（包括自身）。
3. 预测位置 i 只能读真实文字 0..i-1（排除同位置答案）。
4. 预测 SPE 之间只允许读自己，禁止读其他预测 SPE。
5. 首部视觉/SPE 在当前掩码下不读取文字列。

第 2、3 条为什么不同？真实文字段是上下文载体；预测段才取特征去监督同位置词。若预测 SPE 也读到了同位置真实文字，相当于把答案直接递给它。

`triu(diagonal=1)` 取主对角线以上的上三角，主对角线 False，禁止未来但允许自己。`triu(diagonal=0)` 包括主对角线，连自己的真实词也禁止。`diag()` 构造对角矩阵；布尔 `~` 取反让对角线允许、非对角禁止。`~` 不是 Python 的逻辑 not，逐元素张量取反应这样理解。

## 3. 一个完整的小矩阵【必须会】

设首部只有 2 个位置（S=首部 SPE，V=一个视觉 token），文字有三个位置 w0/w1/w2，对应预测 p0/p1/p2。0 表示允许，1 表示禁止：

| query\key | S | V | w0 | w1 | w2 | p0 | p1 | p2 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| S | 0 | 0 | 1 | 1 | 1 | 1 | 1 | 1 |
| V | 0 | 0 | 1 | 1 | 1 | 1 | 1 | 1 |
| w0 | 0 | 0 | 0 | 1 | 1 | 1 | 1 | 1 |
| w1 | 0 | 0 | 0 | 0 | 1 | 1 | 1 | 1 |
| w2 | 0 | 0 | 0 | 0 | 0 | 1 | 1 | 1 |
| p0 | 0 | 0 | 1 | 1 | 1 | 0 | 1 | 1 |
| p1 | 0 | 0 | 0 | 1 | 1 | 1 | 0 | 1 |
| p2 | 0 | 0 | 0 | 0 | 1 | 1 | 1 | 0 |

例如 p1 能看 S、V、w0、自身 p1，不能看正确答案 w1，也不能借 p2 读取未来。多层堆叠时 w0 自己也看不到 w1/w2，因此没有“通过上下文中转读取未来”的这条通路。

这张表是针对源码当前条件构造的示例，不是所有任务、缓存长度、提示前缀都自动用这一个矩阵。未开启条件时函数返回 None，其他 mask 与调用者逻辑仍需一起看。

## 4. 一层 Transformer 的两个分支【必须会】

层内有 self-attention 和 FFN，两者返回残差分支增量，由 forward 加回 x。当前原版装配使用 norm_first=True，即 Pre-LN。

\[
u=x+\operatorname{Attention}(\operatorname{LN}_1(x)),\qquad
v=u+\operatorname{FFN}(\operatorname{LN}_2(u)).
\]

x/u/v 都通常是 `[B,L,D]`。LN=Layer Normalization，按最后一个特征维归一化。源码还有 Dropout、DropPath、可选 LayerScale，上式省略这些正则项以先看清主路径。

- Attention 让不同位置交换信息，受 mask 约束。
- FFN 对各位置的向量独立做相同参数变换，不直接跨位置交换。
- 残差 `x+分支` 保留原表示，也给梯度一条直接路径。

Post-LN 的运算顺序改为先相加再归一化，不能只把名字当成等价开关。源码 norm_first=False 对应这一分支。

## 5. Q/K/V、头数与 FFN【必须会】

`self.self_attn(x,kv,kv,...)` 分别传 query、key、value 的输入来源，MultiheadAttention 内部再做可学习投影。普通自注意力中 kv=x；有历史或提示时 kv 长于 x。

\[
A=\operatorname{softmax}(QK^\top/\sqrt{d_h}+M),\quad O=AV.
\]

每头的 Q 为 `[B,H,Lq,dh]`，K/V 为 `[B,H,Lk,dh]`，H=头数，dh=D/H。矩阵分数为 `[B,H,Lq,Lk]`。M 将禁止位置变成极低分数；softmax 沿 key 轴，使每个 query 的权重和为 1。不同 API 如何实现布尔 mask 的内部转换，应服从本项目调用接口。

`need_weights=False` 表示不要求返回注意力权重用于查看；注意力本身仍然计算。返回是 tuple，源码 `[0]` 取得特征部分。

FFN=`linear2(dropout(activation(linear1(x))))`：从内往外读。若 D=768、F=3072，则 `[B,L,768] → [B,L,3072] → 激活/丢弃 → [B,L,768]`。F 是中间宽度，不是头数，不是词表大小。

## 6. Dropout、DropPath、LayerScale【建议会】

Dropout 训练时随机清零一些元素，按保留概率调整尺度；评价时通常不丢。DropPath 丢的是残差路径，不能解释成“随机删掉某个词”。具体随机广播形状由 timm 实现决定。

LayerScale 的 `gamma_1/gamma_2` 是 `[D]` 可学习向量，与 `[B,L,D]` 广播相乘。初始化较小能控制初始残差更新幅度。gamma 是模型参数，attention mask 则不是。

`nn.Identity()` 原样返回输入，常作为关闭某个操作后的占位组件。`nn.ModuleList` 注册一组层，普通 Python list 不会自动注册其中模块参数。

## 7. 历史与 DeepPrompt 的边界【建议会】

history_states 按层提供旧的隐藏表示。有历史时，key/value 来源为 `cat([history_states,x],序列轴)`，query 仍是当前 x，因此 Lk 可以大于 Lq。

这里拼的是**历史隐藏表示**，不是已经投影的 K/V 缓存；不能只看到变量 history 就称为标准 KV-cache。代码还保留调整 mask 的 TODO，正式生成行为必须沿调用链验证。

DeepPrompt 向 key/value 前端插入可学习提示，query 不加提示。于是位置掩码只需增加 key 列；新列填 False 允许读取提示。padding mask 也补对应有效位置。这些提示是可学习向量，不是一个字符串系统提示。

## 8. 旧接口判断的实际风险【建议会】

本地层用主/次版本字符串判断 PyTorch 是否采用新接口，但条件是“主版本>=1 且次版本>=9”，不是正规的版本元组比较。例如 2.6 的次版本 6 小于 9，就走旧接口分支。源码因此会转置 batch/sequence，并不使用现代 batch_first 参数。

本轮只是注释，未修改原逻辑。这个事实不直接证明整个现代环境不能运行，也不能证明它完全兼容；需要最小前向对形状、历史和 mask 做实际验证。
