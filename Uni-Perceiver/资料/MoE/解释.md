# Uni-Perceiver-MoE 论文与代码解释

## 1. 材料与范围

论文 [原论文.pdf](原论文.pdf)，arXiv:2206.04674，本地为 v2。原版架构见 [Uni-Perceiver 解释](../../解释.md)。代码仍在同一官方仓库，HEAD=`a8c9e37ae25d9526a208c8f7d4403f32f99e7a72`。

核心路径：`UnifiedBertEncoder.from_config → MoETransformerEncoderLayer → TaskMoE → TopKGate → FusedExperts`。本文解释论文方法与主要实验，并对照专家装配、门控和融合路径；属性生产与编码差异见配套说明，层内与附录实验另有详细章节。完整数据链/真实模型运行及翻译审校尚未完成。

## 2. 为什么引入专家【必须会】

共享参数可以让任务互相帮助，也可能互相干扰。图片分类想调整的参数方向，未必帮助遮盖词预测。论文用任务梯度衡量一个任务的更新会让另一个任务损失下降还是上升。

表 1 行表示被影响任务 i，列表示提供更新的任务 j。第 4 层中 caption→图像分类为 +1.29；MLM→图像分类为 -0.57。第 12 层对应为 -2.45、-2.91。负数表示沿另一任务方向更新会使当前任务恶化，不能把 -2.91 解释为准确率下降 2.91 点。

该表由预训练 Tiny 模型各任务 100 批梯度估计，不能推出所有模型、所有数据、所有层都会有同样干扰。指标有归一化，方向不对称，所以 i→j 不要求等于 j→i。

专家思路：保留共享的任务形式与骨干结构，让不同条件激活不同参数子集。不是把每个任务完全拆成独立模型；也不是所有专家都对每个 token 计算完整网络。

## 3. 式 3：如何选择专家【必须会】

\[
G=\operatorname{topk}\left(\operatorname{softmax}(W_g R(x_i)+\epsilon)\right).
\]

x_i 是第 i 个 token 表示，R 是路由条件函数，W_g 是可学习门控权重，epsilon 是探索噪声。E 是总专家数，k 是选中数量，通常 k 远小于 E。G 有 E 项，未选中的项归零。

如果条件表示宽度 D、条件组数 N，门控 Linear 的权重是 `[E,D]`，输入 `[N,D]`，输出 logits `[N,E]`。softmax 沿专家轴计算概率；top-k 选下标。N 不一定等于 B×L：属性路由可对一组具有相同属性的 token 共享决策。

代码 `TopKGate.top2gating` 用 `torch.topk(...,self.k,dim=1).indices` 选专家，chunk 把下标拆成 k 份，再 one-hot 取得概率。k>1 时代码还将选中权重除以选中概率总和，使它们和为 1。论文式 3 的 topk 定义只说清零，未显式写这个再归一化步骤；对照实现要保留差别。

例如四名专家概率 `[0.5,0.3,0.15,0.05]`，top-2 选 0/1；代码再归一化后为 `[0.625,0.375]`。选中下标不是概率，门控权重不是注意力 mask。

## 4. 五种条件如何不同【必须会】

| 路由 | 条件 R | 需要 token 内容吗 | 对新任务的边界 |
|---|---|---|---|
| token | x_i | 需要 | 可跨任务，但缺少明确任务信息 |
| context | concat(x_i,attnpool(X)) | 需要 | 加全局上下文，成本更高 |
| modality | 模态 id 的 embedding | 不需要像素/词内容 | 根据视觉/文字分组 |
| task | 任务 id 的 embedding | 不需要内容 | 未见任务 id 不能直接照搬 |
| attribute | LN(W_attr attr(x_i)) | 不需要内容 | 用任务/模态语义属性描述新组合 |

context 的 concat 是向量拼接，不是求和；attnpool=attention pooling，将全序列压成全局向量。不同条件输入宽度会影响门控 W_g 的输入宽度，不能都假定原始 D。

属性路由中的“data-independent”指不依赖具体像素/词语内容，仍然依赖当前任务和 token 的属性。它不是完全无条件，也不保证任意未知任务都有合理属性描述。

## 5. 表 2：八个二元属性【必须会】

| 下标 | 问题 | 是/否 |
|---|---|---|
| 0 | 当前任务输入含视觉吗 | 1/0 |
| 1 | 当前任务输入含文字吗 | 1/0 |
| 2 | 当前任务目标含视觉吗 | 1/0 |
| 3 | 当前任务目标含文字吗 | 1/0 |
| 4 | 当前 token 是视觉的吗 | 1/0 |
| 5 | 当前 token 是文字的吗 | 1/0 |
| 6 | 当前 token 注意力是因果的吗 | 1/0 |
| 7 | 当前 token 来自输入而非目标吗 | 1/0 |

图像分类输入视觉 token 的属性是 `[1,0,0,1,1,0,0,1]`：输入图片、目标类别文字、当前 token 视觉、非因果、属于输入。

前四项描述整个任务的输入/目标模态，后面项描述当前 token。目标类别文字不等于输入中也有文字，所以第 1 项仍为 0。属性经过 Linear(8,D) 和 LayerNorm，得到门控条件。代码可配置中间 GELU，因此不是所有配置都与论文式 9 完全同一形式。

## 6. 式 4：专家输出与线性融合【必须会】

\[
y_i=\sum_{e=1}^{E}G_e W_e x_i.
\]

W_e 是第 e 个线性专家；未选中 G_e=0，不必计算。PyTorch Linear 权重 `[Dout,Din]`，使用行向量约定时为 `x @ W_e.T + b_e`。论文式 4 的列向量写法与这个代码存储约定不同，数学作用相同。

若组内 G_e 一致，可先令 `W_mix=ΣG_e W_e`、`b_mix=ΣG_e b_e`，再一次 `F.linear(x,W_mix,b_mix)`。这就是 `FusedExperts.mergelayer`。

小例子：x=2，W1=3、b1=1，W2=5、b2=-1，门控 0.625/0.375。分别算再加权：`0.625*(3*2+1)+0.375*(5*2-1)=7.75`。合并 W=3.75、b=0.25，再算 `3.75*2+0.25=7.75`。

合并仅对线性映射成立。一般 `a*GELU(W1x)+b*GELU(W2x)` 不等于 `GELU((aW1+bW2)x)`。论文将 self-attention 与 FFN 的**线性投影**换成 MoE，不是声称整个非线性网络可按权重直接平均。

## 7. 实际源码对象与变量【必须会】

`TaskMoE` 复制专家模板并创建 TopKGate；forward 返回 `(expert_output,[top_indices,gates])`。gate_decision 已提供时复用已有选择；未提供才重新路由。

`copy.deepcopy(expert)` 创建独立专家参数；`ModuleList` 注册这些子模块。`deepspeed_experts` 是历史命名，不表示本路径已经使用跨设备专家并行。

`FusedExperts` 支持一个/两个条件组。两个组时依据 `sample_info['data_cum_length'][1]` 沿序列轴切开，分别用对应门控，再 cat 拼回。indice 是代码的非标准 index 命名；indices 是下标集合。条件组数不是专家数，也不是 batch 大小。

mode='q' 时取合并 QKV 权重的前 1/3 输出行；mode='kv' 取剩余 2/3。它依赖参数按 Q/K/V 存放的约定。历史特征与当前 query 的投影可以使用不同段。

属性查表与论文的编码差异、完整门控形状轨迹及局部运行证据见 [属性与门控代码解释](属性与门控代码解释.md)。

## 8. 实验表的具体结论【建议会】

表 3 在 Uni-Perceiver Tiny 基础上对比路由。ImageNet 验证准确率越高越好，COCO BLEU-4 越高越好，MLM perplexity（困惑度）越低越好，训练时间以原版为 1 倍。

| 设置 | ImageNet 验证 | COCO BLEU-4 | MLM 验证 ppl | 训练/推理时间 |
|---|---:|---:|---:|---|
| 原版共享 | 68.3 | 18.2 | 5.86 | 1.0/1.0 |
| 任务专用参数 | 73.5 | 20.4 | 4.48 | 1.1/1.0 |
| token | 72.7 | 20.9 | 4.96 | 1.8/2.2 |
| context | 73.1 | 21.5 | 4.86 | 2.2/2.6 |
| modality | 72.6 | 21.8 | 5.06 | 1.4/1.0 |
| task | 73.2 | 21.2 | 4.56 | 1.4/1.0 |
| attribute | 73.3 | 23.0 | 4.56 | 1.4/1.0 |

属性相对原版：ImageNet +5.0 个百分点，BLEU-4 +4.8，ppl 下降 1.30。并非属性每列都是最好：任务专用 ImageNet 73.5 与 ppl 4.48 更好。作者强调任务泛化与成本折中，不能简化为“属性路由所有指标第一”。

表 4 Base：ImageNet WT 79.2→80.3，PT1% 80.9→82.0；Kinetics WT 74.5→76.8。WT=without tuning，PT=prompt tuning，FT=fine tuning；1% 是下游数据比例，不是只使用全部预训练数据的 1%。

检索也有下降：Base Flickr 图找文 WT 82.3→82.1，COCO 图找文 WT 64.9→64.6；Large Flickr 图找文 FT100% 94.7→94.1。因此正文总体改善的表述不能代替逐列核查。部署参数列也依任务不同：图像分类 Base 为 86M，而检索原版 124M、MoE 167M；不能宣称所有部署任务参数完全不增加。

## 9. 训练资源与运行边界

论文使用 AdamW，lr=0.0005，weight decay=0.05，β2=0.98，epsilon=1e-6，梯度裁剪 0.5。每个 GPU 独立抽任务/数据，反传后同步梯度。Base/Large 每隔一层放 MoE，Tiny 全层；默认 top-2，门控加入正态噪声探索。实际配置要与这些论文设置区别记录。

静态检查还发现：TopKGate.forward 的 `k==1 and gate=='deepspeed'` 分支赋值 gate_output 后没有在该分支返回，return 位于 else 内；当前路线不能假定所有宣称支持的 top-1 配置都可直接运行。另 load_balance 引用额外状态，必须沿配置初始化检查。这里记录原逻辑，没有未经验证地改算法。
