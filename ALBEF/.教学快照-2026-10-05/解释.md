# ALBEF：论文与源码解释

本文件对应当前 `ALBEF` 文件夹里的**实际源码**。建议同时打开 [`Pretrain.py`](Pretrain.py)、[`configs/Pretrain.yaml`](configs/Pretrain.yaml)、[`dataset/caption_dataset.py`](dataset/caption_dataset.py)、[`models/model_pretrain.py`](models/model_pretrain.py)、[`models/xbert.py`](models/xbert.py) 和 [`models/vit.py`](models/vit.py)。主执行路径和较难语句已添加中文行内注释；本文补上论文公式、变量来源、张量形状与实验的对应关系。

## 1. 读的是什么【必须会】

- 论文：*Align before Fuse: Vision and Language Representation Learning with Momentum Distillation*，本地 [`../papers/ALBEF.pdf`](../papers/ALBEF.pdf) 首页标为 arXiv:2107.07651v2（2021-10-07），发表于 NeurIPS 2021。
- 仓库：作者的 PyTorch 实现，[`README.md`](README.md) 指向 Salesforce/ALBEF；本地 Git 基础提交 `b9727e43c3040491774d1b22cc27718aa7772fac`。本轮编辑的是注释和说明，运行算法应保持原样。
- **ALBEF = ALign BEfore Fuse**：先把整图和整句的**全局语义向量**拉到同一空间，再让细粒度文字 token 通过**交叉注意力**读取图像 patch。论文还提出 **MoD = momentum distillation（动量蒸馏）**，用缓慢更新的教师网络提供软目标，减轻网络图文标注噪声的影响。
- 本文以预训练主路径为界；检索、VQA、NLVR2、视觉蕴含与定位只说明各自入口和与预训练结构的关系。`model_retrieval.py` 等下游模型与 `model_pretrain.py` 不是同一个文件，不能把一个文件里的细节直接当成另一个文件的实现。

## 2. 与 CLIP、ViLT 的关系【必须会】

CLIP 分别编码图像和文字，在两个全局向量之间做相似度；这使检索方便，但没有在主编码路径中让某个词直接读取某块图片。ViLT 把文字 token 与图像 patch 放成一条序列，让共享 Transformer 从早期就混合两种模态。ALBEF 走两阶段：**先全局对齐，再跨模态融合**。

论文图 1 从左往右看：图像编码器 `ViT-B/16` 输出图像位置序列，文字编码器输出文字位置序列；各取第 0 个 `[CLS]` 并投影到 256 维，用 ITC/ITA 对齐；文字序列再进入后半 BERT 融合层，以图像序列作 cross-attention 的 key/value；融合结果用于 MLM 和 ITM。下方动量模型是这些编码器及投影层的缓慢更新副本，用来产生软目标和历史候选。图里的直线箭头是张量流；参数更新则由梯度优化器和动量公式完成，不能把两种箭头理解成同一个计算。

图像编码器、文字编码器、融合层、投影层、ITM 分类头有参数；切片、拼接、矩阵乘、`softmax`、队列索引是计算操作。队列内容是**历史图文全局特征**，不是图片像素和文字 token；所以 ITM 的细粒度难负例只从当前 batch 抽取。

## 3. 符号和张量形状先统一【必须会】

下文固定：`B` 是**当前进程**一次收到的图文配对数，`P` 是图像 token 数（含图像 `[CLS]`），`T` 是文字 token 数，`D_v` 是视觉隐藏宽度，`D_t` 是文字隐藏宽度，`E` 是全局对比向量维度，`Q` 是历史队列长度。默认 [`Pretrain.yaml`](configs/Pretrain.yaml) 里 `image_res=256`、patch 边长 16，故普通方形图片有 `(256/16)^2=256` 个 patch，加图像 `[CLS]` 得 `P=257`；`D_v=768`、`D_t=768`、`E=256`、`Q=65536`。文字 `T` 随本批最长句改变，入口设最多 25 位，不能把 `T` 和 `E` 都记成 256。

| 名字 | 命名含义 | 类型与形状 | 首次产生位置 |
| --- | --- | --- | --- |
| `image` | 原始批内图片 | 浮点张量 `[B,3,256,256]` | Dataset 的 transform，经 DataLoader 拼批 |
| `text` | `forward` 中已编码的文字 | 含 `input_ids`、`attention_mask` 的 BatchEncoding | `Pretrain.train` 调 tokenizer |
| `image_embeds` | 每个图像位置的 embedding | 浮点 `[B,P,D_v]` | 学生 `visual_encoder(image)` |
| `text_embeds` | 每个文字位置的 embedding | 浮点 `[B,T,D_t]` | 学生 BERT `mode='text'` |
| `image_feat/text_feat` | 图或句的全局 feature | 单位化浮点 `[B,E]` | 对各自 `[CLS]` 做线性投影后 |
| `*_m` | momentum 动量教师对应量 | 同学生的形状 | 教师模块，无梯度计算 |
| `*_queue` | 历史全局特征队列 | 浮点 `[E,Q]` | `register_buffer` |
| `*_all` | 本批教师特征 + 队列 | 浮点 `[E,B+Q]` | `torch.cat` 沿候选列拼接 |
| `sim_i2t/sim_t2i` | 图找文／文找图分数 | `[B,B+Q]` | 学生特征乘教师候选 |
| `alpha` | 蒸馏软目标权重 | 0 到 0.4 的 Python 数值 | `Pretrain.train`；首 epoch 逐渐增大 |
| `bs` | 当前 batch size | Python 整数 | `model_pretrain.forward` 的 ITM 部分 |

`embeds` 是整条序列，每个 patch/token 都还在；`feat` 是第 0 位 `[CLS]` 投影、归一化后的全局向量。隔很长一段代码再次遇到 `text_embeds` 时，它仍是学生的文字位置序列；`text_feat_all` 才是历史队列与本批教师的全局候选。`_m` 始终表示动量教师，**不是**“masked（被遮挡）”。

## 4. 从命令、数据、配置到模型【必须会】

```text
README 的 python -m torch.distributed.launch ... Pretrain.py
  → Pretrain.py 读 --config 与 Pretrain.yaml，初始化分布式进程
  → dataset.create_dataset('pretrain', config)
  → pretrain_dataset.__getitem__ 读取图片路径与 caption 字符串
  → create_loader / DataLoader 拼当前进程的 batch
  → Pretrain.train：tokenizer(text) → BatchEncoding
  → ALBEF.forward(image, text_input, alpha)
  → 返回 loss_mlm、loss_ita、loss_itm
  → 三项求和、backward、optimizer.step、调度学习率、保存检查点
```

`python -m torch.distributed.launch` 是按当时 README 推荐的 PyTorch 分布式启动方式，不是普通的 `python Pretrain.py` 单进程命令。`--nproc_per_node=8` 意味一台机器启动 8 个训练进程。论文报告全局 batch 512、8 张 A100；YAML 的 `batch_size: 64` 是**每进程 DataLoader** 的 batch，`8×64=512` 才是全局数。当前仓库配置的 `train_file` 同时列出了 CC12M 等路径，指向更大数据设置；若只想看论文 4M 设置，需改数据路径并明确记录，不能只改模型权重名。

[`pretrain_dataset.__getitem__`](dataset/caption_dataset.py) 把 JSON 中 `{'image': 图片路径, 'caption': 描述或描述列表}` 变成 `(图片张量, 字符串)`。一图多描述时用 `random.choice` 选一句；`pre_caption` 清洗并限制词数；图片经 PIL 转 RGB、随机裁剪与增强，再成为 `[3,H,W]` 浮点张量。[`dataset.create_dataset`](dataset/__init__.py) 决定预处理流水线，`create_loader` 决定 batch、进程采样器及 `drop_last`。图像数据本身不随仓库源码附送。

[`Pretrain.train`](Pretrain.py) 使用 `BertTokenizer` 将 Python 字符串变为整数 `input_ids [B,T]` 和有效位置 `attention_mask [B,T]`。`padding='longest'` 补到本 batch 最长句；`truncation=True,max_length=25` 限上界；`.to(device)` 将返回对象中的张量搬到同一 CPU/GPU。先 `optimizer.zero_grad()` 清旧梯度；`loss.backward()` 算本批梯度；`optimizer.step()` 才真正更新学生参数。教师不在此通过梯度更新，而在模型的 `_momentum_update()` 内更新。

## 5. 论文式（1）（2）：先对齐 ITC／代码 ITA【必须会】

论文把目标称 **ITC = image-text contrastive**；仓库将同类对齐损失变量命名 `loss_ita`，**ITA = image-text alignment**。两种缩写在此分别是论文表述和源码命名，不是两套独立训练损失。对图像全局向量 $v_i\in\mathbb R^E$ 与文字全局向量 $t_j\in\mathbb R^E$，先单位化，然后点积。论文式（1）的图找文概率可写为

$$p^{i2t}_{i,j}=\frac{\exp(v_i^\top t_j/\tau)}{\sum_{k=1}^{M}\exp(v_i^\top t_k/\tau)},\qquad
p^{t2i}_{i,j}=\frac{\exp(t_i^\top v_j/\tau)}{\sum_{k=1}^{M}\exp(t_i^\top v_k/\tau)}.$$

$i$ 是当前批的图片／文字行号，$j,k$ 是候选编号；$M$ 在当前代码实现是本批候选 `B` 加历史队列 `Q`，即 `B+Q`；$\tau$ 是可学习温度 `self.temp`，正值分母越小，相似度差异经 softmax 会被放大。`image_feat @ text_feat_all / self.temp` 的形状是 `[B,E] @ [E,B+Q] → [B,B+Q]`。`F.softmax(...,dim=1)` 沿每行候选计算概率。

一热目标 $y_{i,j}=1$ 只在本批的正确对角位置 $j=i$，其他位置为 0。论文式（2）把图找文和文找图的交叉熵平均：

$$\mathcal L_{ITC}=\tfrac12\bigl[H(y^{i2t},p^{i2t})+H(y^{t2i},p^{t2i})\bigr],\quad
H(y,p)=-\sum_j y_j\log p_j.$$

**数字小例子：** `B=2,Q=3` 时分数表有 2 行、5 列；第 0 行真配对为第 0 列，第 1 行真配对为第 1 列。后 3 列是历史候选，没有本批的一热正标签。若某行 softmax 后真配对概率为 0.8，单行硬标签交叉熵为 $-\log(0.8)\approx0.223$；提高真配对概率会降低损失。实际代码还混入教师软目标，见第 8 节。

**源码路径：** [`ALBEF.forward`](models/model_pretrain.py) 先 `image_embeds` / `text_embeds`，取 `[:,0,:]` 的 `[CLS]`，用 `vision_proj`/`text_proj` 映到 256 维，`F.normalize` 成单位向量，再矩阵乘。`log_softmax` 与目标逐项相乘、按候选求和取负，并平均两个方向。这个阶段尚未运行融合层，所以叫“before fuse”。

## 6. 图 1 中的融合、ITM 难负例【必须会】

文字先以 `mode='text'` 通过 [`xbert.BertEncoder`](models/xbert.py) 的前 6 层；`mode='fusion'` 用后 6 层，并接收图像位置序列作为 `encoder_hidden_states`。当前 [`config_bert.json`](configs/config_bert.json) 明确 `fusion_layer=6`、`num_hidden_layers=12`。[`BertLayer`](models/xbert.py) 中层号大于等于 6 才创建 `crossattention`：文字位置是 query，图像 patch 是 key/value。这和 ViLT 的“先拼成一条共同序列”是不同的融合实现。

论文式（4）是二类 ITM（image-text matching，图文匹配）交叉熵：

$$\mathcal L_{ITM}=\mathbb E_{(I,T)} H(y^{itm},p^{itm}(I,T)).$$

$I,T$ 是图和文字；$y^{itm}$ 表示真/假类别；$p^{itm}$ 是融合 `[CLS]` 经 `itm_head` 后的二类概率。代码中的 `itm_head` 先返回 `[3B,2]` **logits**；`F.cross_entropy` 内部处理 softmax，不能把 logits 直接叫概率。

**难负例怎么造：** 当前批 ITA 相似度矩阵取前 `B` 列，行内 softmax 后把对角真配对概率设 0。对每张图按剩余概率抽一段难文字；对每段文字抽一张难图。相似但错误的候选更容易被抽中。`torch.multinomial(weights,1)` 是按权重随机抽样，不是永远选最大项。两组错误配对分别为“原文字 + 错图”和“错文 + 原图”，共 `2B`；加 `B` 个正确配对是 `3B`。这些配对都真正走融合层，再由 `itm_head` 分类。`B=1` 时去掉对角线后没有可抽候选，原始训练路径不能直接用单配对 batch。

**图与代码对应：** 图 1 的 hard negatives 箭头对应 `weights_i2t/weights_t2i`、`image_embeds_neg/text_embeds_neg`；cross attention 对应 [`xbert.py`](models/xbert.py) 的 `BertLayer.crossattention`；分类对应 [`model_pretrain.py`](models/model_pretrain.py) 的 `output_pos/output_neg → vl_embeddings → itm_head`。

## 7. 论文式（3）：MLM 怎么看图猜词【必须会】

MLM = masked language modeling。论文式（3）可读作

$$\mathcal L_{MLM}=\mathbb E_{(I,\hat T)} H(y^{msk},p^{msk}(I,\hat T)),$$

$\hat T$ 是部分词被遮挡后的句子，$y^{msk}$ 是原词的正确 ID，$p^{msk}$ 是模型结合图片和可见文字给出的词表概率。配置 `mlm_probability=0.15` 表示约 15% 的可遮词位置会被抽为预测题；被抽中的位置再按约 80% `[MASK]`、10% 随机词、10% 保持原词处理。`labels=-100` 的位置不计入词预测损失。

[`model_pretrain.ALBEF.forward`](models/model_pretrain.py) 的真实类名是 `ALBEF`；源码从 `text.input_ids.clone()` 同时建立可修改输入和保留正确答案的 `labels`，再调用 `mask()`。这里的 `clone()` 防止原编码对象被原地遮词操作改坏。教师用 `text_encoder_m(...,return_logits=True)` 得每位置词表分数；学生用 `text_encoder(...,labels=labels,soft_labels=...,alpha=alpha)`。关键混合损失在 [`xbert.BertForMaskedLM.forward`](models/xbert.py)，而不完全在主模型文件中。读到 `masked_lm_loss = (1-alpha)*硬标签损失 + alpha*教师软标签损失` 才算追完 MLM 路径。

## 8. 论文式（6）（7）：动量蒸馏 MoD【必须会】

网络图文配对可能不完整：图片中有狗，原网页文字只提到公园；如果把所有非原文字都视为绝对错误，会惩罚一些语义合理的答案。ALBEF 维护教师副本，让其给出柔软的目标分布。学生通过普通反向传播更新；教师通过指数滑动平均更新：

$$\theta_m\leftarrow m\theta_m+(1-m)\theta_s.$$

$\theta_s$ 是当前学生参数，$\theta_m$ 是教师旧参数，$m$ 是动量系数（配置 0.995）。例如学生某参数从 2 变 4、旧教师为 2，则新教师为 $0.995\times2+0.005\times4=2.01$：教师只慢慢跟进，因此输出通常更平稳。代码是 `copy_params()` 初始化并冻结梯度，随后每次 `forward` 的 `_momentum_update()` 原地更新 `_m` 模块。`@torch.no_grad()` 是装饰器，表示这些更新不进入反向传播图。

论文式（6）的核心混合目标：

$$\mathcal L_{ITC}^{MoD}=(1-\alpha)\mathcal L_{ITC}
+\frac{\alpha}{2}\bigl[KL(q^{i2t}\Vert p^{i2t})+KL(q^{t2i}\Vert p^{t2i})\bigr].$$

$q$ 是教师软概率，$p$ 是学生概率，$\alpha$ 是软目标权重；`KL`（Kullback–Leibler divergence）衡量两分布差异。源码把 $y$ 与 $q$ 先混成 `sim_*_targets = (1-alpha)*one_hot + alpha*teacher_prob`，再对学生做**软交叉熵**。它与上述 KL 在学生优化方向上等价，差一个与学生参数无关的教师熵常数；记录标量数值时两者未必相等。论文式（7）对 MLM 做相同思想：真实词的硬标签损失与教师词表分布损失按 $1-\alpha$、$\alpha$ 混合。

`alpha` 不是模型输入图像亮度；它从 [`Pretrain.train`](Pretrain.py) 传入，第一轮从 0 逐渐到配置 0.4，之后保持配置值。`temp` 是对比 softmax 温度，两者作用完全不同。

### 队列为什么存在【建议会】

ITC 若只用当前批 64 个候选，负例相对少。模型维护 `image_queue/text_queue [E,Q]`，把教师当前特征转置后与历史 `Q` 列拼在一起。`register_buffer` 让队列随模型保存和移动设备，但优化器不更新它。`concat_all_gather` 收集所有分布式进程的当前教师特征；`queue_ptr` 是环形写入指针。`_dequeue_and_enqueue` 要求 `queue_size % 全局当前批量 == 0`。队列帮助**全局对比**；历史位置没有完整 patch/token 序列，不能直接当 ITM 融合负例。

## 9. 论文结果怎样读【建议会】

论文第 7 页 Table 1 在 4M 图像预训练的逐步消融中，Flickr30K 文本检索平均召回（TR，R@1/R@5/R@10 平均，越高越好）由 `MLM+ITM` 的 **93.96** 升到加 ITC 的 **96.55**，增加 **2.59 个百分点**；再加难负例、动量蒸馏会继续改善。这里比较的是作者表中对应设置，不能据此断言单独改一行 ITC 代码，在任何小数据集都会多 2.59 点。第 8 页 Table 2 的 Flickr30K 微调 TR R@1：ALBEF 4M 是 **94.3**，14M 是 **95.9**；数据规模也发生变化。Table 3 的零样本 Flickr30K TR R@1 中，ALBEF 4M 为 **90.5**，CLIP 400M 为 **88.0**；它们的网络结构、数据来源与规模均不相同，不能把差值全部归因于一个损失函数。

论文 Table 4 的 VQA test-std：ALBEF 14M **76.04**，VILLA **73.67**，高 **2.37 个百分点**；NLVR2 test-P：**83.14** 对 **79.30**，高 **3.84 个百分点**。这些是具体 benchmark 的离线分数，不是本地运行结果，也不说明模型在任意真实场景都可靠。论文结尾也指出网络数据可能含隐私、不适合的图片或有害文字，部署前仍需额外分析。

## 10. Python／库函数对照【建议会】

| 用法 | 从哪里来、返回什么、为什么在这里 |
| --- | --- |
| `torch.hub.load_state_dict_from_url` | PyTorch 下载并读取 DeiT 权重字典；`init_deit=True` 时模型构造阶段调用 |
| `BertConfig.from_json_file` | 本项目 `xbert.py` 的配置类从 JSON 读隐藏宽度、层数、`fusion_layer` 等 |
| `BertForMaskedLM.from_pretrained` | 创建并装 BERT 初始权重；后续的 `mode='text'/'fusion'` 来自项目改造 |
| `nn.Linear(a,b)` | 可训练线性映射，最后一维从 `a` 变成 `b`；用在投影与 ITM 分类 |
| `F.normalize(x,dim=-1)` | 对每行全局向量做 L2 单位化；归一化后的点积可解释为余弦相似度 |
| `torch.cat(...,dim=1)` | 在现有第 1 维拼：队列 `[E,B]+[E,Q]→[E,B+Q]` |
| `torch.cat(...,dim=0)` / `torch.stack` | 前者沿原 batch 轴拼已有批，后者从多个单样本新建 batch 轴 |
| `F.softmax` / `F.log_softmax` | 把 logits 变为概率／对数概率；候选方向通常为 `dim=1` |
| `F.cross_entropy` | 接 logits 和整数类别标签，内部处理 softmax；ITM 使用 |
| `torch.multinomial` | 按权重随机抽索引；难负例不等同于固定选最大相似度 |
| `torch.no_grad()` / `@torch.no_grad()` | 无梯度上下文／整个函数无梯度，教师推理和队列更新用 |
| `register_buffer` | 保存随模型走的非可训练张量；这里是对比队列与指针 |
| `argparse` / `yaml.load` / `json.load` | 分别读命令行、YAML 配置、数据标注 JSON；文件类型不同 |

Python 细节：`class ALBEF(nn.Module)` 是继承；`__init__` 创建对象时执行，`super().__init__()` 初始化父类；`self.xxx` 留在模型实例上，`forward` 可继续使用。`@` 在张量表达式里是矩阵乘，在 `@torch.no_grad()` 前则是装饰器语法，二者字形相同、含义不同。`foo_()` 一般是 PyTorch 原地修改（例如 `clamp_`）；普通 `foo()` 通常返回新结果。`with torch.no_grad():` 只在缩进块内生效。
