# PaLI 论文与实现解释

## 1. 版本、材料与范围

本地 [原论文](原论文.pdf) 为 arXiv:2209.06794v4，2023-06-05，ICLR 2023，33 页。已有 [中文](中文论文.pdf)、[双语](双语论文.pdf)，页数/读取核对通过，全文翻译质量仍待审校。

PaLI=Pathways Language and Image model。本文读原版 PaLI，不将名字中的 PaLI-3B 与后来的 **PaLI-3** 论文混为一谈：前者是原版约30亿参数的配置，后者是新的模型系列版本。

原版采用 JAX/Flax、T5X、Flaxformer；视觉 ViT-e 用 big_vision 训练。当前本地 big_vision-PaliGemma 的公开 PaliGemma 代码是另一个模型的参考，不是原版完整 PaLI 实现。

## 2. 为什么用统一文字输出【必须会】

图片分类、图片描述、视觉问答、OCR 等输出形式不同。PaLI 使用“图片+文字提示→文字答案”，让一个模型用同一种生成接口执行这些任务，避免每个任务另建一个固定分类头。

例如描述提示要求生成图中内容；问答提示给一个问题；OCR 提示要求读图中文字；分类可对候选类别字符串的生成概率打分。统一接口不代表训练样本自动包含所有任务，仍需要任务数据和提示模板。

PaLI 使用大量多语言数据，目的是让视觉与不同语言建立联系。多语言输入、跨语言输出、问题与答案同语言，是不同协议，后面的 VQA 实验要分别看。

## 4. 图1：三个组件与形状【必须会】

图片 → ViT → 全部 patch 特征；文字提示 → mT5 编码器；mT5 解码器根据视觉与文字条件逐词生成。视觉 patch 特征不先压成单个全局池化向量。

ViT=Vision Transformer（视觉 Transformer）；mT5=multilingual Text-to-Text Transfer Transformer（多语言文本到文本模型）。mT5 包括 encoder 与 decoder，不是仅有因果 decoder 的 Gemma。

| 数据 | 类型与示意形状 | 维度含义 |
|---|---|---|
| 图片 | 浮点 `[B,H,W,3]`（JAX常用） | B批次，H/W像素高宽，3为RGB |
| 图片patch | `[B,P,Dv]` | P为patch数，Dv视觉宽度 |
| 提示编号 | 整数 `[B,Tin]` | Tin提示长度，编号是词表查表索引 |
| 条件表示 | 浮点序列 | 视觉/文字需按真实模型装配匹配宽度 |
| decoder输入 | 整数 `[B,Tout]` | 前面已知/真实答案前缀 |
| logits | 浮点 `[B,Tout,V]` | V为约250k多语言词表 |

这些是公式层面的形状轨迹，不是已确认完整 PaLI 源码字段名。视觉到语言宽度的投影、拼接位置、各层 mask 和参数加载需要原实现进一步确认；不能用 PaliGemma 字段反推原版精确行号。

ViT-e/14 的 patch边长为14。224×224 对应16×16=256个patch；588×588对应42×42=1764个patch，视觉序列增长6.89倍。若实现含特殊token，完整序列还要计入它。高分辨率不是只改变一项整数而保持计算量不变。

## 5. 自回归概率与损失【必须会】

论文说明用 teacher forcing 和标准 softmax 交叉熵，下面为解释用的通用写法，并非伪造论文编号：

\[
p(y\mid I,s)=\prod_{t=1}^{T}p(y_t\mid I,s,y_{<t}),\qquad
\mathcal L=-\sum_t m_t\log p(y_t\mid I,s,y_{<t}).
\]

I=图片，s=任务提示，y=正确答案，t=生成位置，m_t=有效监督位置开关。乘法表示整句概率分解；取对数变求和。具体按token还是样本归约应由训练实现确定。

teacher forcing=训练时把真实前缀给 decoder。例如答案是“红色 汽车 EOS”，输入前缀可依次为开始标记、“红色”、“汽车”，标签依次为“红色”、“汽车”、EOS。推理时没有真实未来答案，必须用自己已经生成的词。二者不同会产生误差累积。

logits 是未归一化分数；softmax 变概率；交叉熵监督正确词表编号。假设正确词概率0.8，损失约0.223；概率0.2，损失约1.609。损失下降不等于模型已经学会真实图像语义，需要独立数据评估。

与 CLIP 不同，这里主要多任务训练接口是条件文字生成，不是图文双向相似度损失。与 BEiT-3 遮盖任务也要区分：每个模型使用的输入可见性和目标位定义不同。

## 6. 八种预训练任务【必须会】

| 任务 | 输入条件 | 目标与关键解释 |
|---|---|---|
| 纯文字span corruption | 带哨兵的破坏文字 | 恢复文本片段，保留语言能力 |
| SplitCap | 图像+描述前半段+语言/位置 | 生成后半段，随机切点 |
| Cap | 图像+目标语言提示 | 生成完整描述，CC3M及34种翻译语言 |
| OCR | 图像+读字提示 | 生成OCR文字串，OCR=Optical Character Recognition |
| VQA | 图像+问题 | 生成英文答案；VQA=Visual Question Answering |
| VQG | 图像+答案 | 生成问题；VQG=Visual Question Generation |
| Object-aware QA | 图像+列物体/询问存在性 | 物体名称列表或Yes/No |
| 生成检测 | 图像+detect类别提示 | 框坐标和物体标签序列 |

span=连续片段；sentinel=哨兵占位标记，例如 extra_id_k。附录纯文字任务破坏15%词。SplitCap 的 cap1/cap2 是 caption 的两部分，不是两张图。

VQA/VQG 的多语言问题来自翻译，但训练答案保留英文，原因是短答案脱离上下文翻译容易出错。不能称这个预训练分支所有答案都和问题同语言。

检测示例输出 `10 20 90 100 cat ...`，坐标按 **ymin xmin ymax xmax**，量化到0..999，不是像素直接坐标，也不是常见 xyxy 顺序。原版混合中检测主要提升对象感知；存在生成检测训练任务不等于论文给出了现代检测完整性能复现。

## 7. 数据规模：收集量≠训练量【必须会】

WebLI 收集109种语言，10B图片、12B alt-text，另有29B图像-OCR对。alt-text 是网页替代文字，并非全由人按caption数据规范标注。

实际原版训练图文质量筛选保留约前10%，约1B示例；八任务混合总计1.6B训练示例。这三个数字描述不同对象，不能说“原版训练直接用全部10B图片”。生成任务可能多次利用同一底层图像，也不能把示例数直接当不同图片数。

对68个常见下游数据集进行近重复去重，降低泄漏。预训练语言长尾，60%WebLI alt-text是英语；覆盖语言数量不证明各语言质量均等。

## 8. 模型规模和训练阶段【必须会】

| 名称 | 视觉 | 语言 | 总参数 |
|---|---|---|---|
| PaLI-3B | ViT-G 1.8B | mT5-L 1.2B | 3.0B |
| PaLI-15B | ViT-G 1.8B | mT5-XXL 13B | 14.8B |
| PaLI-17B | ViT-e 3.9B | mT5-XXL 13B | 16.9B |

B=billion（十亿），M=million（百万）。名称是近似规模。ViT-G 大写G与ViT-g小写g是不同配置，不能忽略大小写。

ViT-e宽1792、56层、MLP15360、16头；视觉预训练使用JFT-3B。即使WebLI文字来自公共网页，也不能因此声称全部预训练数据可公开下载重建。

第一阶段224分辨率，遍历1.6B混合一个epoch，冻结视觉、更新语言。17B第二阶段588分辨率，10k步、batch1024约10M示例，更新所有参数；仅OCR、CC3M-35L、VQ2A等权混合。

高分辨率位置嵌入通过2D双线性插值适配更多patch，不是重复复制旧表。普通17B阶段约1024张TPUv4七天；高分辨率另512张TPUv4三天。T5X/Flaxformer支持分片；这不是个人单GPU能从零完成的资源量。

## 9. 主实验逐表理解【建议会】

以下全部是论文结果，不是本机训练。

| 表 | 具体数据 | 正确结论与限制 |
|---|---|---|
| 1，caption | COCO BEiT-3 147.6→PaLI17B149.1，+1.5CIDEr | 不使用CIDEr优化；NoCaps test124.4低于GIT2 124.8，非所有列第一 |
| 1，读字caption | TextCaps test GIT2 145.0→160.4，+15.4 | PaLI任务微调使用OCR串；需同输入条件比较 |
| 2，多语言 | 35语均值28.9→53.6，+24.7；中文19.8→36.5，+16.7 | 分词/去标点协议影响CIDEr，不用各语言原分数直接排序语言能力 |
| 3，VQA | test-std BEiT-3 84.0→84.3，+0.3 | PaLI生成，BEiT-3常用固定候选；test-dev差0.1，是另一列 |
| 3，OKVQA | KAT54.4→64.5，+10.1 | 训练微调协议；Flamingo57.8是32-shot，不能当同条件控制实验 |
| 3，TextVQA | val71.81、test73.06 | test低于Mia73.67，不能称每指标都最高 |
| 4，xGQA | 中文39.5→50.6，+11.1 | 多语言问题、英文答案 |
| 4，MaXM | 中文30.3→46.9，+16.6 | 答案与问题同语言，协议不同 |
| 5，分类 | 3B70.06→17B72.11，+2.05 | 224无高分辨率checkpoint；Flamingo5-shot77.3仍更高，且提示协议不同 |
| 6，消融 | 去split-cap：TextVQA41.6→38.8，-2.8 | 3B仅200M示例，不能和完整17B训练直接等规模比较 |
| 6，去OCR | COCO141.4→142.3提高0.9，但TextVQA41.6→39.9降1.7 | 任务贡献有取舍，不能说每项都受益 |
| 6，去VQG | VQG零样本96.7→17.9，降78.8 | 该任务训练是生成问题能力的重要来源；非所有下游任务同幅下降 |

CIDEr=基于n-gram一致性的图像描述指标；Acc=准确率；ANLS=Average Normalized Levenshtein Similarity，用归一化编辑距离评价读字问答。不同单位不能平均成统一“正确率”。

## 10. 图2：联合扩展的结论边界【建议会】

固定视觉ViT-G，语言1B→13B，七任务平均增益约3.1；固定语言XXL，视觉约2B→4B，平均约3.2；高分辨率另加2.0。作者据此强调视觉容量也值得扩展。

七任务混合CIDEr与准确率，平均只是论文总结方式，不是一个统一自然单位指标。也不能把这组观察外推成任意模型“视觉每增加1B一定更划算”。高分辨率还增加额外训练与计算成本。

## 11. 语言能力、OCR与分类的进一步区别

语言保留由纯文字混合帮助，但不能单凭模型大就证明不遗忘。论文用SuperGLUE微调、XTREME中的XNLI/XQuAD/TyDiQA零样本迁移分别评估，完整数字需继续读附录表11。

图中文字可通过视觉编码器学习读取，也可以将外部OCR字符串作为文字输入；这是两个不同系统。主TextVQA/TextCaps的OCR输入协议与无OCR附录结果不能混用。

生成分类对每个候选类别字符串算条件概率，考虑多词类别序列；不是简单拿ViT平均向量接线性1000类头。具体长度归一化、模板集成等由附录C.8进一步确定。

## 12. 代码、库与复现边界

| 工具 | 用途 | 不能推断的事 |
|---|---|---|
| JAX/jnp | 数组、自动求导、编译 | 与PyTorch API不能逐字替换 |
| Flax | 模块/参数管理 | 同样叫nn.Module也不等于PyTorch状态管理 |
| T5X | 大规模encoder-decoder训练/分片 | 框架开源不等于完整PaLI训练已公开 |
| Flaxformer | Transformer组件 | 有组件不等于全部模型装配存在 |
| big_vision | 视觉模型与训练 | 当前PaliGemma不是原版mT5 PaLI |
| Adafactor | 论文语言/多模态训练优化器 | 与AdamW默认行为不同 |

本地公开参考仓库 HEAD=`0127fb6b337ee2a27bf4e54dea79cff176527356`。已检查文件树，现有paligemma.py/gemma_bv.py等为PaliGemma。官方 [PaliGemma说明](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/README.md) 明确其采用SigLIP/Gemma、受PaLI-3启发。它可帮助理解视觉条件生成，但不能代替PaLI原版实现。

必须掌握：ViT与encoder-decoder、保留视觉patch、teacher forcing、提示区分任务、数据量/训练量、冻结与全模型阶段。

第二遍：多语言问答协议、OCR输入、生成检测坐标、模型扩展/消融公平性。

工程可以暂缓：TPU分片、T5X完整配置、JFT/WebLI重建、极大模型训练。

**复现状态：未复现。** 已完成主要方法和主表精读，当前没有确认完整原版实现与本机训练/评价。公开PaliGemma参考讲解/运行不得改变这个状态。
