# PaLI-X 论文与实现解释

## 1. 版本与阅读入口

本地 [原论文](原论文.pdf) 是 arXiv:2305.18565v1，2023-05-29，30页。已有[中文](中文论文.pdf)、[双语](双语论文.pdf)，页数/全页读取已核对，全文审校未完成。前序[PaLI讲解](../PaLI/解释.md)解释通用生成接口，本文展开新增内容。

PaLI-X 约55B参数，由22B视觉ViT与32B语言encoder-decoder组合。B=billion（十亿）；模型结构仍是图像/文字条件生成，不能把PaliGemma的Gemma decoder-only代码称为本篇原实现。

## 2. 要解决什么与变化【必须会】

相比PaLI，PaLI-X扩大视觉与语言组件，同时扩大训练任务范围：读字、文档/图表、视频、带示例条件生成、检测与图像离散token预测。更大的规模与更好的任务混合一起变化，结果不能全部归因为参数变大。

视觉骨干采用ViT-22B，另进行OCR相关预训练；语言骨干是UL2变体32B，encoder和decoder各50层。UL2是统一语言学习的模型/训练框架，不能与原版mT5-XXL视为完全相同。

## 3. 图像与多图输入【必须会】

图像分别经过同一个ViT，输出patch表示；经过投影匹配语言宽度后，与文字embedding拼接给encoder。decoder根据条件生成。视觉patch不在空间轴提前池化成一个向量。

| 变量（解释用） | 示意形状 | 含义 |
|---|---|---|
| images | `[B,n,H,W,3]` | B批次，n图像/帧数，H/W像素 |
| image_features | `[B,n,P,Dv]` | 每图P个patch，Dv视觉宽度 |
| visual_sequence | `[B,n*P,Dl]` | 投影后展平图像/patch轴，Dl语言宽度 |
| input_tokens | `[B,Tin]` | 文字提示和示例编号 |
| condition | `[B,n*P+Tin,Dl]` | 编码器条件序列 |
| text_logits | `[B,Tout,V]` | decoder各位置词表分数 |

这些不是确认的原源码变量名，而是为追踪公式自行定义的名称，不能引用成官方字段。文字和图像实际排列/位置/mask要按原实现核对。

正文视频224分辨率每帧16×16=256个patch。8帧有2048个视觉token，16帧有4096个；计算随序列增长，不等于只是多读几张缩略图。

## 4. 视觉OCR预训练不是句子生成【必须会】

ViT-22B原来做JFT图像分类。为让视觉组件更懂文字，WebLI图片经GCP Vision API提取OCR文本，再用mT5 tokenizer转为词元集合；视觉网络预测每个词元是否出现在图中，这是bag-of-words（词袋）多标签分类。

多标签：多个token可同时出现；通常每个候选有独立存在性预测，不要求概率总和为1。词袋忽略词序，不能只凭这个预训练就说视觉网络已会生成完整句子或恢复排版。

该步骤与后续split-OCR文字生成是两种目标。后者才用多模态encoder-decoder预测文字片段。外部OCR文本还可以作为下游文字输入，必须另标“with OCR”，不能和仅靠图像内部读字比较混用。

## 5. 十三种训练目标地图【必须会】

| 目标 | 输入/输出主要角色 |
|---|---|
| span corruption | 纯文字破坏15%词，恢复文本 |
| split caption | 图+描述前缀→后续描述 |
| multilingual caption | 图+语言提示→描述 |
| split OCR | 图+OCR前缀→OCR后续文字 |
| VQA | 图+问题→答案 |
| VQG | 图+答案→问题 |
| object-aware VQA | 图+物体问题→名称/存在性 |
| episodic caption | 多个相关图文示例→目标描述 |
| four-pair VQA | 多个图问答示例→目标答案 |
| pix2struct | 页面截图→DOM/页面结构文本 |
| video caption | 多帧→视频描述 |
| object detection | 图+类别提示→坐标与名称 |
| masked image tokens | 遮盖图片→离散图像token |

DOM=Document Object Model（文档对象模型），用结构表示页面；pix2struct并不只是普通OCR抄字。image-token目标用ViT-VQGAN在256×256、patch16下产生256个离散图像token，不是直接生成RGB连续像素。论文加入它主要检查是否伤害语言任务，不能据此声称已有完整高质量图像生成评价。

## 6. Episodic数据与少样本原理【必须会】

episode=一组相关示例。Episodic WebLI按URL聚组，希望同一组图文有松散关系，75M组约400M图片。它不是保证每组都同一个精确任务，也不是公开下游评价集。

N-shot输入包含N对示例图片/文字，以及目标图片/提示。模型要根据示例上下文生成目标答案。每张图独立编码，所有patch序列进入条件；不是先把示例变成一个训练梯度并现场更新权重。

训练时有encoder shots与decoder shots：encoder示例给出提示和答案，decoder示例只有提示送encoder，答案需要decoder预测。将部分示例也设为预测目标增加训练任务难度。

评价前还做少样本任务混合微调：预训练最多4 shots，相关微调最多8 encoder shots，然后评价4/32 shots。这与“完全没有少样本相关训练、直接靠大模型自然获得能力”的说法不同。推理测试样本时参数固定，才是in-context学习。

## 7. 注意力再加权【建议会】

随着示例变多，目标图/提示可能在很多上下文token中被稀释。论文在decoder跨注意力中提高目标图和目标提示对应的权重：N个shots时目标相关权重乘N。精确归一化和计算位置仍需原代码确认，不把文字描述替换成编造的实现。

可用示意帮助理解：一组目标注意力总质量为0.1，其他示例为0.9；乘N=4后未归一化质量0.4/0.9。若重新归一化，目标质量约0.308。这个数字是解释用示例，不是论文实际记录。

附录早停3B实验，4/8/16 shots无再加权CIDEr83.4/76.5/66.3，有再加权82.1/84.3/84.5。因此它并非每个shot数都更好；4-shot下降1.3，高shot改善更明显。不能将小模型消融当成55B全部配置的直接验证。

## 8. 训练阶段与损失【必须会】

stage1冻结经OCR混合训练的ViT，其他参数在224分辨率、完整混合上训练2.2B示例。stage2主要用pix2struct、split-OCR、检测，逐步提高到448/672/756。各子阶段冻结/更新细节仍需确认，不只凭原版PaLI策略推断。

通用文字生成仍可写成 `-Σ log p(y_t|图像、提示、真实前缀)`，teacher forcing含义见前篇。图像离散token目标是例外输出类型。统一生成接口不能让词表、EOS、监督mask和目标格式自动相同。

任务微调多数冻结ViT，lr1e-4线性衰减。表20：COCO10k步/batch256；VQAv2、OCRVQA和多任务20k/batch256；其他5k/batch128。一个任务调参结果不代表预训练无需资源。

## 9. 表1/2：扩大模型的收益与反例【建议会】

以下都是论文结果，不是本机复现。

| 比较 | 数字与变化 | 协议/限制 |
|---|---|---|
| COCO CIDEr | PaLI149.1→X149.2，+0.1 | 小改善，不能以参数3倍称显著提高所有任务 |
| NoCaps test | 124.4→124.3，-0.1 | X没有超过原版此列 |
| VQAv2 test-std | 84.3→86.1，+1.8 | 生成问答，模型/训练同时变化 |
| OKVQA |64.5→66.1，+1.6 | 与更大PaLM-E66.1相同，不是严格超过 |
| TallyQA complex |70.9→75.6，+4.7 | 相比MoVie56.8为+18.8；两种基线不能混算 |
| TextVQA test | 无OCR71.44，有OCR80.78 | 差9.34，额外OCR系统明显帮助 |

## 10. 表3/4：多任务与少样本【建议会】

caption多任务微调 vs 单任务：COCO149.2→147.3，-1.9；TextCaps150.8→154.6，+3.8；Screen2Words127.9→120.6，-7.3。六任务平均-1.4，排除Screen2Words约-0.2。优势是一个checkpoint服务多任务，不是完全没有性能损失。

同一多任务checkpoint无逐任务验证最优选择；各任务收敛速度不同，评价条件应计入。训练集还对各任务测试集做去重，避免不同任务混合引入泄漏。

表4 few-shot COCO：4-shot103.2→107.6，+4.4；32-shot113.8→114.5，+0.7。XM3600均值45.1/47.1仍低于原版充分微调53.6，协议不是同样训练量。

少样本VQAv2：Flamingo63.1/67.6，X56.9/57.1，分别落后6.2/10.5。作者讨论语言骨干微调可能影响某些少样本能力，结果不支持所有少样本任务都改善。

## 11. 表5：视频不等于零样本迁移【建议会】

视频任务分别微调，224分辨率，验证集早停；8或16帧，固定数据集时间间隔采样。caption用CIDEr，MSR-VTT/ActivityNet QA用完整字符串准确率，NExT-QA用WUPS（基于语义相似度的指标），不能同数值横比。

16帧对8帧：ActivityNet caption49.0→54.9，+5.9；MSR-VTT caption74.6→76.8，+2.2；MSR-VTT QA46.9→47.1，仍低于先前47.4。VATEX69.3低于GIT2的94.0，但后者用了直接CIDEr优化，协议不同；不能称X全面超过，也不能不说明训练目标差异。

预训练包含四帧视频任务，因此不是完全纯图像模型从没见视频直接测试。

## 12. 表6/25/26：分类数字的区别【建议会】

主表微调分类X756为89.19，GIT2为89.22，X低0.03。附录该X结果带†，训练2.2倍步数；普通756配置88.82。不能把89.19当没有额外步骤的默认配置。

零样本表25：PaLI17B72.11，X71.16，下降0.95；ImageNet-A44.70→46.13提高1.43。更大模型不保证各分布全部提升。

微调分类直接生成英文类别名并检查字符串；零样本使用与PaLI一致的类别计分方式。zero-shot、fine-tuned与few-shot列必须分别解释。

## 13. 检测：提示、坐标和评价范围【建议会】

提示格式为 `detect class1 and class2 ...`，输出指定类别的框/名称。坐标按ymin xmin ymax xmax，范围0..999。正类别/已知负类别/全局负类别用于训练不同类别条件，不能把没标注的物体都视为真实不存在。

表7 LVIS zero-shot AP12.36、rare12.16；检测专项调优后AP30.64、rare31.42。AP=Average Precision，Rare=罕见类别；这两行不是同一个checkpoint协议。相关基线用不同数据设置，论文也说不直接可比。

正文与附录对预训练去除LVIS类别范围的描述不同（正文提LVIS/COCO标签、附录明确LVIS-rare预处理）。实际可重建协议仍需原配置核查，不能自行合成唯一确定答案。

多语言检测、OCR框、长描述图例属于定性能力展示，不证明各种语言检测AP已系统评估。

## 15. 学习优先级与复现状态

必须掌握：encoder-decoder、多图patch序列、OCR词袋与文字生成、少样本训练/推理区别、协议对齐。

第二遍：再加权、encoder/decoder shots、离散图像目标、视频采样、检测坐标。

可以暂缓：超大模型分片、TPU训练、私有WebLI重建、完整55B训练。

**复现状态：未复现。** 完成主要方法、主表与关键附录精读，未运行原模型训练/评估，也未将参考PaliGemma运行标为PaLI-X成功。
