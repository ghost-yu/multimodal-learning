# PaLI-3 论文与代码解释

## 1. 阅读范围与最先要理解的问题

论文是 *PaLI-3: Smaller, Faster, Stronger*，本地原文为 arXiv:2310.09199v2（2023-10-17），共 16 页。[原论文](原论文.pdf)、[中文译文](中文论文.pdf)、[双语译文](双语论文.pdf) 已保存。译文来自 pdf2zh/API，全文排版与翻译仍需审校。下面的解释以英文原文为依据。

PaLI-3 问的是：在视觉语言模型里，如何选择视觉编码器，让较小模型也能做好读图中文字、定位、问答？前一篇 PaLI-X 有约 55B 参数，本篇约 5B。B 是 billion，十亿；5B 约 50 亿，仍然不是普通笔记本上适合从头训练的小模型。

本篇的关键发现是：ImageNet 图像分类成绩较高，并不保证编码器用于视觉语言任务时更好。分类训练偏重把整图分为一个类别；图文匹配会从图片与自然语言的联系中学习。论文比较后发现，后者在文字理解、定位任务上特别有帮助。与此同时，数据、分辨率和训练任务也变了，不能把整个改进都归因于一个损失函数。

代码范围需要准确区分：本地 Big Vision README 标注 PaLI-3 为 partial（部分公开）。这里确认并注释的是 **SigLIP 双塔与图文匹配损失组件**，对应视觉预训练思路；未确认存在完整的本论文 2B ViT + 3B UL2 装配和全部训练流水线。PaliGemma 是相关后续公开模型，不能将其文件直接称为 PaLI-3 原版实现。

## 2. 术语和三套结构

| 名字 | 展开与含义 | 本篇作用 |
|---|---|---|
| ViT | Vision Transformer，视觉 Transformer | 把图像切为 patch（小块），编码为视觉 token |
| SigLIP | Sigmoid Loss for Language Image Pre-Training | 使用 sigmoid 图文匹配目标预训练视觉和文字双塔 |
| UL2 | Unifying Language Learning，一种统一语言学习预训练框架 | 本篇使用约 3B 参数的编码器—解码器语言组件 |
| OCR | Optical Character Recognition，光学字符识别 | 读出图像中文字，也为训练构造文字相关任务 |
| VQA | Visual Question Answering，视觉问答 | 输入图片、问题，生成答案 |
| grounding | 将文字描述对应到图中位置 | 输出框或分割掩码 |
| fine-tuning | 微调 | 在已有权重上针对具体任务继续训练 |
| frozen | 冻结 | 前向仍计算，参数不被梯度更新 |

### 2.1 阶段 0：SigLIP 双塔

图片进入视觉编码器，配套文字进入文字编码器，得到两个相同维度的全局向量。模型判断某图片与某文字是否配对。这时的文字塔用于训练视觉表征，**不是后面负责生成答案的 UL2 解码器**。

### 2.2 阶段 1、2：完整 PaLI-3

SigLIP 的视觉编码器被接入 PaLI 的编码器—解码器结构。输入图像保留未池化的视觉 token，经线性投影后，与输入文字 token 一起给 UL2 编码器；UL2 解码器逐个生成输出 token。SigLIP 的匹配文字塔不作为这个生成结构的语言模型沿用。

### 2.3 任务专门化

使用上述模型的检查点，在特定数据集上微调。这个阶段的评估成绩，不等于不用训练就获得的 zero-shot（零样本）成绩。

## 3. 输入、形状与参数流

【必须会】设批量大小为 $B$，图像高宽为 $H,W$，patch 边长为 $P$，视觉宽度为 $D_v$，UL2 宽度为 $D_l$，输入文字长度为 $L$，输出长度为 $T$。

1. Big Vision 常用图片形状为 $[B,H,W,3]$，最后 3 维表示 RGB 通道。PyTorch 常见的 $[B,3,H,W]$ 排列与它不同。
2. 若尺寸可整除，视觉 patch 数为 $N=(H/P)(W/P)$；例如 224 和 patch 14，$N=16^2=256$。实际实现可能还有特殊 token，必须按编码器输出核对，不能无条件把所有视觉序列都当 256。
3. ViT 输出未池化序列 $V\in\mathbb{R}^{B\times N\times D_v}$。线性投影 $V'=VW_p+b_p$，其中 $W_p\in\mathbb{R}^{D_v\times D_l}$，$V'\in\mathbb{R}^{B\times N\times D_l}$。
4. 输入文本的 token IDs 为整数 $[B,L]$；嵌入查表得到 $E\in\mathbb{R}^{B\times L\times D_l}$。编码器接收视觉与文字序列，长度约为 $N+L$。concat（拼接）是延长 token 序列，不是把每个视觉向量和文字向量按特征硬接起来。
5. 解码器依据编码器信息和已有输出前缀生成词表分数 $[B,T,|\mathcal V|]$，$|\mathcal V|$ 是词表大小。它学习的是生成文字的交叉熵，不是 SigLIP 的 $[B,B]$ 配对损失。

这是一张语义形状图，不声称本地已运行完整 UL2。论文提到 ViT-G 的宽度从常用 1664 调整为 1536 以改善硬件利用率；不能只凭名字相同就认为所有 ViT-G 配置完全一致。

## 4. SigLIP 的公式，逐项算清楚

### 4.1 双塔向量与分数

【必须会】令图片向量为 $v_i\in\mathbb R^C$，文字向量为 $u_j\in\mathbb R^C$。$i,j$ 是本批样本索引；$C$ 是共享匹配特征宽度。代码把每条向量除以自己的 L2 范数（向量长度），用一个很小的 $\epsilon=10^{-8}$ 防止零除：

$$\hat v_i=\frac{v_i}{\|v_i\|_2+\epsilon},\qquad \hat u_j=\frac{u_j}{\|u_j\|_2+\epsilon}.$$

然后计算未转成概率的 logit：

$$s_{ij}=a\hat v_i^\top\hat u_j+b,\qquad a=\exp(t)>0.$$

$t$ 是学习到的 log-scale（缩放系数的对数），$a$ 是实际正缩放，$b$ 是共享偏置。源码 `extras["t"]` 存的是 $a$，`out["t/parameter"]` 才存原始 $t$。名字叫 temperature 的初始化项，在这里实际乘在相似度上，不能直接按“除以温度”解释。

两个批量向量矩阵都是 $[B,C]$。`jnp.dot(zimg, ztxt.T)` 把文字矩阵转置为 $[C,B]$ 后相乘，得到 $[B,B]$。矩阵第 $i,j$ 个数表示第 $i$ 张图片与第 $j$ 条文字的匹配分数。

### 4.2 正负标签与损失

默认同索引图文是真配对，其余组合为负对：

$$y_{ij}=\begin{cases}+1&i=j\\-1&i\ne j\end{cases},\qquad
\mathcal L_{\mathrm{SigLIP}}=-\frac1B\sum_{i=1}^B\sum_{j=1}^B\log\sigma(y_{ij}s_{ij}).$$

$\sigma(x)=1/(1+e^{-x})$ 是 sigmoid。正对希望分数大；负对标签为 $-1$，希望原分数小，乘标签后变大。`jax.nn.log_sigmoid` 稳定地算对数 sigmoid，避免先得到几乎为零的概率再取 log。

源码 `m1_diag1` 名字拆开是 **minus one / diagonal one**：非对角为 -1，对角为 +1。计算 `-ones_like(logits)+2*eye`；`eye` 是单位矩阵。`nll` 是 negative log likelihood（负对数似然），对每行先 sum，再对行 mean，因此系数为 **$1/B$**。如果直接对全部格子取平均，会变成 $1/B^2$，与当前代码尺度不同。

数字例子：$B=2$，两塔向量都是 $[[1,0],[0,1]]$，$a=2,b=-1$。点积矩阵是单位阵，logits 为 $[[1,-1],[-1,1]]$。乘标签后四格都是 1，每格负对数似然约 0.313262。每行求和约 0.626523，两行平均仍约 **0.626523**。全格 mean 会得到 0.313262，少一倍。

负对通常多于正对，偏置能调整默认匹配倾向。双塔训练并不理解数据中“不同索引但仍然语义匹配”的所有情况；对角配对假设是目标构造约定，不是真实世界绝对规则。

### 4.3 与 CLIP、后续文字生成的联系

CLIP 常用行/列 softmax 对比交叉熵：样本在批内与其他候选竞争。SigLIP 把各图文对作为二元配对判断，用共享模型表示连接这些判断。这里的区别不等于两个方法完全没有共同点，两者都学对齐的图文嵌入。

接入 UL2 后，输出文字采用自回归生成目标，可概括为：

$$\mathcal L_{\mathrm{text}}=-\sum_{t=1}^{T}\log p_\theta(w_t\mid w_{<t},I,q).$$

$I$ 是图片，$q$ 是输入问题/指令，$w_t$ 是正确输出 token，$w_{<t}$ 是此前正确输出前缀（teacher forcing，教师强制）。真实代码还需处理 padding mask 和归约尺度；本地未确认完整 PaLI-3 该路径，不能把这个概括式当成已执行代码。

## 5. 公开组件的代码入口

| 文件/对象 | 功能 | 对应范围 |
|---|---|---|
| [two_towers.py](../../big_vision-PaliGemma/big_vision/models/proj/image_text/two_towers.py) `Model.__call__` | 两塔创建、前向、单位化、缩放和偏置 | SigLIP 预训练组件 |
| 同文件 `load` | 恢复图像/文字/缩放/偏置参数树 | 检查点加载 |
| [siglip.py](../../big_vision-PaliGemma/big_vision/trainers/proj/image_text/siglip.py) `update_fn/loss_fn` | 标签矩阵、sigmoid 损失、梯度、优化更新 | SigLIP 训练器核心 |
| 完整 ViT→投影→UL2→生成 | 未找到并确认完整本论文装配 | 不能用 PaliGemma 替代 |

库的角色：`importlib` 是 Python 动态导入标准库；`typing` 提供类型提示；`absl.logging` 记录日志；`flax.linen` 管理神经网络模块/参数；`jax.numpy` 提供数组运算；`jax.value_and_grad` 自动微分；`optax` 提供优化器变换与参数增量应用。这里 `nn` 是 Flax 的别名，不能照搬 PyTorch 的接口。

Flax 常见调用关系：构造 `model` → `model.init(...)` 初始化变量树 → `model.apply({"params": params}, ...)` 前向。`@nn.compact` 允许在方法内部声明模块/参数；`self.param` 在初始化时建立参数，在前向时读取已有参数。装饰器名字 compact 不表示模型已经压缩。

变量回顾：`ztxt`=文字嵌入，`zimg`=图像嵌入，均 $[B,C]$；`out/extras`=辅助字典；`labels` 在训练器入口是文字 token IDs，**不是**正负图文对标签；真正正负标签是 `m1_diag1`；`grads`=梯度参数树；`opt`=优化器状态；`updates`=优化器计算的参数增量。详细说明已写入源文件。

检查点函数的注意点：`init_files.pop("image", init_files.pop("img", None))` 内层默认参数会先计算，两个别名同时提供时都会被消费；`{**init_files}` 是浅复制，防止外层字典被 pop 改动。检查点别名表包括后来的 SigLIP2，不能用它证明本篇用了 SigLIP2。

## 6. 四个训练环节

| 环节 | 训练什么 | 图片尺寸/数据 | 阅读要点 |
|---|---|---|---|
| 阶段 0 | SigLIP 视觉和文字双塔 | WebLI 筛选保留约 40%，224 分辨率 | 学图文对齐，视觉编码器约 2B |
| 阶段 1 | 组合模型，冻结视觉 | 224；增强 WebLI、文档/PDF/海报等多语数据，以及 OCR、问答、检测相关任务 | 让约 3B UL2 学习使用视觉 token |
| 阶段 2 | 解冻全模型，短期高分辨率训练 | 812、1064 的课程安排，偏重 OCR/定位 | 高分辨率增加视觉 token 与计算量 |
| 任务专门化 | 特定任务微调，冻结 ViT | 多数 812；DocVQA/InfoVQA 1064 | 下游成绩来自各自微调设置 |

UL2 在语言预训练时使用多种 denoising（去噪）任务；PaLI 的任务混合包含文本生成，不是把所有任务都当 SigLIP 二分类。

论文说没有视频**预训练**。视频实验仍然对视频任务做微调：从阶段 1 检查点开始，224 分辨率，采样 16 帧，最多 4096 个视觉 token。因此“无视频预训练”不代表“从未见过视频训练数据”。

## 7. 实验怎么读

### 表 1：视觉预训练方式的受控比较

使用相同 PaLI 框架、224 分辨率、缩短的阶段 1 训练（20% schedule）比较分类预训练与 SigLIP。G 规模的 8 任务平均 few-shot probe（冻结视觉后的少样本线性分类探测）88.1 下降约 2.5 点，但 TextVQA 31.9 提高 18.7 点，RefCOCO 51.6 提高 15.1 点，RefCOCO+ 43.5 提高 19.1 点，RefCOCOg 43.4 提高 17.7 点。

这支持“分类 probe 并非视觉语言能力的充分指标”。小规模 B 的 XM3600 英文/非英文 caption 成绩分别下降 2.0/0.2，提醒并非每个任务都改善。分类预训练采用 JFT，SigLIP 用 WebLI，数据来源与目标同时不同；不能声称只改损失、完全排除了数据因素。

### 表 2：读字、文档、界面任务

有额外 OCR 输入时，PaLI-3 的 TextVQA 80.78 与此前最佳相同；DocVQA 88.6 比 88.4 高 0.2；InfoVQA 62.4 比 61.2 高 1.2。AI2D 75.2 低于 81.4，ChartQA 69.5 低于 72.3。

无额外 OCR 输入时，TextCaps 158.8 比 147.0 高 11.8，TextVQA 79.51 比 71.44 高 8.07，InfoVQA 57.8 比 49.2 高 8.6，DocVQA 87.6 比 80.0 高 7.6。AI2D/ChartQA 仍不是全面领先。with OCR 是向模型额外提供识别结果，不代表 without OCR 的图片没有文字。

CIDEr 衡量描述与参考文本一致性；ANLS=Average Normalized Levenshtein Similarity（平均归一化编辑距离相似度），允许小拼写差异；问答任务还使用准确率、精确匹配，ChartQA 使用其容差协议。表中的平均混合了不同尺度的指标，不应解释为统一的“正确率”。

### 表 3：文字指代分割

分割希望逐像素判断对象位置。论文用 VQ-VAE（Vector Quantized Variational Autoencoder，向量量化变分自编码器）把 $64\times64$ 掩码压为 16 个离散码，码本大小 128。PaLI 输出四个框坐标 token 和 16 个掩码 token；外部解码器恢复框内掩码，再映射回原图。它并非直接输出 $H\times W$ 个像素标签。

RefCOCO/+/g 验证集 mIoU 从 PolyFormer 的 76.94/72.15/71.15 到 77.33/73.53/72.72，提高 0.39/1.38/1.57。mIoU=mean Intersection over Union（平均交并比），越高越好。组合训练集排除验证/测试样本，VQ-VAE 的数据划分也要排除它们；不能只检查主模型划分。

### 表 4：自然场景理解

COCO CIDEr 145.9 低于 PaLI 149.1、PaLI-X 149.2。VQAv2 test-std 85.2 低于 PaLI-X 86.1，差 0.9 点。OKVQA 60.1 低于 PaLI 64.5、PaLI-X 66.1。TallyQA complex 70.5 低于 PaLI 70.9、PaLI-X 75.6。这些反例说明模型更小、读字更强，与所有任务都超过大模型是不同结论。

### 表 5、10：视频与数据可用性

视频问答 MSRVTT-QA 49.3 相比 48.0 提高 1.3，ActivityNet-QA 51.2 相比 49.4 提高 1.8；MSRVTT caption 78.3 低于 80.3，ActivityNet caption 50.8 低于 54.9。VATEX 66.9 与采用 SCST（Self-Critical Sequence Training，自我评价序列训练）的 94.0 不能只按数字归因于模型规模。

附录表 10 给出重新收集后可用的视频数。例如 MSRVTT test 从 2990 到 2135，保留 71.40%；ActivityNet-QA test 从 8000 到 7040，保留 88%。失效链接使实验子集与原始公开划分不同。SMIT valid 一列的 8096/14604 与打印的 100% 不一致，正文/表题关于 training/evaluation 的描述也需谨慎，不能自行修正为某个未证实划分。

### 表 6、11与图 3、4：单独的视觉组件

SigLIP-G 在 ImageNet 518 分辨率微调为 89.6，分类预训练 G 为 90.5，下降 0.9；ImageNet-v2 82.3 对 83.3。多语检索则把两种视觉组件接入可比较的 LiT 文本调优设置，XM3600 平均图搜文 56.85 对 35.99，提高 20.86；文搜图 43.98 对 28.46，提高 15.52。比较对象 ViT-G 约 2B、ViT-e 约 4B，并非完全相同编码器尺寸。

Recall@1 表示第一候选命中比例。中文图搜文 57.92 对 33.61，增加 24.31；文搜图 41.51 对 28.24，增加 13.27。论文表题声称所有语言更强，但 quz（克丘亚语）文搜图 1.89 低于 1.90，存在微小反例；mi（毛利语）0.64/0.30 仍很低。平均提升不证明每种语言都可靠。图 3/4 每根柱对应一个语言、横轴为语言代码，两个颜色为两种视觉组件；它们评估检索组件，不是完整 PaLI-3 生成模型。

## 8. 公平性实验与局限

表 7/8 使用 Perspective API 评分阈值大于 0.8 的毒性/威胁输出，过滤部分不足 20 条的分组。FairFace 总体毒性 0.04%、威胁 0.11%；MIAP 总体 0.07%/0.65%。这是指定提示、数据、自动评分器与阈值下的比例，不是模型永远无害的保证。

表 9 对只有一个人的图片询问是否有人，记录假阴性。不同性别分组错误率 0.41%/1.78%；肤色部分组只有 1、2、6 个样本，0% 不能视为高可信总体结论。

图 2 的 demographic parity（人口统计均衡）量取职业前缀下不同性别组的平均 log-perplexity（对数困惑度）差。均值约 0.37；bodybuilder、plumber 对男性有较强关联。均值±2标准差是该分析使用的显示范围，不能自动看成每个职业都有严格统计覆盖保证。

原规模的数据和计算、封闭/部分公开训练组件、高分辨率成本、多语覆盖不均、输出幻觉与训练数据偏差，都会限制复现和使用结论。论文将一般限制指向 PaLI-X；这里不因为模型更小就省略这些问题。

## 9. 掌握顺序与 Paper ↔ Code

### 必须会

- 区分 SigLIP 双塔预训练、PaLI 图文编码与 UL2 生成、任务微调。
- 跟踪 $[B,C]→[B,B]$ 配对分数；会算 $B=2$ 的标签与损失。
- 理解未池化视觉 token 与全局匹配向量的区别。
- 根据具体指标、数据与训练协议理解表格，保留反例。

### 第二遍再学

- Flax 参数树、JAX 随机键/自动微分、Optax 状态。
- 高分辨率课程、离散掩码编码、多帧序列。
- LiT 组件评估与完整生成模型评估的差别。

### 可暂缓的工程细节

多设备分片、编译缓存、云端检查点存储、完整训练数据管线。暂缓不代表这些对大规模训练不重要。
