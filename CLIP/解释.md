# CLIP：论文与源码解释

本文直接对应当前文件夹中的 OpenAI 官方 CLIP 仓库。请一边打开本文件，一边打开 [`clip/clip.py`](clip/clip.py)、[`clip/simple_tokenizer.py`](clip/simple_tokenizer.py)、[`clip/model.py`](clip/model.py)。这三个**实际运行的源码文件**已加中文行内注释；这里解释为什么这样写、数据怎样在文件之间传递，以及论文与代码哪里能对应。

## 1. 先确认我们在读什么

- 论文：*Learning Transferable Visual Models From Natural Language Supervision*，本地原文在 [`../papers/CLIP.pdf`](../papers/CLIP.pdf)，PDF 首页标有 arXiv:2103.00020v1、2021 年 2 月 26 日。
- 代码：本地 OpenAI/CLIP 仓库，当前 Git 基础提交为 `d05afc436d78f1c48dc0dbf8e5980a9d471f35f6`。本次对 `clip/` 下 Python 文件添加的是解释性注释，算法语句保持原样。
- CLIP = **Contrastive Language-Image Pre-Training**，逐词是“对比式／语言－图像／预训练”。它接收一张图片和若干文字描述，学会判断哪段文字更匹配图片。
- 本文默认你只熟悉基础 Python。看到形状 `[B,C,H,W]` 时，方括号表示张量各轴的长度，不是 Python 列表：`B` 是一次输入的图片数，`C` 是颜色通道数，`H/W` 是高/宽。

## 2. 论文先解决什么问题？【必须会】

常见图片分类模型只认训练时预先规定的类别。例如训练集只有“猫／狗”，要新增“飞机”通常要收集带“飞机”标签的图片并调整分类器。CLIP 改用互相配对的图片和自然语言文字作为监督信号。文字能灵活描述类别，因此推理时可以临时写出新的候选描述，例如 `a photo of a dog`，不必为每种新类别重新训练一个固定输出头。

论文贡献可以先记成三步：

1. 用大规模图片－文字配对数据学习图像编码器与文字编码器。论文称训练数据 WIT（WebImageText），规模约四亿对；数据本身**不在此仓库**。
2. 在一个 batch 内让正确图片－文字配对的相似度高、错误配对的相似度低。这个训练任务比逐词生成完整描述简单。
3. 把候选类别写成文字，用文字编码器临时产生“类别向量”，然后用图片向量与它们比较，实现零样本分类（zero-shot：目标数据集的标注样本没有参与该任务的训练）。

这里的“零样本”不等于模型没见过任何图片／文字；它已在大规模图文数据上预训练。论文报告了跨数据集迁移效果，也指出复杂计数、卫星影像、交通标志等任务仍有明显弱点。

## 3. 论文图 1：先训练，再使用【必须会】

论文第 2 页的 Figure 1 有三个阶段，按箭头从左往右读：

| 阶段 | 输入 | 哪些部分有参数 | 输出和作用 | 本仓库对应 |
| --- | --- | --- | --- | --- |
| (1) 对比预训练 | 同一个 batch 中 `N` 张图片和各自配对的 `N` 段文字 | 图像编码器、文字编码器、投影矩阵、相似度尺度 | `N×N` 分数矩阵，对角线是真配对 | 编码器与矩阵运算见 `clip/model.py`；完整训练循环与损失**未找到** |
| (2) 构造候选类别 | 如 `dog`、`car`，填进 `a photo of a {label}` | 已训练好的文字编码器；此时通常不更新参数 | 每个类别得到一个文字向量 | `clip.tokenize`、`model.encode_text`；prompt 列表由调用者编写 |
| (3) 零样本预测 | 图片向量 + 类别文字向量 | 已训练好的图像／文字编码器 | 各类别分数，经 `softmax` 可形成候选类上的概率 | `model(image, text)` 与 README 的示例 |

图中 `I1·T2` 的点号是**向量点积**，意思是“第 1 张图片向量与第 2 段文字向量的匹配程度”，不是 Python 成员访问的点号。训练时希望 `I1·T1` 等主对角线较大。推理时可以有 1 张图片、3 段候选文字，矩阵就是 `[1,3]`；只有同批配对训练才要求图片数和文字数都等于 `N`。

## 4. 图 3 和核心公式：每个符号是什么意思【必须会】

论文第 5 页 Figure 3 给了 NumPy 风格伪代码。用本仓库的写法重述：

```text
I = 图像输入，形状 [N, 3, H, W]
T = 文字 token 整数表，形状 [N, 77]
I_f = 图像编码器输出，形状 [N, D]
T_f = 文字编码器输出，形状 [N, D]
I_e = I_f / ||I_f||₂ ，形状 [N, D]
T_e = T_f / ||T_f||₂ ，形状 [N, D]
S = exp(logit_scale) × (I_e @ T_e.T)，形状 [N, N]
L = (CE(S, [0,1,...,N−1]) + CE(S.T, [0,1,...,N−1])) / 2
```

逐一解释：`N` 是训练 batch 的配对数；`D` 是图像和文字共同的向量维度，具体数值取决于模型版本；`||·||₂` 是向量二范数，即各分量平方求和再开方；`@` 是矩阵乘法；`.T` 交换矩阵两个轴；`S[i,j]` 是第 `i` 张图片与第 `j` 段文字的分数；`CE` 是交叉熵（cross entropy），让正确类别的分数占更大比例。`logit_scale` 是**对数尺度参数**，做 `exp` 后成为正数，乘在余弦相似度上。它与论文温度 `τ` 的关系可理解为尺度约为 `1/τ`。

为什么要除范数？假设图片向量为 `(3,4)`、文字向量为 `(0,5)`，它们的长度都为 5，归一化后是 `(0.6,0.8)` 与 `(0,1)`，点积 `0.8`。这样比较主要反映**方向**，避免只因向量长度大就获得高分。两个向量的余弦相似度在 `−1` 到 `1` 之间。

再用 `N=2` 看标签为什么是 `[0,1]`：

```text
               文字 0    文字 1
图片 0          2.0       0.1
图片 1          0.2       1.5
```

第 0 行的正确位置是第 0 列；第 1 行的正确位置是第 1 列。因此图片找文字的标签是 `[0,1]`。转置后，文字找图片的标签仍是 `[0,1]`。两方向交叉熵取平均就是“对称”损失。数值只是教学例子，并非论文实验结果。

**代码对应与缺口：** [`CLIP.forward`](clip/model.py) 实现编码、归一化、`logit_scale.exp()`、`@`、转置并返回两个分数矩阵；它**没有**在函数内调用交叉熵。此仓库里也未找到官方发布的完整预训练脚本。工作区另有 [`../小型复现/训练CLIP小样本.py`](../小型复现/训练CLIP小样本.py) 教学训练脚本，不能把它当成论文原始训练程序。

## 5. 从 README 的示例一路走到源码【必须会】

按照实际执行顺序阅读，先看 [`README.md`](README.md) 的 Usage，然后沿着这条链走：

```text
import clip
  → clip/__init__.py 将 clip.py 的公开函数放到包顶层
clip.load("ViT-B/32")
  → 查 _MODELS 权重 URL → 下载或读本地权重 → build_model(state_dict)
  → 返回 (model, preprocess)
preprocess(PIL 图片)
  → Resize → CenterCrop → RGB → ToTensor → Normalize
clip.tokenize(文字列表)
  → SimpleTokenizer.encode → 加起始/结束 token → 补足到 77 个位置
model(image, text)
  → encode_image / encode_text → 归一化 → 相似度矩阵
softmax / argmax
  → 调用者解释各候选文字的分数
```

`import clip` 的 `import` 是执行模块载入；[`clip/__init__.py`](clip/__init__.py) 里的 `from .clip import *` 把 `load`、`tokenize` 等公开名字导出。`clip.load` 中的点才是“访问模块属性”。`model, preprocess = ...` 是 Python 拆包：右边返回两个对象，左边分别接住；`model` 是网络，`preprocess` 是图片处理函数。

### 5.1 图片进来后为什么要预处理？

[`_transform`](clip/clip.py) 返回多个 `torchvision.transforms` 组成的 `Compose`。`Resize` 调整尺寸，`CenterCrop` 取中心区域，`_convert_image_to_rgb` 保证三色通道，`ToTensor` 把 PIL 图片变成 `[3,H,W]` 的浮点张量，`Normalize` 逐通道减均值、除标准差。`preprocess(...).unsqueeze(0)` 在最前面加 batch 轴，让 `[3,H,W]` 变 `[1,3,H,W]`。`.to(device)` 把张量放到 CPU 或 GPU，与模型所在设备一致。原 README 的这条预处理是**推理**流程；论文中的训练图片增广并不由这个 `_transform` 完整表达。

### 5.2 文字为什么先变整数？

网络层无法直接把 Python 字符串当张量计算。[`simple_tokenizer.py`](clip/simple_tokenizer.py) 实现 BPE（byte pair encoding，字节对编码）：先清洗字符串，再按规则分成文本片段，把片段变为字节表示，按合并表逐步组合，最后查词表得到 token 整数编号。`encoder` 是“文本片段 → 整数”的字典；`decoder` 是反向字典；`cache` 保存已经算过的 BPE 分词结果，避免重复工作。

[`clip.tokenize`](clip/clip.py) 在编码序列前后加起始／结束标记，放进形状 `[B,77]` 的整数张量。`B` 在这里是文字条数，77 是代码默认的总位置数，包含两个特殊标记和必要的补齐位。论文第 5 页写“最大序列长度限制为 76”，而公开推理代码默认 `context_length=77`；两处数字及其计数口径不能擅自视为相同，实际分析以当前源码创建的 `[B,77]` 张量为准。超长文本在 `truncate=False` 默认设置下报错；若 `truncate=True`，会截断并保证末位是结束标记。

### 5.3 `clip.load` 为什么较长？

[`clip.py`](clip/clip.py) 里的 `_MODELS` 只是“名字 → 权重地址”字典；`_download` 用 SHA256 验证文件；`load` 还兼容 TorchScript/JIT 权重与普通权重，处理设备 CPU/GPU 与精度，然后调用 [`build_model`](clip/model.py) 从权重键和张量形状反推出模型构造参数。`state_dict` 是“参数名 → 参数张量”的字典，并非一个能直接运行的模型对象。JIT（just-in-time）相关分支属于较深的部署工程细节，第一次读可以先走 `jit=False` 分支。

## 6. 模型内部：两条支路怎么变成同一种向量【必须会】

### 6.1 图片编码器：ViT 分支

以 `ViT-B/32` 的 `224×224` 输入为例，`patch_size=32`，所以一边有 `224/32=7` 块，共 `7×7=49` 块。[`VisionTransformer.forward`](clip/model.py) 用 `conv1` 把图片变成 patch 特征；随后展平空间维，把每个 patch 放成序列元素；前面拼接一个汇总用的 class token，因此长度 `49+1=50`；再加位置向量，让模型知道块原本在哪里。`ln_pre` 是进入 Transformer 前的层归一化，`ln_post` 是末端归一化。取第 0 个汇总 token，经线性矩阵 `proj` 得到共同的图文维度。张量跟踪：

```text
x: [B,3,224,224]
conv1 后: [B,W,7,7]       W = 视觉 Transformer 内部宽度
展平并换轴后: [B,49,W]
加 class token 后: [B,50,W]
Transformer 内部: [50,B,W]  因为该实现的 MultiheadAttention 采用序列优先布局
取汇总 token、投影后: [B,D]
```

`B` 是图片数量，`W` 是中间特征宽度，`D` 是最终共同向量维度。`permute` 只改轴顺序，`reshape` 改视图／形状时可能涉及内存安排，`expand` 可以用广播视图扩展 batch 轴，这些操作都不是新增训练样本。

### 6.2 图片编码器：ResNet 分支

同一 `CLIP` 类也可按权重选择 [`ModifiedResNet`](clip/model.py)。`Bottleneck` 是残差块；旁路 `identity` 与卷积分支 `out` 相加，以便信息和梯度更容易经过深层网络。这个分支相较常规 ResNet 修改了前端卷积、降采样方式和末端池化。[`AttentionPool2d`](clip/model.py) 先把空间特征放成序列，再让一个汇总位置通过 Q/K/V 多头注意力读取各位置，而不是只做普通全局平均。`Q` 是 query（要找什么），`K` 是 key（匹配索引），`V` 是 value（被汇集的内容）。两种视觉骨干最终都要输出 `[B,D]`，才能与文本向量比较。

### 6.3 文本编码器

[`CLIP.encode_text`](clip/model.py) 接收整数张量 `[B,77]`；`token_embedding` 像查表一样把每个整数映射到宽度为 `W_t` 的向量，因此变 `[B,77,W_t]`。加 `positional_embedding` 告诉模型 token 所在位置；经过 Transformer 后，用 EOT（end of text，文本结束）位置的输出代表整句，再做 `ln_final` 和 `text_projection`，得到 `[B,D]`。

源码用 `text.argmax(dim=-1)` 找 EOT：这里依赖该词表里结束 token 的编号大于一般 token 编号。`argmax` 本意只是找最大整数所在位置；它不是通用的“查找结束 token”API。若换了词表或自行改 token 规则，应重新检查这一约定。

### 6.4 注意力、因果遮罩和一些常见 Python 写法

[`ResidualAttentionBlock`](clip/model.py) 包含注意力和 MLP（multi-layer perceptron，多层感知机）两段，每段都有残差相加。注意力层可以让一个位置参考其他位置；文本分支的 `build_attention_mask` 把未来位置遮住，称 causal mask（因果遮罩）。图像分支不使用同样的文本遮罩。

`class X(nn.Module)` 表示定义继承 PyTorch `nn.Module` 的类；`__init__` 在创建对象时登记子层与参数；`super().__init__()` 先初始化父类；`forward` 定义输入如何变输出。写 `model(x)` 时 PyTorch 调用 `nn.Module.__call__`，再进入 `forward`，因此不要在普通用法中直接调用 `model.forward(x)`。`self.xxx` 保存到实例上，后续方法能再次取到；`nn.Parameter` 明确标记可训练张量；`nn.Sequential` 按登记次序依次调用子层。更具体的变量名、库函数、每步形状都写在对应源码行旁。

## 7. 一次零样本分类怎么算？【必须会】

假设只有 1 张图片和 `cat/dog/car` 三个类别，先构造三句文字，例如 `a photo of a cat` 等；输入图片形状 `[1,3,H,W]`、token 形状 `[3,77]`。`model(image,text)` 返回 `logits_per_image` 形状 `[1,3]`，以及 `logits_per_text` 形状 `[3,1]`。三个图片方向分数分别对应三句话。README 的 `softmax(dim=-1)` 把这一行分数变为和为 1 的相对比例。**这只是给定三个候选文字之间的归一化结果**；漏掉真正类别或改变文字模板，比例也会改变。

论文 Figure 1 的候选文字向量可以预先算好并缓存，再给很多图片重复使用。论文第 7 页指出 prompt（提示语模板）会影响结果：单个 `a photo of a {label}` 模板和多模板平均都可以提升特定评测表现。模板文字本身不是由本仓库 `model.py` 自动发明的，需调用者提供。

## 8. 实验怎样读，哪些结论不能扩大【建议会】

论文 Table 1（PDF 第 7 页）比较的是三个数据集上的**零样本图片分类准确率，越高越好**。ImageNet 上 Visual N-Grams 为 `11.5%`，CLIP 为 `76.2%`，差 `64.7` 个百分点；aYahoo 上 `72.4% → 98.4%`；SUN 上 `23.0% → 58.5%`。这里的 `76.2%` 来自论文报告的最佳 CLIP 设置，不能从这些数字推断本地 `ViT-B/32` 或教学小模型也达到它。论文明确提醒：两系统在数据规模、模型、计算量、年代等方面不受控，所以 Table 1 不能单独证明“只替换损失函数就带来全部提升”。

论文 Figure 2 比较训练效率：从逐词生成描述改为词袋预测，再改为对比目标，零样本 ImageNet 表现随所处理图片数量更快增长。曲线是在对应实验设置下的比较，不代表任何小数据集都能按同样倍数提高。论文 Figure 5 则展示 27 个数据集上零样本 CLIP 与一个监督线性探针基线各有胜负；不能把“零样本”理解为所有任务都更强。

论文的局限包括训练所需数据和算力很大、某些专门任务表现弱、不同 prompt 影响评测，以及网络数据与人为类别定义可能带来偏差。尤其在医疗等场景，论文中的零样本准确率不能直接当成可靠部署保证。
