# ViLT：论文与源码解释

这份说明对应当前 `ViLT` 目录中的**实际运行代码**。第一次阅读建议同时打开 [`run.py`](run.py)、[`vilt/config.py`](vilt/config.py)、[`vilt/datasets/base_dataset.py`](vilt/datasets/base_dataset.py)、[`vilt/modules/vision_transformer.py`](vilt/modules/vision_transformer.py)、[`vilt/modules/vilt_module.py`](vilt/modules/vilt_module.py) 和 [`vilt/modules/objectives.py`](vilt/modules/objectives.py)。较难语句的中文解释已写进这些源码文件；本文把论文原理、变量来源、张量形状和函数调用串起来。

## 1. 论文与仓库边界

- 论文：*ViLT: Vision-and-Language Transformer Without Convolution or Region Supervision*。本地原文 [`../papers/ViLT.pdf`](../papers/ViLT.pdf) 首页标为 arXiv:2102.03334v2（2021-06-10），发表于 ICML 2021。
- 代码：论文作者提供的 [`README.md`](README.md) 所指仓库，本地 Git 基础提交 `762fd3975c180db6fc88f577cf39549983fa373a`。已有少量中文注释；本次继续往实际源码添加解释，不改算法语句。
- ViLT = **Vision-and-Language Transformer**，即“视觉与语言 Transformer”；VLP = **vision-and-language pre-training**，即视觉语言预训练。
- 本文解释预训练主路径 **MLM + ITM + WPA**，并说明 VQA、NLVR2、检索如何复用模型。论文中的 MPP（遮图像 patch 预测）是消融实验，不能误写为主预训练目标。

## 2. 它要解决的问题【必须会】

早期图文模型常在图像前面接一个目标检测器或很深的 CNN。检测器先提出候选框、做区域池化与筛选，最后才把“物体区域特征”给图文 Transformer。这增加了数据准备和推理的耗时；预先抽好的区域特征也限制了后续视觉表示能改变多少。

ViLT 的思路是：直接把原图切成小块（patch），用很浅的投影把每块变成向量；把这些向量和文字 token 向量拼成一条序列，让同一批 Transformer Block 同时处理图和文。模型计算更多集中在**图文交互**，而不是前置视觉特征提取。论文图 2 把这归为 `MI > VE = TE`：`MI` 是 modality interaction（模态交互），`VE` 是 visual embedding（视觉嵌入），`TE` 是 textual embedding（文本嵌入）；图块的相对高度表示计算量概念，不是严格的参数个数公式。

**容易误解的标题：** [`PatchEmbed`](vilt/modules/vision_transformer.py) 确实使用了 `nn.Conv2d`，但它的卷积核大小和步长都等于 patch 大小。每个不重叠的 patch 被映射成一个向量，数学上相当于“把 patch 展平后做一次线性投影”。论文说 *Without Convolution*，重点是没有单独的**深 CNN 骨干或检测器**；不是代码中禁止出现 `Conv2d` 算子。

ViLT 与 CLIP 的关键区别：CLIP 先分别算**整图向量**和**整句向量**，最终做点积；ViLT 较早把**图像局部 patch**和**文字局部 token**放进同一条序列，注意力层可在它们之间交换信息。二者原论文任务侧重也不同，不应只凭结构推断哪一个在所有数据集更强。

## 3. 图 3 与论文公式（1）至（6）【必须会】

读图 3 时，从下往上看：左边文字变 token 向量，右边图片变 patch 向量；各自加位置和模态类型信息；中间拼接后进入共同 Transformer；顶部的 MLM、ITM、WPA 是不同训练目标。文字/图像初始嵌入、位置表、类型表、Transformer 和任务头都有可训练参数；拼接、切片、mask、softmax 等操作本身没有独立参数。

为防论文把 `H` 同时用作图片高度与隐藏宽度造成混淆，下文写：`B`=批量，`T`=文字 token 数，`P`=**选中图像 patch 数（不含图像 CLS）**，`D`=隐藏宽度，`C`=颜色通道数，`h/w`=图片像素高宽，`s`=patch 边长，`A`=注意力头数。主 ViLT-B/32 中 `D=768`、`s=32`、`A=12`、Block 数 12；运行时 `P` 会受图像尺寸、有效区域和 `max_image_len` 影响。

论文式（1）`t̄ = [t_class; t₁T; …; t_LT] + T_pos`：文字先通过词表嵌入矩阵 `T` 变向量，前面有一个文字分类标记，再逐位置加文本位置向量。`L` 是正文 token 数；分号是按序列轴拼接。代码中 [`BertEmbeddings`](vilt/modules/vilt_module.py) 负责词 ID、位置等基础文字嵌入，输入整数 `[B,T]`，输出浮点 `[B,T,D]`。它只是 BERT 风格**嵌入层**，不是导入一整套 BERT Transformer 权重。

论文式（2）`v̄ = [v_class; v₁V; …; v_NV] + V_pos`：每块图片像素映射到 `D` 维，图像 CLS 在最前面，再加图像位置向量。若图片恰好 `384×640`，每边 patch `32`，原始网格为 `(384/32)×(640/32)=12×20=240` 块；预训练命名配置常令 `max_image_len=200`，因此实际抽取后最多 200 块，再加 1 个图像 CLS。代码在 [`PatchEmbed.forward`](vilt/modules/vision_transformer.py) 和 [`VisionTransformer.visual_embed`](vilt/modules/vision_transformer.py)。

论文式（3）`z₀ = [t̄ + t_type ; v̄ + v_type]`：加两个**不同可训练类型向量**，告诉共享 Transformer 哪些位置是文字、哪些是图像，再沿 token 轴拼接。代码在 [`ViLTransformerSS.infer`](vilt/modules/vilt_module.py) 中的 `token_type_embeddings`、`torch.cat(..., dim=1)`。例如 `B=2,T=40,P=200,D=768`：文字 `[2,40,768]`、图像含 CLS `[2,201,768]`，拼后 `[2,241,768]`。`dim=1` 是位置数轴，不能误写成特征宽度轴。

论文式（4）`ẑ_d = MSA(LN(z_{d−1})) + z_{d−1}`：`d` 表示第几层；`LN` 是 layer normalization（层归一化）；`MSA` 是 multi-head self-attention（多头自注意力）；`+ z_{d−1}` 是残差连接。论文式（5）`z_d = MLP(LN(ẑ_d)) + ẑ_d`：再经多层感知机与第二个残差。代码在 [`Block.forward`](vilt/modules/vision_transformer.py)。图文都在 `z` 中，所以文字 query 可读取图像 key/value。

论文式（6）`p = tanh(z_D^0 W_pool)`：`z_D^0` 是第 `D` 层后序列第 0 位的特征（**这里的上标 0 是位置，不是幂**）；`W_pool` 是可训练矩阵；`tanh` 是逐元素激活，得到整对图文向量 `p`，形状 `[B,768]`。代码在 [`heads.Pooler`](vilt/modules/heads.py)。注意论文也用 `D` 表示层数；本文用“Block 数”说深度，`D` 只表示向量宽度。

**一个小数值例子：** 假设文字有 2 个位置、图片有 3 个位置（包括图像 CLS），拼接后的序列长度就是 `2+3=5`；每个注意力头先形成 `5×5` 分数表。第 1 行第 4 列表示“第 1 个文字 token 要从第 4 个序列位置读取多少信息”；如果第 4 位是图片 patch，它就是跨模态注意力。`softmax` 将每行变成总和为 1 的读取权重。真实模型每个 batch 有 12 个头并重复 12 个 Block，此例只为看懂矩阵方向。

## 4. 从命令到 batch：按实际调用顺序走【必须会】

```text
TRAIN.md 的 python run.py with ...
  → run.py 中 @ex.automain 的 main(_config)
  → vilt/config.py 默认配置 + 命名配置 + 命令行覆盖
  → MTDataModule / BaseDataModule 建 Dataset、BertTokenizer、MLM collator
  → BaseDataset.get_suite 取一条真图文与所需负图
  → BaseDataset.collate 把多条样本补齐并拼成 batch 字典
  → ViLTransformerSS.training_step → forward → objectives.compute_*
  → infer → 文字嵌入 + visual_embed → 共享 Transformer
  → 返回损失；Lightning 负责反向传播与优化器步骤
```

[`TRAIN.md`](TRAIN.md) 示例中的 `python` 是解释器，`run.py` 是入口脚本，`with` 是 Sacred 用来传配置覆盖项的语法，**不是** Python 文件里的 `with open(...)`。`task_mlm_itm` 是 [`config.py`](vilt/config.py) 中的命名配置，开启 `itm` 与 `mlm`，并把 `max_image_len` 设为 200；`whole_word_masking=True` 则让同一个词拆出的多个子词一起被遮。`per_gpu_batchsize` 是一张 GPU 一次能装的 microbatch；`batch_size` 是经多 GPU 与梯度累积后希望达到的全局 batch。默认配置把 `per_gpu_batchsize` 留为 0，因此不能不填就直接照默认值训练。

[`run.py`](run.py) 的 `pl.Trainer.fit` 会触发训练循环。`pl.LightningModule` 是类继承关系；子类按规定定义 `training_step`、`configure_optimizers` 等方法，Trainer 才知道何时求损失、何时更新权重。`self` 是当前模型对象；`self.xxx` 表示保存在对象上的参数或子模块。`model(batch)` 会经 PyTorch `nn.Module.__call__` 进入 `forward(batch)`。

[`BaseDataset`](vilt/datasets/base_dataset.py) 从 `.arrow` 文件读图片字节和文字，再用 PIL 解码图片、`BertTokenizer` 转文字整数 ID。`collate` 把不同大小的图片补到本批最大高宽，并保留多视图列表，因此在 `infer` 中 `batch['image'][0]` 是**第 0 个视图对应的整批图片**，并非第 0 张图片。数据流常见键：

| batch 键 | 类型／形状 | 来源与作用 |
| --- | --- | --- |
| `image` | 图片视图列表；其中元素 `[B,3,h,w]` | 正图，模型取列表 `[0]` |
| `false_image_0` | 同结构图片视图列表 | 随机负图，ITM 用来替换部分正图 |
| `text_ids` | 整数 `[B,T]` | 原文字 token 编号，普通推理用 |
| `text_ids_mlm` | 整数 `[B,T]` | 依遮词规则替换后的模型输入 |
| `text_labels_mlm` | 整数 `[B,T]` | MLM 正确答案，其他位置为 `-100` |
| `text_masks` | 整数/布尔 `[B,T]` | 有效 token 为 1，padding 为 0 |

变量名中的 `ids` 是整数编号，`embeds` 是连续浮点向量，`feats` 是经过共享 Transformer 后的融合特征；`labels` 是监督答案，`masks` 表示位置是否有效。它们都不是可以互换的名字。

## 5. `infer`：最关键的函数逐段解释【必须会】

入口 [`ViLTransformerSS.infer`](vilt/modules/vilt_module.py) 的 `batch` 是上述字典；`mask_text=True` 选择键名带 `_mlm` 的文字；`mask_image=True` 要求视觉侧准备 MPP 遮块；`image_token_type_idx=1/2` 用于普通图或 NLVR2 第二张图。`image_embeds/image_masks` 可选传入已算好的视觉 token。虽然名字叫 `infer`，训练时也会调用它，默认不会自动关闭梯度。

1. `imgkey` 是 image key（图像键名）字符串。普通任务取 `image`；NLVR2 根据索引取 `image_0` 或 `image_1`。`f'image_{...}'` 是 Python 格式字符串，把数字插入键名。
2. `text_ids` 为 `[B,T]` 整数；`self.text_embeddings(text_ids)` 变 `[B,T,D]`。`text_labels` 只是随返回字典传给损失函数，不进入嵌入层。
3. `self.transformer.visual_embed(img, max_image_len=..., mask_it=...)` 将 `[B,3,h,w]` 变为 `image_embeds [B,P+1,D]` 与 `image_masks [B,P+1]`，同时返回 patch 坐标及可选 MPP 标签。`patch_index` 是 patch 在原网格中的行列索引，并非预测出的物体框。
4. `nn.Embedding(2,D)` 的第 0 行是文字类型向量、第 1 行是图像类型向量。`torch.zeros_like(text_masks)` 造文字类型索引；`torch.full_like(image_masks, image_token_type_idx)` 造图像类型索引；相加后维度不变。NLVR2 会把表扩为 3 行，第二图使用索引 2。
5. `co_embeds = torch.cat([...], dim=1)` 得到 `[B,T+P+1,D]`；`co_masks` 用相同顺序拼出 `[B,T+P+1]`。`co` 是 combined（组合）的缩写。
6. `for i, blk in enumerate(self.transformer.blocks)` 中 `i` 是层号，`blk` 是这一层对象，`x` 是不断更新的融合序列。`_attn` 是注意力矩阵，前导下划线表示当前函数拿到但不继续使用。
7. 最后 `x[:, :T]` 取文字位置、`x[:, T:]` 取图像位置；此时两边都已吸收对方的信息。`text_feats` 是 `[B,T,D]`，`image_feats` 是 `[B,P+1,D]`，`cls_feats=self.pooler(x)` 是 `[B,D]`。`raw_cls_feats=x[:,0]` 尚未过 Pooler，数值不等于 `cls_feats`。

**注意力的 `mask` 和 MLM 的“遮词”不是一件事。** `co_masks` 主要让注意力忽略批内补齐的空位置；`text_ids_mlm` 把部分真实词换成 `[MASK]` 让模型预测。两个机制都用中文“遮”，但输入、位置和目的不同。

## 6. `visual_embed`：为什么代码比“切方块”长【建议会】

[`PatchEmbed.proj`](vilt/modules/vision_transformer.py) 一次将每个 `32×32×3` patch 投到 768 维。输入 `[B,3,h,w]` 经过核大小与步长都为 32 的卷积，变 `[B,768,h/32,w/32]`（高宽可整除时）。例如 `384×640` 变 `[B,768,12,20]`。接下来 [`visual_embed`](vilt/modules/vision_transformer.py) 还要做四件事：

1. **识别补齐区。** 批内图片先补到相同 `h,w`，零值边框不应当成真实 patch。`x_mask` 逐图标出有效网格，再根据它求 `x_h/x_w`。这里 `x_h/x_w` 是**patch 网格尺寸**，不是原始像素高宽。
2. **插值位置表。** ViT 预训练位置表对应固定正方形网格，但输入图片可能是长方形。把位置表还原成二维网格、用 `F.interpolate` 调整到该图有效高宽，再 pad 成批内共同尺寸。`pos_embed` 是位置向量，`patch_index` 则是离散行列坐标，二者作用不同。
3. **抽取/补齐 patch。** `max_image_len` 决定每张图送入的 patch 数。有效 patch 多就随机抽；不足就从补齐位置补足，同时 mask 保持 0。`select` 是本批被选的 `[样本行号, patch 序号]` 二列索引，随后同步选特征、位置和有效标记。
4. **加图像 CLS。** `cls_token` 在 patch 序列前加一格；位置表和有效 mask 也要相应多加一格，最后返回 `image_embeds`、`image_masks`、`patch_index`、可选标签。

这些步骤解释了为什么图像 token 数不能简单永远写成 `h*w/32²+1`。配置中 `max_image_len=-1` 是“按有效 patch 上限”路径；预训练命名配置通常改成 200。`max_image_len` 是 patch 数上限，`image_size` 是像素尺寸，两个变量不能混淆。还有一个源码细节：`mask_tokens` 的原英文文档字符串写了“80% mask、10% random、10% original”，但当前函数实际只显式进行 80% 的 mask 替换，其余被选 patch 保持原样，未找到随机特征替换语句；读实现时以可执行语句为准。

## 7. 三个主要损失：标签从哪里来【必须会】

### 7.1 MLM：masked language modeling

[`BaseDataModule`](vilt/datamodules/datamodule_base.py) 创建 `DataCollatorForWholeWordMask` 或 `DataCollatorForLanguageModeling`；配置 `mlm_prob=0.15`。`BaseDataset.collate` 得到遮过词的 `text_ids_mlm` 和答案 `text_labels_mlm`。[`compute_mlm`](vilt/modules/objectives.py) 让 `infer(mask_text=True)` 输出融合后的 `text_feats [B,T,D]`；`MLMHead` 输出 `mlm_logits [B,T,V]`，其中 `V` 是词表大小。交叉熵前把前两轴展平成 `[B*T,V]` 与 `[B*T]`；`ignore_index=-100` 跳过不需要预测的位置。

数值例：某位置真实词 ID 为 7，遮词后输入 `[MASK]` 的 ID；模型输出词表所有词的分数。交叉熵希望第 7 项分数相对其他项提高。模型可利用同句其他词和图片 patch 信息；整词遮挡减少它只靠同一个词剩余子词猜答案的机会。

### 7.2 ITM：image-text matching

[`compute_itm_wpa`](vilt/modules/objectives.py) 给约一半样本保留真图片，另一半换为 `false_image_0`，并产生 `itm_labels`：1 表示真配对，0 表示假配对。经融合模型和 `ITMHead` 后得到 `[B,2]` logits，再用 `F.cross_entropy` 做二分类。`torch.randperm` 只打乱标签次序，不会生成负图；负图来自 Dataset。`batch = {k:v for ...}` 是字典的浅复制，随后只把本地 `batch['image']` 换成混合正负图片。

### 7.3 WPA：word-patch alignment

WPA = 词与 patch 对齐，附加在 ITM 上。`cost_matrix_cosine` 把每个真实词向量与每个真实 patch 向量比较，得到 `cost [B,T,P+1]`；公式是 `1 − cosine_similarity`，所以越相似成本越小。去掉 padding、文字 CLS/SEP、图像 CLS 后，`ipot` 用最优传输近似算法分配词－patch 匹配权重 `T_transport`。源码把这个权重局部变量也命名为 `T`，**它不是上文的“文字长度 T”**。加权成本 `distance` 对真配对希望低，对假配对希望高，故 `ot_loss = (正例距离和 − 负例距离和)/B`，最后乘 `0.1`。论文第 5 页给 IPOT 参数 `β=0.5`、迭代 50 次；代码中的调用正是 `0.5, 50, 1`。

最优传输矩阵是从模型特征和约束中算出的软对齐，不是人工标注的逐词目标框。`torch.no_grad()` 让 IPOT 的迭代本身不建反向图，后面的带梯度成本矩阵仍参与损失。读 WPA 的第一遍只需掌握成本矩阵、padding mask、正负距离方向；`sigma/delta/Q` 的迭代可第二遍再看。

[`training_step`](vilt/modules/vilt_module.py) 将返回字典中**键名含 `loss`** 的数值加总，所以 `itm_loss`、`itm_wpa_loss` 与 `mlm_loss` 都会进入总损失。代码里的 `loss_names` 主要用于选择/创建任务，不能简单想成每个损失都自动按字典数值相乘。

## 8. 下游任务和论文实验【建议会】

- **VQAv2：** 图片 + 问题 → 融合 `cls_feats` → `vqa_classifier` 输出候选答案分数。[`compute_vqa`](vilt/modules/objectives.py) 给可能的多个答案建立软目标，使用 `binary_cross_entropy_with_logits`；不能误以为每题只能有一个 one-hot 答案。
- **NLVR2：** 同一句话分别配两张图，各做一次 `infer`；把两个 `[B,D]` 融合向量沿特征轴拼成 `[B,2D]` 再二分类。`image_token_type_idx=1/2` 让第二图可有不同类型向量。
- **图文检索 IR/TR：** 基于融合图文对的匹配分数进行排序；要为多对候选分别运行融合模型。它与 CLIP 可分别缓存整图/整句向量再矩阵乘的推理结构不同。

论文 Figure 1 给三类视觉输入路径与大致延迟，并注明比较的任务分数依次为 NLVR2 test-P accuracy、Flickr30K 文本检索 R@1、图像检索 R@1。例如图 1 的 ViLT-B/32 为 `76.1 / 83.5 / 64.4`，而区域特征的 UNITER-Base 为 `75.8 / 85.9 / 72.5`：ViLT 在第一项略高、后两项较低，不能说所有任务指标都领先。论文 Table 6 在指定输入长度与硬件测得 ViLT 约 `15 ms`、Pixel-BERT-R50 约 `60 ms`、部分区域模型约 `900 ms`；这些是论文条件下的延迟，不代表你电脑上也会得到同一数字。`R@1`（recall at 1）表示正确匹配进入排名第一的比例，越高越好；`accuracy` 为分类正确比例，越高越好。

论文 Table 2 主任务结果显示，ViLT-B/32 在 VQAv2 test-dev 比一些重视觉模型低，而速度更快。Table 5 消融中，整词遮挡、训练更久、适用的图片增强带来提升；可选 MPP 没有稳定改善，因而论文主预训练选择 MLM + ITM。比较不同模型时要同时看预训练数据量、模型尺寸、输入分辨率、延迟测量条件和是否加数据增强，不能把不同实验的数字看成只改变了一个模块。
