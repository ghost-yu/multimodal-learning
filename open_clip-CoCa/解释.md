# CoCa 论文与代码解释

## 1. 阅读对象与边界

论文是 **CoCa: Contrastive Captioners are Image-Text Foundation Models**，本地 PDF 为 arXiv:2205.01917v2，2022 年 6 月 14 日版本，19 页。CoCa 是 Contrastive Captioner 的缩写：Contrastive 表示“把正确图文配对拉近”，Captioner 表示“根据图像生成描述”。[原论文](原论文.pdf) · [中文论文](中文论文.pdf) · [双语论文](双语论文.pdf)。

本地代码是 **OpenCLIP 的 CoCa 实现**，仓库 HEAD 为 `2d5346092bf447ff73a782d372a8e018fb269ffc`。论文实际采用 Lingvo 与 GSPMD。本地 PyTorch 实现可以帮助理解方法，但不能作为原作者训练代码完全一致的证明。尤其本地 README 明确列出后续改动：`coca2_*` 配置、有效位掩码、融合 caption 损失、modern text tower、训练 Task 等。阅读下面内容时，以实际文件为准，不把这些扩展倒推成原论文贡献。

本文假定你只了解 Python 基本变量、列表和函数。源码旁的中文注释解释局部操作，本文解释为什么需要这些操作。先读整体数据流，再打开函数；只看每一行会失去“这段代码正在解决什么问题”的主线。

## 3. 为什么不能只用 CLIP 的整句向量？【必须会】

CLIP 把图和文字各压成一个向量，适合回答“这句话是否对应这张图”。要生成“一只猫坐在椅子上”，需要逐词预测：先给出“一只”，再给出“猫”，再给出“坐”……一个整句向量并不直接提供这个接口。

CoCa 保留两类输出：用于比较的**全局向量**，用于生成的**位置序列**。它的文字网络分成上下两段：

```text
图片 [B,3,H,W] → 视觉编码器 → 生成池化器 → 视觉 token [B,Q,E]
                                              ├→ 对比池化器 → 图片全局 [B,E]
                                              └───────────────────────┐
文字编号 [B,L] → 下半段：因果文字自注意力 → 文字 token [B,L,D]         │
                     └→ 句子全局 [B,E]                              │
文字 token ─────────────────→ 上半段：因果自注意力 + 图文交叉注意力 ←─┘
                                                ↓
                                     每个位置的词表分数 [B,L,V]
```

`B` 是 batch size（一次处理的样本数）；`L` 是文字长度；`Q` 是视觉池化查询数；`E` 是对比向量的共同宽度；`D` 是解码隐藏宽度；`V` 是词表大小。配置可使 `D=E`，但这两个字母描述不同角色，不能只凭名字断言所有网络宽度相同。

### 3.1 下半段为什么不能提前看图片？

检索时希望数据库中每条文字都能预先算好表示。如果算文字表示必须同时拿到候选图片，图片一变就要重算全部文字，无法使用独立双塔检索。所以对比学习用的整句向量来自**没有读取图片的文字网络**。

### 3.2 下半段为什么也需要因果注意力？

causal 是“因果”的意思，在文字生成中表示位置 $t$ 只能读取不晚于 $t$ 的文字。如果下半段提前读到正确的下一词，上半段即使加了因果掩码也无法删除已经混入隐藏向量的答案。因此本地构造器拒绝双向 modern 文字塔用于 CoCa caption 路径。

图像作为条件可以被当前文字位置读取，不受“文字未来词”限制。不要把图像交叉注意力误画成只能看左上角一部分 patch。

### 3.3 句子汇总 token 放在哪里？

论文使用附加在文字**末尾**的可学习 `[CLS]` 来汇总句子。CLS 是 classification 的缩写，名字沿用分类汇总标记的习惯；在这里它主要提供对比向量。放在末尾使它在因果注意力下能读取前面的整句。不能照搬 BERT“第一个位置为 CLS”的理解。

## 5. 从一批输入追踪变量【必须会】

### 5.1 创建网络

`CoCa.__init__` 中创建 `self.visual`、`self.text`、`self.text_decoder`。`self` 表示当前模型对象；`self.visual` 保存下来，所以 `_encode_image` 以后能读取。同一个方法内部的 `vision_cfg` 是局部变量，不会因为命名就自动变成模型权重。

`cfg` 是 configuration 的缩写。Python 字典 `{"width":512}` 可通过 `CLIPTextCfg(**text_cfg)` 转成配置对象；`**` 把字典展开成关键字参数。`@dataclass` 根据字段自动生成初始化等方法，降低配置样板代码。

### 5.2 图片编码

`_encode_image(images)` 接收浮点图片，通常形状 `[B,3,H,W]`。`image_latent` 是整张图的隐表示 `[B,E]`；`tokens_embs` 是多个视觉 token，供生成使用。latent 不是类别编号，embs 是 embeddings 的复数简称。

原生视觉塔返回两个值；timm token 模式返回字典：`patch_tokens`、`patch_valid`、`pooled`。代码先检查输出类型，再选择相应分支，因此不能把所有视觉塔的返回值假设为相同 tuple。

pooling 是把多项特征聚合成较少特征。注意力池化使用可学习 query（查询）读取图片 patch 的 key/value（用于匹配与汇总的内容）。生成池化器保留多个查询，提供细节；对比池化器只需一个查询，把它压成整图表示。

- **cascade**：对比池化器读取生成池化器的输出，形成串联。
- **parallel**：两个池化器分别读取视觉主干，形成并联。

`F.normalize(image_latent, dim=-1)` 在最后一维把向量除以自身长度。例：$[3,4]$ 长度为 $5$，单位化得到 $[0.6,0.8]$。这一步处理全局向量；这里没有把用于生成的每个视觉 token 都强制变成单位向量。

### 5.3 文字编码

`text` 为 `[B,L]` 整数编号，不是字符串，也不是已生成的词向量。Embedding 查表后得到每个编号的向量，文字 Transformer 输出位置隐藏状态。`_encode_text` 返回 `text_latent` 与 `token_embs`，分别对应句子整体与文字序列。

`text_valid` 是 `[B,L]` 布尔或 0/1 掩码，表示哪些位置是真实词。valid 是有效的意思。它不能代替监督标签：标签告诉模型“应预测哪个词”，掩码只告诉模型“这个位置是否有效”。

### 5.4 前向输出

`CoCa.forward` 可以只收到图片，只收到文字，或收到配对图文。只收到图片返回图片表示；只收到文字返回句子表示。图文都有时，返回全局 features、对比分数尺度，以及生成 logits 或已计算的 caption CE。

`features` 在这里是全局特征 `[B,E]`；`image_embs` 是视觉序列 `[B,Q,E]`。两个名字都和图像有关，但用途和维度不同。

`logit_scale` 参数存储的是 $\log(1/\tau)$，前向调用 `.exp()` 还原成正的 $1/\tau$。初始 $\tau=0.07$，尺度约为 $14.286$。在对比学习里它乘余弦相似度，不是词表词编号。

## 6. 损失公式及代码差异

### 6.1 对比损失【必须会】

令单位图像向量为 $v_i\in\mathbb R^E$，单位文字向量为 $u_j\in\mathbb R^E$，batch 中有 $N$ 对数据。定义 $s_{ij}=v_i^\top u_j/\tau$，分数矩阵形状为 `[N,N]`。正确配对在对角线上，即第 $i$ 张图片对应第 $i$ 条文字。

论文式 (2) 写为：

$$
\mathcal L_{\mathrm{Con}}=-\frac1N\sum_{i=1}^N\left[
\log\frac{e^{s_{ii}}}{\sum_j e^{s_{ij}}}
+\log\frac{e^{s_{ii}}}{\sum_j e^{s_{ji}}}
\right].
$$

第一项是图片找文字，第二项是文字找图片。`ClipLoss` 分别计算两个交叉熵再除以 **2**，因而按上式的书面定义，本地代码的对比损失是论文数值的一半。不能只因两者都叫对比损失就宣称缩放完全一致；移植权重时要连同归约方式一起检查。

小例子：两对图文，矩阵为 $\begin{bmatrix}2&0\\0&2\end{bmatrix}$。正确概率为 $e^2/(e^2+1)\approx0.881$，单向平均 CE 约为 $0.127$。论文式 (2) 两方向求和约为 $0.254$；本地两方向平均仍约为 $0.127$。两种写法都鼓励对角分数变大，但损失权重的数值不能脱离缩放解释。

### 6.2 生成损失【必须会】

论文式 (3)：

$$
\mathcal L_{\mathrm{Cap}}=-\sum_{t=1}^T \log P_\theta(y_t\mid y_{<t},x).
$$

$x$ 是图片；$y_t$ 是第 $t$ 个真实词编号；$y_{<t}$ 表示它以前的词；$\theta$ 是模型参数集合；$T$ 是需要预测的词数。每一步从长度为 $V$ 的词表分数中，取真实下一词的概率，再取负对数。

正确词概率 $0.8$ 时，单位置损失约为 $0.223$；概率 $0.2$ 时约为 $1.609$。正确词越不可能，损失越大。本地 `CrossEntropyLoss` 默认对有效标签取均值，论文公式写的是求和；序列长度和有效位处理影响数值，训练配方必须明确归约方式。

`logits` 是未经 softmax 的分数 `[B,L,V]`，不能把它直接当概率。PyTorch 交叉熵内部处理 log-softmax，不需要先手工调用 softmax。

### 6.3 输入和标签为什么错开一格？

输入 `[BOS,猫,坐,EOS,PAD]` 的各位置需要预测 `[猫,坐,EOS,忽略]`。代码 `text[:,1:]` 去掉第一个编号作为目标；`logits[:,:-1]` 去掉最后一个预测位置，与目标长度相同。

`masked_fill(~valid[:,1:], -100)` 把无效目标改为 `-100`。`~` 对布尔张量取反；`masked_fill` 在掩码为 True 的位置填值。`-100` 是 `ignore_index`（忽略索引），不是一个真实词，不能拿它去查词嵌入表。

本地 SimpleTokenizer 的 `0` 可能是正常词表编号，不能永远解释成专门的 PAD。优先传真实 `text_valid`，避免“真实词恰好编号 0”被错误忽略。`CoCaTask` 已把标签处理成 `-100` 后，构造 `CoCaLoss` 使用 `pad_id=None`，防止再次按编号误删。

`loss_logits.permute(0,2,1)` 将 `[B,L,V]` 改成 `[B,V,L]`。这里交换的是轴的访问顺序，值的含义不变；因为 `CrossEntropyLoss` 的类别轴要求在第 1 维，目标仍是 `[B,L]`。

### 6.4 联合目标【必须会】

论文式 (4)：

$$\mathcal L_{\mathrm{CoCa}}=\lambda_{\mathrm{Con}}\mathcal L_{\mathrm{Con}}+\lambda_{\mathrm{Cap}}\mathcal L_{\mathrm{Cap}}.$$

$\lambda$ 是权重系数。论文主要设置 $\lambda_{\mathrm{Con}}=1$、$\lambda_{\mathrm{Cap}}=2$。本地 Task 的默认数字也是 1 和 2，但前述归约区别意味着同数字不自动代表完全一样的优化尺度。

`CoCaLoss` 返回 `contrastive_loss` 和 `caption_loss`；Task 挑选名字以 `_loss` 结尾的项相加。诊断值 `caption_loss_ce` 没有这个结尾，避免 CE 和加权 CE 重复计入。`.detach()` 保留数值但断开求导，仅用于报告；不能把所有训练项都 detach 后再期待网络学习。

### 6.5 融合 CE、z-loss 与梯度检查点【可以暂时不掌握】

融合路径传 `labels` 到模型内部，由 `fused_caption_loss` 分块计算词表投影与交叉熵，输出标量而不是完整 `[B,L,V]`。目标仍是预测下一词，它主要改变显存与计算组织。`lm_head_params` 中 LM=language model，head=最终输出层，`*tuple` 把权重与偏置展开成参数。

`caption_z_loss_weight` 默认 0；非零时增加本地可选稳定项，不能描述成论文原始第三损失。融合路径当前不支持 `--accum-freq > 1`，源码会明确抛出 `NotImplementedError`。梯度检查点是在反向时重算部分前向以节省显存；不等于保存模型 checkpoint 文件。

## 7. 解码器内部：图片怎样影响每个词？

`MultimodalTransformer.forward(context,text_embs)` 的 `context` 是视觉条件 `[B,Q,D]`，`text_embs` 是文字位置表示 `[B,L,D]`。

循环 `zip(self.resblocks,self.cross_attn)` 把同层的自注意力模块和交叉注意力模块配对。

1. `resblock` 用因果掩码让文字位置只读取过去的文字。
2. `cross_attn` 让文字作 query，图片作 key 和 value。`k_x=context,v_x=context` 是明确指定图像来源。
3. LayerNorm 处理特征，词表投影 `out @ self.text_projection` 把隐藏宽度 $D$ 转成 $V$ 个词的分数。

矩阵乘法形状为 `[B,L,D] @ [D,V] → [B,L,V]`。投影参数不是“图片到文字编号的一张查找表”；它是根据当前图片条件与文字前缀的隐藏状态计算每个候选词的分数。

## 8. 配置数字怎么读？

本地 `coca_ViT-B-32.json`：图片 224×224，小块 32×32，视觉宽度 768、12 层；文字宽度 512、12 层；多模态解码器宽度 512、12 层；共同对比宽度 512；词表 49,408；文字 context length 为 76。

`ViT`=Vision Transformer；B=Base（规模命名）；32=patch 边长，不是层数。224/32=7，原图分成 7×7=49 个 patch；主干内部是否额外添加汇总 token，以及池化后有多少 token，需要看实际配置分支，不能把 49 直接填进生成解码器长度。

论文用 288×288、patch 18、64k SentencePiece 词表，生成池化查询数 256。两者图片分辨率、patch、词表等都不同。旧 `coca_*` 配置与 `coca2_*` 池化行为也不同：README 说明后者独立对比池化，使 caption 可访问全部 256 个生成查询；旧配置路径可能只有 255 个生成 token。阅读时明确你实例化的具体配置。

## 9. 推理与训练的区别【建议会】

训练能一次输入真实 caption，用因果掩码同时计算各位置下一词损失。生成时不知道真实 caption，要从 BOS 开始，预测一个词、接到前缀，再预测下一词，直到 EOS 或长度限制。

`generate` 委托 `generation.generate_multimodal`，并提供图片编码、文字编码与解码器函数。`beam_search` 是维护多个候选续写的搜索方法；`num_beams` 是候选数量。它不是训练目标，也不保证生成内容一定真实。

`temperature` 在生成采样中调节词表概率；对比学习的温度调节图文配对分数。名称相似，但作用位置不同。

Caption 指标：BLEU@4 关注四元词组匹配；METEOR 使用词匹配等因素；CIDEr 衡量与多个人工描述的一致性；SPICE 关注语义结构匹配。它们有不同算法与尺度，不能平均这四列得出一个随意的“总准确率”。

### 10.1 表 8 消融更接近回答“为什么有效？”

- **8a**：生成训练的线性评价 82.1，分类训练 81.0，增加 1.1 点；微调 84.9 对 85.1，下降 0.2 点。不能总结为生成训练所有评价都更好。
- **8b**：仅对比 ZS=70.7、VQA=59.2；联合 ZS=71.6、VQA=69.0，分别提高 0.9 和 9.8 点。仅 caption VQA=68.9，但 ZS 列为横杠，表示该设置没有这项结果，不能当作 0 分。
- **8b 资源**：caption-only 成本 1.17×，联合 1.18×，相对于 caption 增加约 0.85%；对比-only 为 1×。这是该消融的 TPUv3-core-days 成本，不是任意硬件上都会快同样的比例。
- **8c**：caption:contrastive 从 1:1 到 2:1，ZS 71.5→71.6（+0.1），VQA 68.6→69.0（+0.4）。支持作者选用 2:1，但权重迁移需要考虑代码归约。
- **8d**：固定总解码层数 12，unimodal 层 3/6/9 的 ZS 为 70.2/71.6/71.4。6 层取得该设置的平衡，不等于所有模型永远各占一半最优。
- **8e**：一个 CLS 的 COCO 平均 R@1 为 41.4，加入文字 token 聚合为 40.2，下降 1.2 点。这里只支持当前聚合选择，不能断言所有文本平均池化都不好。
- **8f**：parallel 71.2/68.7，cascade 71.6/69.0，分别 +0.4/+0.3。单视觉查询 VQA 64.4，默认 256 查询为 69.0，多 4.6 点。`nquery=0` 意为不使用生成池化器、直接读主干 token，并非没有视觉输入。

消融使用较小模型、12 个总解码层、batch 4096；不要把它与主实验 Base 的 12+12 层或大模型主结果合在一行。

## 11. 能否在本机小型复现？

论文完整训练使用 JFT-3B 与 ALIGN，batch 65,536，每批两来源各一半，500k steps；论文报告约 2,048 个 CloudTPUv4 芯片训练 5 天，之后继续使用 576×576 分辨率。优化器为 Adafactor。这样的资源和数据条件不适合普通本科生设备完整复制。

可做的学习目标分三层：

1. **结构验证**：用很小的图文配置跑 forward，核对四类表示、下一词标签和损失。
2. **小数据训练**：用授权取得的配对图文数据，只检查损失是否能优化、模型是否能记住有限例子，记录训练/验证划分。
3. **迁移实验**：加载可用 OpenCLIP CoCa 权重做 caption 或检索，明确权重、tokenizer 与配置版本。

目前本篇状态为 **部分成功**：使用本地真实 CoCa 类完成 CPU 极小前向、普通/融合 CE 对照、20 步固定模拟批次优化和 beam search 接口检查。总损失 10.638439→0.282685，梯度有限且非零；生成返回人工编号 `[1,3,4,5,2]`，且恢复调用前训练模式。

[逐行注释检查脚本](复现/scripts/检查小型CoCa.py) · [环境与运行说明](复现/README.md) · [实际结果](复现/outputs/小型CoCa检查.json)。模拟图片与人工编号没有真实语义；该结果证明小配置计算路径可以运行，不证明自然图文泛化、真实数据训练质量或原规模论文指标。
