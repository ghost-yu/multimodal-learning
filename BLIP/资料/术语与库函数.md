# BLIP 零基础词典：英文、缩写、库函数和每一步的形状

这份词典配合 [BLIP 主流程讲解](../解释.md) 和已经加中文注释的 [预训练模型源码](../models/blip_pretrain.py) 使用。遇到英文词或函数名时，先在本页搜索；再回到源码，看这一行的输入与输出。论文术语以[BLIP 原论文](https://proceedings.mlr.press/v162/li22n/li22n.pdf)为准，代码变量名以本地仓库为准。下面的形状采用默认预训练配置：图片 224×224、ViT-Base、文字最长 30 token、对比向量 256 维。

## 1. 先认识源码里的英文和缩写

| 词 / 缩写 | 英文全称或原词 | 中文意思，以及在 BLIP 中做什么 |
|---|---|---|
| BLIP | **B**ootstrapping **L**anguage-**I**mage **P**re-training | 自举式图文预训练。预训练同时学图文对齐、图文匹配、图像描述生成。这里讲的是 BLIP 一代。 |
| ViT | **Vi**sion **T**ransformer | 视觉 Transformer。把图片切成小块（patch），再让这些块通过注意力交换信息。 |
| DeiT | **D**ata-efficient **i**mage **T**ransformers | BLIP 预训练中 ViT-Base 的一种初始权重来源；代码首次加载时会下载相应检查点。 |
| BERT | **B**idirectional **E**ncoder **R**epresentations from **T**ransformers | 用 Transformer 编码文字的模型。BLIP 的文字部分在 BERT 基础上加入图文交叉注意力。 |
| MED | **M**ultimodal mixture of **E**ncoder-**D**ecoder | 多模态编码器与解码器混合架构。文字结构可作纯文字编码器、图文融合编码器或图像条件下的生成解码器；读代码时看 `mode` 和 `is_decoder`。 |
| ITC / 代码中的 ITA | **I**mage-**T**ext **C**ontrastive / **I**mage-**T**ext **A**lignment | **论文称 ITC（图文对比）**，这份代码沿用 `loss_ita`（图文对齐）变量名，指此处的同一对比训练目标：真配对整体向量靠近、错误配对远离。读论文与代码时要记住名字不同。 |
| ITM | **I**mage-**T**ext **M**atching | 图文匹配。把一张图和一句话联合编码，再二分类判断是否真实配对；损失名 `loss_itm`。 |
| LM | **L**anguage **M**odeling | 语言建模。看到图片和已经生成的前文，预测下一个词；损失名 `loss_lm`。 |
| VQA | **V**isual **Q**uestion **A**nswering | 视觉问答。给图片和问题，输出答案，是 BLIP 的下游任务之一。 |
| CLS | **Cl**a**s**sification token | 序列第 0 个特殊 token。ViT 的 CLS 汇总图像；BERT 的首 token 汇总句子。`x[:,0,:]` 即取每个样本的首 token。 |
| BOS | **B**eginning **o**f **S**equence | 句子开始标记。BLIP 给 tokenizer 加的 `[DEC]` 用作生成开始 token。 |
| ENC / DEC | **Enc**oder / **Dec**oder | `[ENC]` 提示图文联合编码，`[DEC]` 提示开始解码生成。它们是特殊 token，不是普通英文单词。 |
| SEP | **Sep**arator | BERT 的 `[SEP]` 特殊 token；生成到它可以表示句子结束。 |
| PAD | **Pad**ding | 补齐短句的占位 token。它不是真实文字；`attention_mask=0` 或标签 `-100` 会让相关计算忽略它。 |
| Q / K / V | **Q**uery / **K**ey / **V**alue | 查询、键、值。Q 与 K 算相关度，再按权重汇总 V。图文交叉注意力中 Q 来自文字，K/V 来自图像。 |
| MLP / FFN | **M**ulti-**L**ayer **P**erceptron / **F**eed-**F**orward **N**etwork | 多层感知机 / 前馈网络。这里通常是两层线性变换加激活，逐 token 加工特征。 |
| EMA | **E**xponential **M**oving **A**verage | 指数滑动平均。动量教师参数逐步跟随学生：`教师新值 = m×教师旧值 + (1-m)×学生新值`。 |
| DDP | **D**istributed **D**ata **P**arallel | 多进程数据并行。一般每个 GPU 一个进程，处理不同数据，反向传播时同步梯度。 |
| GPU / CPU / CUDA | Graphics Processing Unit / Central Processing Unit / NVIDIA Compute Unified Device Architecture | GPU 负责大规模张量计算；CPU 负责常规程序与数据准备；`cuda` 是 PyTorch 中常见的 NVIDIA GPU 设备名。 |
| COCO | Common Objects in Context | 常见图像和图像描述数据集；BLIP 的 caption 微调、评估使用它。 |
| LAION | Large-scale Artificial Intelligence Open Network | 图文数据来源；代码允许按 JSON 分片轮换载入。 |
| CIDEr / BLEU | Consensus-based Image Description Evaluation / BiLingual Evaluation Understudy | 图像描述质量指标。`Bleu_4` 中的 4 代表比较最长 4 个词组成的连续片段。`train_caption.py` 用验证集的 `CIDEr + Bleu_4` 选最佳检查点。它们是评估分数，不是训练 loss。 |
| CapFilt | **Cap**tioning and **Filt**ering | 论文的数据自举方法：生成新描述、筛选图文对。它属于 BLIP 论文的另一部分；此处的 `BLIP_Pretrain.forward()` 只展示模型的三项训练损失。 |

常见但容易误会的词：`caption` 是图片描述句子；`embedding` 是连续数字向量；`logits` 是 softmax 前的原始类别分数；`label` 是正确答案；`loss` 是训练要最小化的误差；`checkpoint` 是保存模型参数等状态的文件；`pretrained` 指先在别的数据上学过的初始参数；`fine-tuning` 指在目标任务继续训练；`inference` 指用模型预测而不更新参数。

| 常见英文词组 | 白话解释 |
|---|---|
| bootstrapping（自举） | 利用已有模型生成或筛选额外训练数据，再用这些数据改进模型。BLIP 论文的 CapFilt 就是这种思路；读当前 `forward()` 时先看三项损失。 |
| batch / batch size（批 / 批大小） | 一次喂给模型的若干样本；默认 `B=75` 是每个 GPU 每批 75 对图文。 |
| epoch（训练轮） | 把当前 Dataset 大致完整遍历一遍。一个 epoch 通常包含许多 batch。 |
| learning rate / warmup（学习率 / 预热） | 学习率决定每次参数更新步幅；预热让它在训练开始的若干步从较小值逐渐升高。 |
| weight decay（权重衰减） | 优化器对权重数值施加的约束，常用于减少过拟合；不是让训练 loss 按比例减少。 |
| temperature（温度） | 对比分数除以 `temp` 再 softmax。温度较小会让概率更集中，但极端值可能不稳定。 |
| hard negative（难负例） | 标签为“错误配对”却与真配对很相似的图文，能迫使模型学更细的区别。 |
| soft target / hard target（软/硬目标） | 软目标给多个候选分配概率；硬目标通常只给真配对位置 1、其他位置 0。 |
| contrastive learning（对比学习） | 让正确图文更接近、错误图文更远离的训练方式。 |
| cross-attention（交叉注意力） | 一类 token 发出 Q 去读取另一类 token 的 K/V；BLIP 中通常是文字读取图片。 |
| Beam Search / nucleus sampling（束搜索 / 核采样） | 前者同时保留若干条高分候选句；后者在累计概率覆盖 `top_p` 的高概率词集合中抽样。 |

**word 与 token 的区别**：word 是人眼看到的词；token 是 tokenizer 词表中的一个编号单位。一个词可能拆成多个 token，特殊标记 `[CLS]`、`[SEP]`、`[PAD]` 也各占 token 位置。因此“最多 30 个 token”不保证等于“最多 30 个英文单词”。`pre_caption(...,30)` 先按空格截词，BERT tokenizer 后续仍可能拆出更多 token，再按 `max_length=30` 截断。

### 变量名拆词读

| 变量名 | 逐词翻译 | 在此处是什么 |
|---|---|---|
| `image_embeds` | image + embeddings | ViT 输出的**整串**图像 token `[B,P,Dv]`；保留每个 patch。 |
| `image_feat` | image + feature | 图像 CLS 经过 `vision_proj`、归一化后的**整体**向量 `[B,E]`。它比 `image_embeds` 少了 patch 维。 |
| `text.input_ids` | input + IDs | token 的整数编号 `[B,T]`，不是词向量，也不是原始字符串。 |
| `text.attention_mask` | attention + mask | 哪些文字位置有效的 0/1 张量 `[B,T]`。 |
| `text_output.last_hidden_state` | 最后一层隐藏状态 | 最后一层 BERT 每个文字 token 的向量 `[B,T,Dt]`。 |
| `text_feat` | text + feature | 文字 CLS 投影、归一化后的整体向量 `[B,E]`。 |
| `vision_proj` / `text_proj` | vision/text + projection | 图像/文字投影层，将两边的 CLS 变成相同 E 维。 |
| `_m`，如 `image_feat_m` | momentum（动量）后缀 | 教师网络算出的特征，不是“米”或另一个模态。 |
| `i2t` / `t2i` | image-to-text / text-to-image | 以图找文 / 以文找图，查询与候选角色相反。 |
| `sim_i2t` | similarity + image-to-text | 每张图与全部候选文字的相似度 `[B,B+Q]`。 |
| `sim_targets` | similarity + targets | 真配对硬标签；本批第 i 个图文在矩阵 `(i,i)` 位置为 1。 |
| `weights_t2i` | text-to-image sampling weights | 给每条文字抽错图时使用的概率权重。 |
| `encoder_hidden_states` | 编码器隐藏状态 | 在 BLIP 的图文交叉注意力里通常是图像 token `[B,P,Dv]`。 |
| `pos` / `neg` | positive / negative | 正配对 / 错误配对；与图像“正负像素”无关。 |
| `atts` | attentions / attention masks 的缩写 | 此仓库里的 `image_atts` 是图像 token 有效位 `[B,P]`。 |
| `proj`、`pred`、`ptr` | projection、prediction、pointer | 投影、预测、指针；`queue_ptr` 指下次覆盖队列的位置。 |
| `bs` | batch size | 当前这一批样本数，通常来自 `image.size(0)`。 |

源码的导入别名也要认：`torch` 是 PyTorch 主包；`nn` 是 `torch.nn` 网络层模块；`F` 是 `torch.nn.functional`，提供直接调用的函数；`dist` 是 `torch.distributed` 多进程通信模块；`utils` 是**本仓库的** `BLIP/utils.py`，不是 PyTorch 官方模块；`yaml` 在本项目是 `ruamel_yaml` 的别名。

## 2. 形状写法：先看清一行张量在表示什么

| 符号 | 这份项目中的意义 | 默认例子 |
|---|---|---|
| `B` | batch size，一批样本数 | `config['batch_size']=75`，是每个 GPU 的训练批大小 |
| `H,W` | 图片高度、宽度 | 224、224 |
| `P` | 图像 token 数，包含 CLS | `(224/16)² + 1 = 197` |
| `T` | 文字 token 数，包含特殊 token 与可能的 PAD | 预训练最多 30 |
| `D` / `Dv` / `Dt` | 模型隐藏维度 / 图像隐藏维度 / 文字隐藏维度 | Base 通常是 768 |
| `E` | 对比学习的共享向量维度 | 256 |
| `Q` | 历史特征队列长度 | 57600 |
| `V` | 词表大小 | 由 BERT tokenizer 和新增特殊 token 决定 |

`[B,3,224,224]` 是 B 张 RGB 图片；`[B,P,Dv]` 是每张图 P 个 token、每 token Dv 个数；`[B,T,Dt]` 是文字 token 特征；`[B,E]` 是每张图或每句话一个整体向量。`[B,B+Q]` 是本批 B 个查询与本批及队列中的候选之间的相似度矩阵。方括号只是在说明**张量形状**，不代表 Python 列表值。

## 3. Python 语法和方法名：为什么模型看起来像函数

| 代码写法 | 一步一步理解 |
|---|---|
| `class BLIP_Pretrain(nn.Module):` | 定义一个类，继承 PyTorch 的模型基类 `nn.Module`，所以其子层能注册参数。 |
| `def __init__(self, ...):` | 创建对象时运行一次，负责建立 ViT、BERT、线性层、队列等；这里通常不处理某个具体 batch。 |
| `super().__init__()` | 先执行父类 `nn.Module` 初始化；缺它会影响参数注册。 |
| `def forward(self, image, caption, alpha):` | 定义一批数据如何从输入走到输出。训练时调用 `model(image, caption, alpha)`，PyTorch 的 `__call__` 会转而调用 `forward`。 |
| `self.visual_encoder` | `self` 是当前模型对象；点号表示它持有一个名为 `visual_encoder` 的子模型。 |
| `**kwargs` | 把一组“参数名=值”的关键字参数打包/拆包，例如工厂函数传给 `BLIP_Pretrain(**kwargs)`。 |
| `@torch.no_grad()` | 装饰器，让整个函数运行时不记录梯度；动量更新、评估用它。 |
| `with torch.no_grad():` | 只让缩进块里的运算不记录梯度。 |
| `enumerate(loader)` | 逐批遍历的同时获得序号 `i`，所以循环可以写成 `for i, batch in ...`。 |
| `zip(a,b)` | 按同一位置把两个序列配对；例如把图文模型中的学生参数与教师参数一一对应。 |
| `[x for x in items]` | 列表推导式；逐个处理 `items` 并生成新列表。 |
| `x[:,0,:]` | 三维张量中取“全部样本、第 0 个 token、全部特征”，结果 `[B,D]`。 |
| `x[:,:bs]` | 保留所有样本、前 `bs` 个候选；`bs` 这个位置不包含在内。 |
| `x[:, :-1, :]` | 去掉最后一个 token 位置；生成训练时用于“用前文预测下一个词”。 |
| `x[:, 1:]` | 去掉第一个标签；与上一行错开一步。 |
| `f'{epoch}'` | f-string，在字符串中插入变量值。 |
| `if __name__ == '__main__':` | 直接运行脚本时执行命令行入口；别的文件 `import` 它时不自动启动训练。 |

## 4. PyTorch 模型层与参数：构造器创建了什么

| 调用 | 输入 → 输出 / 作用 |
|---|---|
| `nn.Module` | 神经网络基类，管理参数、子模型、设备迁移以及 `train()/eval()` 状态。 |
| `nn.Linear(in_features, out_features)` | 线性变换。例如 `nn.Linear(768,256)` 把 `[B,768]` 变成 `[B,256]`；权重和偏置由训练更新。 |
| `nn.Embedding(vocab_size, hidden_size)` | 词向量表：整数 token ID `[B,T]` 变为浮点向量 `[B,T,D]`。 |
| `nn.LayerNorm(D)` | 对每个 token 的 D 维特征做归一化并学习缩放/偏移，形状不变。 |
| `nn.Dropout(p)` | 训练时随机将部分值置零以降低过拟合，`model.eval()` 时通常关闭。 |
| `nn.ModuleList([...])` | 按顺序保存多层子模型并注册其参数；ViT 的 12 个 block 就放在里面。 |
| `nn.Parameter(tensor)` | 告诉 `nn.Module`：这个张量是可训练参数。例如 BLIP 的温度 `self.temp`。 |
| `register_buffer(name, tensor)` | 注册随模型保存、搬设备的张量，但不作为训练参数。例如历史向量队列和队列指针。 |
| `PatchEmbed(...)`（timm） | 图像 `[B,3,224,224]` 切为 196 个 patch 并投影成 `[B,196,768]`。 |
| `checkpoint_wrapper(...)`（fairscale） | 梯度检查点：前向少保存中间值，反向时重算部分前向，以计算时间换显存。 |

`model.state_dict()` 返回“参数或 buffer 名称 → 张量”的字典，用于保存；`model.load_state_dict(state_dict, strict=False)` 把权重放回模型。`strict=False` 允许部分层缺失或多余，返回的 `msg.missing_keys` 等信息仍应检查。`model.to(device)` 把参数和 buffer 搬到 CPU/GPU；输入张量也须在同一设备。

## 5. 张量函数：先说参数，再说形状与结果

| 源码里的调用 | 参数的意思 | BLIP 里的具体效果 |
|---|---|---|
| `torch.zeros(shape)` / `torch.ones(shape)` / `torch.randn(shape)` | 建全 0、全 1、标准正态随机张量；`shape` 指各维长度。 | `sim_targets` 先用全 0 建标签；`image_atts` 用全 1 表示图像 token 都有效；队列先随机初始化。 |
| `torch.zeros_like(x)` / `torch.ones_like(x)` | 建与 `x` 同形状、同设备/类型的 0 或 1 张量。 | 分布式 `all_gather` 先建立接收容器。 |
| `x.size()`、`x.shape`、`x.size(0)` | 看全部形状、全部形状、第 0 维长度。 | `image.size(0)` 得到本批图片数 `B`；`image_embeds.size()[:-1]` 得到 `[B,P]`。 |
| `.to(device)` | 把张量或模型搬到指定设备。 | `image.to(device)` 让图片与模型同在 GPU；tokenizer 输出也要 `.to(image.device)`。 |
| `.clone()` | 复制当前数值到新张量，避免修改新张量时改变原张量；默认仍能追踪梯度。 | `encoder_input_ids`、`decoder_input_ids` 从原始文字 ID 分出不同用途。 |
| `.detach()` | 将张量与梯度计算图断开；通常共享数据存储，不能把它当深拷贝。 | 历史队列作为对比候选，不通过旧特征回传梯度。 |
| `.clamp_(min,max)` | 把元素限制在区间内；结尾 `_` 表示原地改。 | `self.temp.clamp_(0.001,0.5)` 防止温度取极端值。 |
| `F.normalize(x, dim=-1)` | 沿最后一维把每个向量缩到长度约为 1。 | 图像 CLS 投影成 `[B,256]` 后归一化，便于用点积量相似度。 |
| `x @ y` / `torch.matmul(x,y)` | 矩阵乘法；中间维度必须对应。 | `[B,256] @ [256,B+Q] -> [B,B+Q]`，算图与候选文字的相似度。 |
| `.t()` / `.T` | 转置二维矩阵；`.T` 在 BLIP 的二维特征上效果相同。 | `[B,256] -> [256,B]`，供候选矩阵拼接或队列写入。 |
| `.transpose(-2,-1)` | 互换倒数两维，不改变元素数目。 | 注意力里 K 的 `[B,H,N,Dh] -> [B,H,Dh,N]`，才能与 Q 点积。 |
| `.reshape(...)` / `.view(...)` | 改张量形状但保持元素总数；`view` 要求兼容的内存布局。 | ViT 把 `3D` 的 QKV 投影分成三个矩阵和多个注意力头。 |
| `.permute(2,0,3,1,4)` | 明确按指定顺序重新排列各维。 | 把 QKV 的 `[B,N,3,H,Dh]` 排成 `[3,B,H,N,Dh]`。 |
| `.contiguous()` | 让数据在内存中按当前形状连续存放，方便随后 `.view()`。 | MED 在展平“批 × 词位置”前调用。 |
| `torch.cat(list, dim=...)` | 沿**已有维度**拼张量，其他维度必须一致。 | 沿 `dim=1` 拼当前与历史候选；沿 `dim=0` 拼正负图文样本。 |
| `torch.stack(list, dim=0)` | 创建一个**新维度**并堆叠同形张量。 | `B` 个 `[P,Dv]` 负图变成 `[B,P,Dv]`。 |
| `.expand(B,-1,-1)` | 把长度为 1 的维广播为 B；`-1` 表示保持原长度，通常不复制完整数据。 | 一枚 `[1,1,D]` CLS 参数供 B 张图片共享使用。 |
| `.repeat_interleave(k, dim=0)` | 沿指定维度让每项重复 k 次。 | Beam Search 中每张图复制 k 份视觉特征，与 k 条候选句对应。 |
| `.masked_fill(mask, value)` | 在布尔 mask 为真的位置填入 `value`，返回新张量。 | 文字 PAD 标签填成 `-100`，后续交叉熵忽略。 |
| `.fill_diagonal_(value)` | 把矩阵对角线原地填成给定值。 | ITA 的真配对标为 1；负采样权重对角线设为 0，避免抽到真配对。 |
| `torch.multinomial(weights,1)` | 根据非负权重随机抽一个索引；权重越高越可能抽中。 | 从相似但错误的图/文中选“难负例”。`weights[b]` 是第 b 行候选权重。 |
| `F.softmax(scores,dim=1)` | 沿第 1 维把分数变成和为 1 的概率。 | 每个查询对 `B+Q` 个候选得到一个概率分布。 |
| `F.log_softmax(scores,dim=1)` | 对上述概率取对数，数值上比 `softmax` 后再 `log` 更稳定。 | ITA 中与软目标相乘，计算交叉熵。 |
| `F.cross_entropy(logits,labels)` | 比较每行类别分数与正确类别整数，返回平均损失。 | ITM 的 `[3B,2]` 分数配上 `3B` 个 0/1 标签。 |
| `.mean()`、`.sum(dim=1)`、`.item()` | 求平均、沿一维求和、把单元素张量转为 Python 数。 | ITA 先对候选求和再对 batch 平均；记录日志时才使用 `.item()`。 |

**`dim` 要结合当前张量理解。** 对 `[B,T,D]`，`dim=0` 是样本，`dim=1` 是词位置，`dim=2` 是特征。对 `[B,B+Q]`，`dim=1` 是候选图/文。不要把 `dim=1` 永远背成“文字长度”。

### 一个小算例：ITA 的矩阵乘法

假设 `B=2`、`E=3`、队列 `Q=4`。`image_feat` 是 `[2,3]`：两张图片，每张一个 3 维向量。`text_feat_all` 是 `[3,6]`：6 条候选文字，每条也是 3 维。`image_feat @ text_feat_all` 得到 `[2,6]`：第 0 行是图 0 对六条文字的分数，第 1 行是图 1 的分数。两张真配对分别是位置 `(0,0)` 和 `(1,1)`，所以 `fill_diagonal_(1)` 可建立当前 batch 的硬标签。

| `resize_token_embeddings(len(tokenizer))` | BLIP 新增 `[ENC]`、`[DEC]` 后，模型的词向量表也要扩容，否则新 token ID 会越界。 |

| `model.train()` / `model.eval()` | 切换训练/评估状态，主要影响 Dropout 等层；`eval()` 本身**不会**关闭梯度，因此评估还用 `@torch.no_grad()`。 |
| `optimizer.zero_grad()` | 清除上一批梯度，因为 PyTorch 默认把多次反向传播的梯度相加。 |
| `loss.backward()` | 从标量 loss 沿计算图反向求各可训练参数的梯度，存入参数的 `.grad`。 |
| `optimizer.step()` | AdamW 根据 `.grad` 和优化器内部状态，真正修改模型参数。 |

| `torch.save(obj,path)` / `torch.load(path)` | 保存/读取检查点。原代码还保存优化器状态和 epoch，便于续训。 |
| `DistributedDataParallel(model,device_ids=[gpu])` | 包装多 GPU 训练模型，反向传播时同步各 GPU 的梯度。包装后原模型可用 `.module` 取到。 |
| `torch.distributed.all_gather(outputs,tensor)` | 每个 GPU 把本地张量发给全部 GPU；BLIP 用它保持各进程历史队列一致。 |
| `torch.distributed.all_reduce(tensor)` | 将各 GPU 的统计张量求和并让每个进程都得到结果；`MetricLogger` 汇总 `count`、`total` 时使用。 |

这里有两组特别重要的区别。`model.train()` 与 `model.eval()` 是切换层的行为；`loss.backward()` 与 `optimizer.step()` 才负责求梯度和改参数。`self.visual_encoder(image)` 读取**图像特征**；`self.text_encoder(...,mode='text')` 读取**纯文字特征**；同一文字编码器传 `encoder_hidden_states=image_embeds` 时会做**图文融合**；`self.text_decoder(...,labels=...)` 则算**生成损失**。

### `generate()` 的参数逐个读

`sample=False` 使用 Beam Search（束搜索）；`sample=True` 使用随机采样。`num_beams=3` 表示束搜索同时保留 3 条候选句。`max_length`、`min_length` 控制最终 token 数范围。`top_p=0.9` 是核采样阈值：只在累计概率达到约 0.9 的高概率候选里抽词。`repetition_penalty` 影响重复词的偏好。`eos_token_id` 是结束 token 的整数 ID；`pad_token_id` 是补齐 token 的整数 ID。返回的仍是 token ID，最后由 `tokenizer.decode(..., skip_special_tokens=True)` 变成文字，并去掉固定 prompt。

注意原仓库 `BLIP_Decoder.generate()` 的采样分支把重复惩罚写成固定 `1.1`；传入的 `repetition_penalty` 参数在束搜索分支使用。阅读源码时以具体分支为准。

## 8. 把最难的三段代码逐句翻译

### A. ITA：为什么能让正确图文更接近？

1. `image_embeds = self.visual_encoder(image)`：ViT 返回整张图的 token 序列 `[B,197,768]`。
2. `image_embeds[:,0,:]`：取每张图的 CLS，成为 `[B,768]`。
3. `self.vision_proj(...)`：线性投影成 `[B,256]`，与文字进入同一个特征空间。
4. `F.normalize(...,dim=-1)`：每行向量变成长度约为 1；点积高说明方向接近。
5. 文字侧同样 tokenizer、BERT、取 CLS、投影、归一化，得到 `text_feat: [B,256]`。
6. `_momentum_update()`：把学生的一小部分新参数混入教师。因为教师不直接接收梯度，它的预测变化较平稳。
7. `torch.cat([text_feat_m.t(), self.text_queue.clone().detach()],dim=1)`：当前教师文字 `[256,B]` 与旧文字 `[256,Q]` 拼为 `[256,B+Q]`。
8. `image_feat_m @ text_feat_all / self.temp`：教师给当前 B 张图对所有候选的分数 `[B,B+Q]`。温度越小，分数差异在 softmax 后越显著。
9. `sim_targets.fill_diagonal_(1)`：前 B 列中第 i 张图与第 i 句文字配对正确。队列列没有这种对角线真标签。
10. `alpha * F.softmax(sim_i2t_m,dim=1) + (1-alpha)*sim_targets`：目标分布是“教师软概率”和“确定的真配对标签”的加权平均。
11. 学生也计算相似度，`F.log_softmax` 变为对数概率；与目标逐项相乘、求和、取负，得到图搜文交叉熵。另一个方向文搜图同理。两者均值为 `loss_ita`。

**软目标与硬目标**：硬目标只承认第 i 个配对；软目标允许相似的其他描述有一点概率。例如一张“猫在沙发上”的图，与“黑猫躺在沙发上”虽然未被标成配对，也可能语义接近。这里 `alpha` 控制教师软目标比例；它不是学习率。

### B. ITM：难负例为什么是“难”的？

1. 正样本是原始 `B` 对图文，标签为 1。
2. `F.softmax(sim_t2i[:,:bs],dim=1)` 将相似度变成“为当前文字选哪张图”的权重；只取当前 batch 的图，因为后面必须拿得到该图的完整 patch 特征。
3. `fill_diagonal_(0)` 将真正对应的图片权重设为零，保证负样本不会误抽到正样本。
4. `torch.multinomial(weights_t2i[b],1)` 按权重抽一个索引。越相似的错误图通常权重越高，所以比随便挑一张图更难判断。
5. 同理给每张图抽错误文字，得到两类各 `B` 个负样本；`torch.cat` 将它们合成 `2B` 对。
6. MED 让文字读取图像 token，输出融合的 CLS；`itm_head` 把 `[3B,768]` 变成 `[3B,2]`，两列是“不匹配/匹配”分数。
7. `F.cross_entropy(vl_output,itm_labels)` 根据前 B 个 1、后 2B 个 0 计算二分类损失。

### C. LM：到底哪一行在“预测下一个词”？

1. tokenizer 给文字变成 `[B,T]` 的整数 token ID，首 token 替换成 `[DEC]`。
2. `decoder_targets = ...masked_fill(...PAD...,-100)`：PAD 占位符不应成为要预测的答案。
3. `self.text_decoder(...,encoder_hidden_states=image_embeds,labels=decoder_targets)`：文字 token 读图像；给 `labels` 意味着要求计算损失。
4. [med.py](../models/med.py) 的 `prediction_scores[:, :-1, :]` 去掉最后一个预测位置；`labels[:,1:]` 去掉第一个目标位置。两者对齐后，第 0 位输出预测第 1 位词，第 1 位输出预测第 2 位词。
5. `CrossEntropyLoss(label_smoothing=0.1)` 比较每个位置的词表分数与目标词 ID，返回 `loss_lm`。标签 `-100` 的位置不算。

## 9. 阅读时特别容易踩的四个点

1. **图片 patch 与文字 token 不是同一种东西。** 图片 patch 来自像素块；文字 token 来自 tokenizer。二者可以通过交叉注意力交流，但输入来源和长度不同。
2. **`mode='text'` 与图文融合不是同一次计算。** 前者只让文字互相读，用于全局对比；后者让文字读图像，用于 ITM 和生成。
3. **队列不保存原始图片。** `image_queue/text_queue` 保存的是以前 batch 的低维整体向量 `[E,Q]`。抽 ITM 负例时只在当前 batch 抽，因为 ITM 还需要完整图像 token。
4. **语法检查不等于训练成功。** 默认 YAML 使用作者机器上的 `/export/...` 数据路径，原仓库还依赖特定版本的库、预训练权重和分布式环境。当前源码注释可以阅读，但要运行训练需另配数据与环境。
