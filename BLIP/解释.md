## 1. 论文地图：两个核心问题【必须会】

第 1～2 页交代问题和相关研究，第 3 页介绍 MED 与三个训练目标，第 4 页介绍 CapFilt，第 5～6 页分析数据质量、采样多样性与参数共享，第 6～8 页评估检索、图像描述、VQA、NLVR2、对话和视频迁移，第 9 页进一步控制训练样本数与继续训练变量，第 12 页给下游超参数和数据统计。

第一个问题是模型能力：CLIP 擅长全局图文对齐，ALBEF 还学习图文融合与补词；如果希望模型看图生成完整句子，需要一个能预测下一词的解码路径。BLIP 的 **MED = multimodal mixture of encoder-decoder，多模态编码器与解码器混合**，通过三种调用方式完成单模态编码、图像条件文字编码和图像条件文字解码。第二个问题是训练数据：网络图片的 alt-text 可能是网页背景说明、地点、广告等，并不描述画面。**CapFilt = captioning and filtering，生成描述并过滤**，给图片补写描述，再剔除不匹配的原文和生成文。

BLIP 名字里的 **Bootstrapping** 指用已训练模型改善数据，再用改善后的数据训练新模型。它与模型内部的 momentum teacher 是两个层次：CapFilt 改造数据集，动量教师为当前对比训练产生软目标。不要把二者都记成一个“教师模型步骤”。

## 2. 仓库与实际执行链【必须会】

```text
python -m torch.distributed.run ... pretrain.py --config configs/pretrain.yaml
 → pretrain.main：读取配置、创建 Dataset / DataLoader、模型和优化器
 → data/pretrain_dataset.py：图片路径＋caption → 图片张量＋字符串
 → pretrain.train：批量图片搬设备，计算 alpha，调用 model(image,caption,alpha)
 → models/blip_pretrain.py：视觉编码、文字编码、ITC/ITA、ITM、LM
 → models/vit.py：patch embedding 与 ViT
 → models/med.py：BERT 自注意力、交叉注意力、因果 mask 和下一词损失
 → 三损失相加 → backward → optimizer.step → 保存 checkpoint
```

`pretrain.py` 是训练入口；`models/blip_pretrain.py` 是预训练模型；`models/blip.py` 放 `create_vit`、`init_tokenizer`、caption 模型、加载权重等公共函数。`train_caption.py` 做描述微调，`train_retrieval.py` 做检索，`train_vqa.py` 做问答。配置中的图片尺寸、batch、队列长度、alpha 由入口传入模型，模型并不从 YAML 自动读取所有变量。

源码保留了作者机器的 `/export/...` 数据路径。当前配置只列 COCO 和 VG 标注，并不是论文 14M 或 129M 数据的完整清单。只下载仓库、采用默认配置，不能直接宣称复现论文预训练。

## 3. 图 2：沿一次图文输入追张量【必须会】

统一记号：`B` 是当前进程批量数，`P` 是图像 token 数且包含 CLS，`T` 是文字 token 数且包含特殊 token 与 PAD，`Dv`／`Dt` 是视觉／文字隐藏宽度，`E` 是对比向量宽度，`Q` 是历史队列容量，`V` 是词表大小。

图像 `[B,3,224,224]` 经 patch16 的 ViT-Base 得 `[B,197,768]`：224÷16=14，14×14=196 个 patch 加 1 个 CLS。caption 起初是 B 条 Python 字符串，在 `BLIP_Pretrain.forward` 中经 tokenizer 填充／截断至 30 位，得到整数 `input_ids [B,30]` 与有效位 `attention_mask [B,30]`。这里 `T=30` 是预训练配置路径，不是所有下游任务都固定 30。

图 2 左侧图像编码器输出被多个目标复用。单模态文字模式不开图像交叉注意力，输出 `[B,T,Dt]`；两侧 CLS 分别经投影与单位化得到 `[B,E]`，用于 ITC。图像条件文字编码模式让文字 Query 读取图像 Key/Value，融合 CLS 进 ITM 头。图像条件文字解码模式还加入因果自注意力，仅根据前文与图片预测下一词。普通生成路径不存在“未来正确 caption”输入。

图中的相同颜色表示共享参数。代码 `tie_encoder_decoder_weights(...,skip_key='/attention')` 递归绑定对应参数对象，跳过文字自注意力：编码器可双向读当前句子，解码器要因果预测后续词，所以自注意力分开；embedding、交叉注意力、FFN 等可共享。绑定 `encoder_pointer.weight = decoder_pointer.weight` 是引用同一个 Parameter，而非复制一份数值。教师视觉编码是额外无梯度分支；论文图示中学生视觉特征复用不代表实际程序只调用视觉网络一次。

## 4. 三损失的公式、变量与代码【必须会】

论文 §3.2 以文字描述目标，没有给这三个目标统一编号公式。下列公式是为了理解源码作的数学展开，不冒充论文原式编号。

### 4.1 ITC／源码 ITA：比较整图和整句

单位图像向量 $v_i\in\mathbb R^E$、单位文字向量 $t_j\in\mathbb R^E$，相似度 $s_{ij}=v_i^\top t_j/\tau$，温度 $\tau>0$。一行 softmax 是

$$p^{i2t}_{ij}=\frac{e^{s_{ij}}}{\sum_{k=1}^{B+Q}e^{s_{ik}}}.$$

`image_feat [B,E] @ text_feat_all [E,B+Q]` 得 `[B,B+Q]`。`_all` 由本批教师向量与历史队列拼出；队列存全局向量，并非图片像素或文字序列。`_m` 是 momentum teacher 后缀，不是 masked。教师参数更新为 $\theta_m\leftarrow m\theta_m+(1-m)\theta$，`m=0.995` 保留大部分旧教师状态。例如旧教师 10、学生 12，更新为 10.01。教师不经 optimizer 更新，计算由 `torch.no_grad()` 包住。

教师 softmax $p_m$ 与真配对 one-hot $y$ 混合成 $q=\alpha p_m+(1-\alpha)y$。学生损失是 $-\sum_jq_{ij}\log p_{ij}$，两个检索方向平均。若硬标签 `[1,0]`，教师 `[0.8,0.2]`，alpha=0.4，目标变 `[0.92,0.08]`；它允许教师给语义相关的另一句少量概率，而不是把所有非对角候选都绝对视作无关。注意这不保证教师判断一定正确。

代码对应 `BLIP_Pretrain.forward` 的 `image_feat`、`text_feat`、`sim_i2t`、`sim_t2i`、`sim_*_targets` 与 `loss_ita`；`F.normalize(dim=-1)` 单位化最后一维，`F.log_softmax` 是稳定的对数概率，`.detach()` 切断教师／队列目标梯度。`self.temp.clamp_` 限制温度范围，但不取消它作为可学习参数的身份。

### 4.2 ITM：图文融合后判断真假

融合编码器输出 `output_pos.last_hidden_state [B,T,Dt]`，取首 `[ENC]` 位置形成 `[B,Dt]`。ITC 分数经 softmax 变采样权重，排除正确对角，再用 `torch.multinomial` 选容易混淆的错图、错文。正例 B 对、错图 B 对、错文 B 对，总共 `3B` 个融合向量进入 `itm_head`，logits `[3B,2]`，标签是 B 个 1 与 2B 个 0。

$$\mathcal L_{ITM}=-\frac1{3B}\sum_{r=1}^{3B}\log\operatorname{softmax}(z_r)_{y_r}.$$

$r$ 是组装后的配对索引，$z_r$ 是两类原始分数，$y_r$ 是匹配类别编号。例子：正确类别概率 0.8，负对数损失为 $-\log0.8\approx0.223$。`F.cross_entropy` 接收 logits，内部完成概率归一化；外面不必先 softmax。代码 `[CLS]→[ENC]` 的首 token 替换为融合模式提供信号，但真正启用交叉注意力还受 MED 的调用参数控制。

### 4.3 LM：按前缀逐词生成

$$\mathcal L_{LM}=-\sum_{t\in\mathcal S}\log p(w_{t+1}\mid w_{\le t},I).$$

$I$ 是图像，$w_{\le t}$ 是截至位置 t 的前缀，$\mathcal S$ 是有效预测位置。MED 输出词表分数 `[B,T,V]`；`prediction_scores[:,:-1,:]` 对齐 `labels[:,1:]`，使当前位置预测**后一位置的词**。PAD 标签设 `-100` 不计损失，首 token 改为 `[DEC]`；源码用 0.1 label smoothing（标签平滑）。完整损失细节在 [MED 与生成](资料/02-MED与生成.md)。

例子：输入 `[DEC],a,cat,[SEP]` 时，位置 0 预测 `a`，位置 1 预测 `cat`，位置 2 预测结束符。因果 mask 保证预测 `cat` 时读不到作为未来输入的 `cat`。`generate` 从前缀反复算下一词、选择词、追加词，直到结束符或长度限制；训练的 teacher forcing 直接给正确前缀，两条执行路径不同。

## 5. 变量名与库函数的重点提醒【必须会】

| 名字 | 命名、来源与形状 | 后续用途 |
| --- | --- | --- |
| `caption` | 描述，DataLoader 返回的 B 条字符串 | tokenizer；不是初始 ID 张量 |
| `image_embeds` | embeddings，每个图像位置的表示 `[B,P,Dv]` | MED 交叉注意力 Key/Value |
| `image_feat` | feature，图像 CLS 投影后 `[B,E]` | ITC 全局对比 |
| `text_output` | MED 返回的结构化对象 | `.last_hidden_state` 才是文字序列张量 |
| `decoder_input_ids` | 为生成训练准备的 token ID `[B,T]` | 首位改 DEC 后进因果解码器 |
| `decoder_targets` | 下一词监督来源 `[B,T]` | PAD=-100，MED 内错位一格 |
| `queue_ptr` | pointer，历史队列下一写入位置 `[1]` long | `_dequeue_and_enqueue` 原地更新 |
| `alpha` | 教师软目标的混合比例，入口传入 float | ITC 软／硬标签混合 |
| `bs` | batch size，从图片第 0 轴取出的整数 | 组装 ITM 标签与负例 |

隔很远再次遇 `image_embeds`，仍要回想它是整条图像序列；`image_feat_all` 则是全局候选列。`text_encoder` 编码当前文本或融合图像，`text_decoder` 因果预测后续词。`nn.Linear` 是登记参数的网络模块，`F.normalize` 是无新参数的函数；`torch.cat` 沿已有轴拼接，`torch.stack` 新增 batch 轴；`register_buffer` 是保存／搬设备但不训练的状态，`nn.Parameter` 会由优化器训练。每个 import 与实际 API 的详细解释在各分章和原文件旁，尤其 [预训练流程](资料/03-预训练流程.md) 中按执行顺序重复提醒变量来源。

## 6. 图 3：CapFilt 是数据级流程【必须会】

先用人标图文 $(I_h,T_h)$ 和网络图文 $(I_w,T_w)$ 预训练 MED。用 COCO 微调一个 captioner（LM）和一个 filter（ITC+ITM）；两者分别微调。Captioner 为每张网络图片生成描述 $T_s$，filter 对原文 $T_w$ 和新文 $T_s$ 都判匹配，剔除被判负例的内容；保留的人标对、过滤后网络对、过滤后生成对组成新数据集，再预训练新的 BLIP。

[models/blip.py](models/blip.py) 的 `BLIP_Decoder.generate` 对应“写描述”；[models/blip_itm.py](models/blip_itm.py) 的 `BLIP_ITM.forward(match_head='itm')` 对应“判是否匹配”；[models/blip_pretrain.py](models/blip_pretrain.py) 对应在已准备数据上训练。**当前仓库未找到把上述步骤完整串起来、自动生成 14M／129M CapFilt 数据的独立流水线脚本**。README 提供 bootstrapped 数据说明，并不意味着运行 `pretrain.py` 会自行生成与过滤数据。`predict.py` 是演示推理，也不是完整 CapFilt 数据构建器。

图 3 的两种共享关系不同：预训练时 MED 编码／解码共享非 SA 参数；CapFilt 的 captioner 与 filter 各自微调。若共享这两个数据处理模型参数，captioner 的错描述更容易被 filter 接受，论文称可能有 confirmation bias（确认偏差）。这个解释是作者对实验现象的推断，并不是对全部错误机制的证明。

## 7. 实验：数值支持什么结论【建议会】

表 1（PDF 第 5 页）在 14M 图片、ViT-B/16 的设置中比较 CapFilt：无 C/F 时 COCO 微调 TR@1=78.4、IR@1=60.7、caption CIDEr=127.8；同时加 C/F 后为 80.6、63.1、129.7，分别 +2.2、+2.4、+1.9。Flickr 零样本 TR@1 从 93.9 到 94.8，NoCaps CIDEr 从 102.2 到 105.1。C/F 是 captioner/filter，R@1 是正确目标在第一候选的比例，CIDEr 衡量与参考描述的词组一致性；都越高越好，但不是同一含义的“准确率”。

表 2 在同为 14M 图片的条件下比较生成方式：beam search 过滤噪声比例 19%，nucleus sampling 为 25%，后者 COCO TR@1=80.6、CIDEr=129.7，前者 79.6、128.9。较高过滤比例与较好下游效果同时出现，作者认为可能是描述更有多样性；该表不能证明“噪声越多越好”。

表 3 比较 MED 参数共享：全部共享 224M 参数、COCO TR@1=77.3；除 SA 外共享 252M 参数、TR@1=78.4；全部不共享 361M 参数、TR@1=78.3。采用除 SA 外共享，在这个设置中兼顾性能与参数量，不能推断任意编码器／解码器都该如此绑定。

表 5／6（第 6 页）分别是各数据集微调检索与 Flickr 零样本迁移。14M 的 BLIP 在 COCO 微调 TR@1=80.6、IR@1=63.1，ALBEF 14M 为 77.6、60.7；两个方向平均增益 $(3.0+2.4)/2=2.7$ 点。这里 BLIP 还用 ITM 对候选重排；不要与只用全局点积的 CLIP 宣称完全等成本比较。论文的“零样本 Flickr”使用在 COCO 微调过的模型直接迁移，表示没有 Flickr 微调，不是从未接受下游微调。

表 8（第 7 页）中 14M BLIP VQA test-std=77.62、ALBEF=76.04，+1.58 点；论文段落称提升 +1.64，而 test-dev 列的 77.54−75.84=1.70、test-std 列差值为 1.58；该概括值与这两个表格列均不完全一致，学习时优先标清列和值，不擅自抹平差异。NLVR2 test-P 的 BLIP 14M=82.30，ALBEF=83.14，BLIP 并非所有任务都更高。论文注明 ALBEF 对 NLVR2 做额外预训练，比较条件也有差异。

表 12（第 9 页）控制每 epoch 文字样本数：重复原网络文本到 24.7M，COCO TR@1=78.3；同样 24.7M 的 CapFilt 为 80.6。它支持改进不只是更多训练样本导致，仍不等于所有数据质量因素都被独立控制。表 13 中继续训练旧模型与新模型训练的结果互有微小差异，不应解读成继续训练绝对不可用。

## 8. 训练资源、配置差异与本地状态

论文 §4.1 报告 2 个 16-GPU 节点、20 epoch、ViT-B 总批次 2880／ViT-L 2400，预训练分辨率 224；AdamW 权重衰减 0.05，Base 初始峰值学习率 3e-4。本地 YAML batch_size=75 是每 GPU 数量；实际卡数与梯度累积决定总批次，不能直接说 75=2880。论文段落学习率衰减率写 0.85，本地 YAML `lr_decay_rate=0.9`，应记录所用版本与配置。附录下游多数分辨率 384，VQA 480，caption 微调 5 epoch、检索 6 epoch，均非本地已执行结果。

**复现状态：未复现。** 当前完成阅读、原文件注释扩充与静态核对；未完成原论文训练／评估。默认数据路径不在本机，构造 Base 模型还要取 DeiT/BERT 初始化权重。原入口依赖分布式进程组，队列容量要求能整除汇总后的 batch，ITM 采样需至少有错误候选；B=1 不能直接学正常批内难负例。`tie_encoder_decoder_weights` 的少数分支使用未定义 `logger`，是否触发依对象类型，不能忽略但也不能据此断言所有运行必败。

## 9. 掌握次序与 Paper ↔ Code

**必须会：** 区分 ITC/ITA、ITM、LM；沿图像与文字输入追到三损失；知道 encoder 双向、decoder 因果；区分数据级 CapFilt 与模型级动量教师；知道张量形状与字符串 caption 的区别。

**第二遍建议会：** EMA、历史队列、难负例、非 SA 参数共享、beam／nucleus、微调检索重排、不同任务指标及实验公平性。

**工程细节可以暂缓：** MED 兼容旧版 Transformers 的全部生成分支、checkpoint 插值、复杂分布式恢复、全部下游脚本与外部增强模块。
